# solo-web 站点优化建议书

> **范围**：`solo-web` 全站副本（`index.html` / `styles.css` / `main.js` / `DESIGN.md` / `README.md`）。**只评不改**，本文件是唯一新增物。
> **判据来源**：① 站点自身规范 `DESIGN.md`；② solo 仓库真理源 `docs/FEATURE-MATRIX.md`、`src/themes/presets/*.json`、`src/components/Editor/tiptap/extensions/callout.ts`；③ 本机实算的 WCAG 2.1 对比度。
> **文中所有对比度数字为公式实算**，不引用 `DESIGN.md` 里写的值。

---

## 结论（三句话）

1. **站很好看了，但有 3 处在骗用户**：8 张主题卡里有 3 张把主题画成了别的颜色；callout 写成"8 套配色"（真值 12）；结尾深色区块在下载按钮上，明亮主题下那个按钮几乎看不见。
2. **最贵的缺口是"没有一张真图"**：全站所有产品画面都是 HTML 手工复刻，主题区连自己都没发现（`index.html:370` 写了"示意预览"）；加上没有 Open Graph，分享到微信/飞书是一张白卡。
3. **文案口径整体可信**：我按 `README.md:39` 的约定逐条核了 FEATURE-MATRIX，自动保存 30 秒/下限 5 秒、7 款字体、10 万字不卡、改名同步互链、折叠跨文档记忆、Apache 2.0、仓库地址——全部对得上。**只有下面 P0-1 / P0-2 / P1-4 三处不符**。

**严重度**：P0 = 用户会被误导或页面功能坏掉 · P1 = 明显拉低转化/可用性 · P2 = 规范漂移与打磨。

## P0-2 callout 的"8 套配色"与实际不符

`index.html:273`：「12 种类型、8 套配色，重点一眼可见」。真实情况：`callout.ts:11-12` 定义 12 种类型，`themes/types.ts:86-109` 为**每一种类型各配一对前景/背景 token**（共 12 套），且随主题切换（FEATURE-MATRIX:141）。"8" 应是跟"8 套主题"串了行。
**建议**：改为「12 种类型，配色全部跟随主题」。

## P0-3 明亮主题下，深色区块的朱墨失效（含结尾下载按钮）

`styles.css:213-218` 的 `.section-dark` 重写了 `--ink/--ink-2/--ink-3/--line/--surface/--zhu-tint`，**唯独没重写 `--zhu` / `--zhu-strong`**。于是明亮主题进深色带（`#safety` `index.html:418`、尾部 CTA `index.html:545`）时强调色仍是明亮主题的 `#a63d2f`：

- `--zhu #a63d2f` on `#211d19` = **2.65:1**（AA 正文要 4.5:1）→ 「数据安全」小标题 `.eyebrow` 几乎糊进背景（`styles.css:220-224`）。
- 尾部主按钮 `background: var(--zhu)` vs 深色带底 = **2.65:1** → **全站转化动作在最后一屏变成一块看不清边界的暗砖红**。
- `.safety-note`（`styles.css:491-496`）左边框用暗砖红、底用 `--zhu-tint`（暗红透明），两者不是一套色，看着像渲染出错。

**建议**：`.section-dark` 内补 `--zhu: #d4654f; --zhu-strong: #e07a63; --dai: #6aa8a0;`（即深色主题的那套强调色），并在 `DESIGN.md §2` 记一句「深色区块恒用暗色板强调色，与用户主题无关」。

## P0-4 JS 没跑起来 = 整页空白

`styles.css:585` `[data-reveal] { opacity: 0 }` 是无条件生效的。`main.js` 加载失败/被扩展拦截/报错时，全站 45 个 `data-reveal` 块（`index.html` 实测计数）**永久透明**（`prefers-reduced-motion` 有兜底 `styles.css:651`，普通用户没有）。
**建议**：`index.html:10-19` 那段内联脚本里加一行 `document.documentElement.classList.add('js')`，选择器改成 `.js [data-reveal] { opacity: 0 }`。两行成本，把"白屏"降级成"没有动画"。

`README.md:34` 与 `DESIGN.md:51` 声明 AA。但 `--ink-3 #8f867a`（`styles.css:48`）实测：

## P1-1 全站没有一张真实产品截图

`index.html:94-142` 的"编辑器示意窗"、`:374-405` 的主题卡（三根灰条）、`:300-328` 的 mermaid 手绘图，全是 HTML 复刻。**一个以"排版书卷气"为卖点的编辑器，用户看不到一行真实渲染**。`index.html:370` 自己写了"（以下为示意预览）"——诚实，但也自证了缺口。
**建议**：真机截 4 张 PNG 放 `imgs/`（`书卷气`日间整屏 / `夜读墨色`夜间整屏 / 焦点模式 / callout+表格混排），首屏示意窗改成"真截图 + 现有 HTML 复刻"二选一或并列；其中一张裁成 1200×630 兼作 OG 图。**这张图我做不了，需要你开软件截。**

## P1-2 没有 Open Graph / theme-color / 结构化数据

`index.html:3-20` 只有 `title` + `description`。缺 `og:title/description/image/type`、`twitter:card`、`<meta name="theme-color">`、`canonical`、JSON-LD。
**后果**：分享到微信/飞书/微博没有卡片图，标题下面一片空白——而这个产品唯一的公开联系渠道就是微信（`index.html:569`），等于把最可能的传播路径裸奔。
**建议**：补 OG 三件套 + `theme-color`（亮/暗各一）+ 一段 `SoftwareApplication` JSON-LD（`operatingSystem`/`license`/`downloadUrl`），依赖 P1-1 的截图。

## P1-3 下载只给 GitHub 一条路，而项目自己已经在维护国内镜像

`index.html:46`、`:76`、`:550`、`:567` 四个下载入口全指 GitHub Releases。但 solo 仓库 `docs/RELEASE_PROCESS.md:299` 明确写着：**CNB（cnb.cool）作国内手动下载渠道，因为 updater 端点写死 GitHub**。
**建议**：主按钮保持 GitHub，旁边加一个"国内镜像下载"次按钮（镜像 URL 需你确认真实可达，我离线无法验证）。

## P1-4 已知的真实限制没进 FAQ：自动更新在国内会失败

`RELEASE_PROCESS.md:299` 同一行：软件自动更新端点写死 GitHub，镜像那份**不参与自动更新**。目标用户是国内、网络不稳的人群，这条不写就等于埋了个"我点了更新怎么一直失败"的客服问题。站点 `README.md:39` 的约定恰恰要求"未实现/有限制的如实标注"。
**建议**：FAQ 加一条「自动更新失败怎么办 / 我怎么拿到新版本」，答：手动到 Releases 或镜像下载。

## P1-5 把最抓中国用户的功能写成了"PDF 的替代品"

`index.html:522` 在"能导出 PDF 吗"的回答里顺带提到"复制为富文本 HTML"。但这个功能本身是主力卖点之一：FEATURE-MATRIX:167 显示状态栏复制按钮写的是**双槽**——`text/plain` = Markdown 源码、`text/html` = 带完整主题排版的富文本。贴进公众号/飞书/语雀不乱格式，这比"不能导 PDF"性感得多。
**建议**：特性区（`index.html:193-247`）新增一张卡「一次复制，两处不乱」，主标题讲排版跟随、副文案讲双槽；FAQ 那条改成"导 PDF 暂未做，日常分发用状态栏复制"。（注意：FEATURE-MATRIX:167 记录了软件里这个按钮的 `title` 口径也不统一，文案定稿前顺带统一。）

## P1-6 触控目标 36px，规范写 ≥44px

`DESIGN.md:136` 声明"触控目标 ≥44px"，代码里唯一的 "44px" 是 `styles.css:368` 那根装饰横线。`.icon-btn` 36×36（`styles.css:171-177`）、`.nav-toggle` 36×36（`:612-617`）、`.btn-sm` 高约 34px（`:200`）——手机上"下载"是最小的点击块之一。
**建议**：给这三个类加透明热区（`::after { content:""; position:absolute; inset:-4px }` + 父级 `position:relative`），视觉尺寸不动；`DESIGN.md` 注明"视觉 36px、热区 44px"。

## P1-7 性能区四个"数字"，三个是形容词

`styles.css:502-506` 把 `.m-num` 设计成 28–40px 衬线大字号（明显是给数字用的），`index.html:458-461` 里填的却是"轻量""懒加载""降内存"，只有"10万+"是数。设计上最强的一个位置被形容词占了。
**建议**：填真实测量值（安装包 MB / 冷启动 ms / 空载内存 MB），测不出的就把该区从"指标"改成"四条说明"并去掉大字号衬线——**别让样式等着，内容却不来**。

## P1-8 信息层级：9 张等权重卡片 + 10 个区块只有尾部一个 CTA

- 特性区是标准 3×3 等权重网格（`index.html:193-247`），九张卡字号、图标、高度全一致，没有主次——这恰好是 `DESIGN.md:126` 反对的"模板感"来源之一。
- `index.html:244` 的卡片标题与 `:455` 的性能区 `<h2>` **同一句话**「秒开秒关，大文档不卡」，同一句话在两处出现会被读成"没内容可写了"。
- 导航（`index.html:33-38`）列了 6 项，但 **`#safety` 和 `#performance` 不在其中**——而"数据安全底线"是产品最强的差异点（`DESIGN.md §1` 的核心），用户不滚到底就看不到。
**建议**：特性区改成"1 张大卡（所见即所得，配真截图）+ 8 张小卡"；性能区 H2 换成带数字的标题；导航补「安全」一项。

## P1-9 示意窗的可访问性标注是失效的

- `index.html:94` 把 `aria-label` 挂在**没有 role 的 `div`** 上 → 主流读屏引擎会忽略它（`DESIGN.md:155` 声明"功能性配 aria-label"，这条没落地）。
- 窗内的 `:102` `<h2 class="md-h1">欢迎来到 solo</h2>` 会**进入真实文档大纲**，读屏用户按 H 键跳转时会跳进一段假内容里。
**建议**：`.editor-window` 改 `role="img"`（保留 `aria-label`）——一个 role 同时解决"标签生效"和"子树不进大纲"。

## P1-10 移动端菜单四个状态漏洞

`main.js:30-43`：① 无 Esc 关闭、无点击外部关闭；② 开菜单后拖宽窗口，`.mobile-nav` 会以一整列链接留在页头（`hidden` 已被移除，`styles.css:621` 的显示规则只在 ≤768px 内）；③ 用链接关闭时只重置 `aria-expanded`，`aria-label` 停在"关闭菜单"（`:39-40`），读屏报的状态和实际相反；④ 打开后焦点没进菜单。
**建议**：加 `keydown` Esc + `resize>768` 自动收起 + 关闭时一并复位 `aria-label`，三处都在同一个函数里。

## P2 打磨小项

1. **暗色缺 `color-scheme`**：全文没有 `color-scheme` 声明 → 暗色主题下浏览器滚动条/表单控件仍是亮色，右侧一条白边很跳。`:root[data-theme="dark"] { color-scheme: dark }`（亮色同理），一行。
2. **锚点被吸顶页头压住**：`.site-header` sticky（`styles.css:141`）、`min-height:64px`（`:155`），而区块 `padding-block` 最小也是 64px（`:211`）→ 小屏点导航后标题正好贴在页头下沿。加 `--header-h: 64px` token + `section[id] { scroll-margin-top: calc(var(--header-h) + var(--sp-2)) }`（走 token，不撒魔法数字，按 `AGENTS.md §1.2`）。
3. **`transition: all`**（`styles.css:410`）违反 `DESIGN.md:126`「不动画化布局属性」→ 明确列出 `color, border-color, background-color`。
4. **品牌位用的是 favicon**：`index.html:27`、`:561` 的 logo 是 `favicon.svg`（小尺寸方章），而 `public/icon.png` 才是产品正式图标。另建议补 `apple-touch-icon` 和 PNG 兜底。
5. **衬线"书卷气"依赖本机装了什么**：非中文 Windows 上大概率只剩 `SimSun` 或不确定的 `serif` 兜底，主视觉气质随机。**建议在 `DESIGN §1` 的"零外链"前提下自托管一个标题字子集**——全站标题只用到约 60 个汉字，子集化后是几 KB 量级，既不破"无外部请求"，又能保证 `h1` 在每台机器上都是同一张脸。
6. **导航无当前区块高亮**：10 个区块 6 个入口，滚到中间就不知道自己在哪。复用已有的 IntersectionObserver 加 8–10 行。
7. **mermaid 示意图两处待真机确认**：`index.html:306` 用 `font-family="var(--font-sans)"`（表现属性里放 `var()`，SVG 1.1 文法不合法，现代浏览器一般可解析，但没兜底）；`:313` 一条 `path` 里放两个子路径再挂 `marker-end`，箭头是否两支都出得来取决于实现。建议：`var()` 改写到 `style` 或 `<style>` 里，两个子路径拆成两条 `path`。
8. **首屏代码示例的函数名是编的**：`index.html:117-120` 的 `write_tmp_then_rename`，仓库里真名是 `atomic_write` + `MoveFileExW`（FEATURE-MATRIX:47）。技术区读者会去搜这个符号，搜不到。
9. **文案两处**：`index.html:77`、`:550` 的「下载 for Windows」中英混排，建议「下载 Windows 版」；`index.html:70` 的「把稿存安」是硬凑的对仗，"存安"不是词，第一遍读会卡（备选方向：把产品名词放进 H1 或副标题首句，现在访客要先读完 badge + lead 才知道这是个软件）。
10. **缺系统要求口径**：站内没写最低 Windows 版本与 WebView2 依赖，仓库文档里我也没搜到（`README.md`/`SECURITY.md` 均无）。建议先在仓库定口径再上站，别在站点先写。
