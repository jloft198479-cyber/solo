## 一、总账（先给结论）

**方向可以采信，但按它执行会白跑一趟。**

- 它对「痛点存在」的判断成立：200 条提交里 **75 条（37.5%）是纯文档提交**，且这还是下限（只按 `docs` 前缀统计，像「台账 §二 #29 标已修复」这类没带前缀的没算进去）。
- 但它**把税源认错了**：它指认的最大税源（AGENTS.md:187 死链扫描）在 75 条文档提交里只占 **2 条**。真大头它一个字没提。
- 它的「零信息丢失、git mv 即可」不成立：阶段 1 会砸断 **116 处现行引用**，并把**全仓保真体检的硬断言跑红**。
- 它松绑的 5 条指令里，**1 条指向的位置根本没有它说的内容**（证伪），**1 条不在仓库权限范围内**（改不动）。

一句话：这份方案是「看着文件列表推出来的」，不是「看着提交历史量出来的」。所以它砍在了次要矛盾上。

## 三、方案会碰坏护栏的一处（必须先堵）

**`git mv` 会把全仓保真体检跑红。**

`fidelity-scan.spec.ts:102` 的 `SKIP_DIRS` 不含 `docs` 与 `archive`，`:132` 是 `walk(ROOT)` 全仓扫描 ⇒ **仓库自己的 md 就是体检语料**。而 `KNOWN_SCAN_SIGNATURES`（`:58` 起）**按路径**登记预期丢失签名，`:205-208` 是**硬断言**：

> 扫出来的文件若在登记表里查不到路径 ⇒ `unknownFiles` ⇒ `toEqual([])` **失败**。

后果：把 `docs/IME-问题简报与资料汇编.md` 移到 `docs/archive/` 后，路径变了、登记表查不到 ⇒ 这条 2066 行文档立刻以「此前不在登记表里却出现净内容减少」的身份**把测试变红**。执行者会以为减负动作引入了保真 bug，回来查一整天。

方案的「阶段 1：git mv 即可」建立在这件事不知情之上。

## 四、更狠的版本（这是你要的「力度更大」）

方案的天花板是「少跑几次扫描、少同步几处」——**还是人在管**。真正的减负是把人从链路里撤出去。三刀，按收益排序。

### 刀一：死链扫描从「人工 grep」换成一条测试，然后 AGENTS.md 那条直接删（10 分钟，永久免费）

仓库已经有 vitest。加一个 `docs-lint.spec.ts`：扫全仓 md 的 `](...)` 链接 + 源码注释里的 `docs/xxx.md` 指针，目标不存在即红。

- 比方案更彻底：方案说「仅删/重命名时跑」，还留了个人工判断；脚本挂在 `bun run test` 上，**跑不跑不用你想**。
- 护栏一点没弱，反而更强（现在是每次 test 全量校验，而不是偶尔手扫）。
- 于是 AGENTS.md:181（§5 表最后一行）、:81 尾句、:189 的「更新文档」连带都能删减。

### 刀二：砍真大头——台账降级 + 复核分级（省下的是那 75 条提交里的主体）

75 条文档提交按活动分类（有重叠）：**登记 11 / 台账 9 / 订正 5 / 归档 5 / 核实+复核 5 / 审核 3 / INDEX 4 / 死链 2**。大头是**「把证据写成散文并反复订正」**，不是死链。三条：

1. **台账条目降级**：`KNOWN-ISSUES.md` 一格写成几百字证据（参 #31、#35、#36 三行），这就是税。改成**一行现象 + 一行根因 + 复现锁的测试名**。证据本来就在测试和 commit message 里——**代码即证据，不许再抄一遍进台账**。
2. **「已修复需独立复核」（AGENTS.md:157）改成分级触发**：只有**数据损失级 / 不可逆 / 发版前 gate**三类要改动者以外复核；其余由「修复前实测为红 → 修复后绿」的复现锁**自证**。仓库里 `useDocumentSession.spec.ts` 那三条已经是这么干的（台账 #36 记的「修复前第一条实测为红」），说明测试足以背书，多 agent 复核是给 prose 背书——**成本最高、收益最低的那块**。
3. **取消日报类文档**：`00-今日修改总览-*.md` 这类一次性快照本身就是税基，删掉连归档都不用。

> ⚠️ 第 2 条动的是**验收纪律**，不是文档格式。它是这把刀里唯一需要你拍板的取舍：放松复核＝少数静默 bug 可能漏到发版。我的判断是**该砍**——复核轮次已经在产出「证伪三份、再补一版订正」的自循环（近期 5 条 `docs(cell)` 提交就是这么来的），换来的边际安全远低于烧掉的时间。但这条要你点头。

### 刀三：斩断「代码 → 文档」的反向依赖（做完，Tier B 归档才真的免费）

src 里 13 处注释把 docs 当契约来源。只要这些指针在，文档就是**拆不动的承重墙**，方案阶段 1/2 就永远是「高风险大活」。

做法：判据**就近写回**——契约要点缩成一句放进注释或测试名（现在注释里已经有半句了），文档降级为「可选背景，不是依据」。做完之后：

- 归档 30 份文档 = 纯 `git mv`，**零引用要同步**；
- AGENTS.md §3 敏感区表里「先读某 PROPOSAL」那类格子，改指代码位置（`list-demote.ts` 而不是提案文档）——**代码在哪，契约就在哪，文档死了也不碎**。

这一刀是三刀里唯一让「力度」真正上一个台阶的：前两刀是少交税，这一刀是**把税基拆掉**。
