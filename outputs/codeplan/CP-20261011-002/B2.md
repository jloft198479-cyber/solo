### 发现

**🔴 1 — 规则①.2「ZWNJ 只清文本节点」违反敏感区 #23③ 的属性通道契约，且与方案自带验收自相矛盾**

证据：
- `docs/sensitive-areas.md:43`（#23③）原文：「任何**读解析期产物**后要**对外呈现 / 计数 / 写盘**的地方，都必须过 `stripZwnj`。**「解析期产物」＝ 正文文本 ＋ 属性通道**（由正文衍生的 attrs：alt / title / label / target / alias / latex 等）」，⑤ 的覆盖清单明确列了 `image alt＋title`、`link title`、`footnoteRef/footnoteDef label`、`callout title`、math `attrs.latex`。
- `src/components/Editor/tiptap/zwnj.ts:14–17` 同一条契约；`serializer.ts:438–442` 注释直接写「`[标题](https://x.com/a，**b**.md)` **实测中招**」（href/title 通道），`serializer.ts:723–730`（alt/title/src 通道）。
- 可达性不是构造出来的：`parser.ts:737–764` 的插入是**对整篇源**（只保护代码区）做正则，`![...]()` / `[...](...)` / `[^...]` / `[[...]]` / `> [!note]` 内的 `**` 都会带上 U+200C；`roundtrip.spec.ts` Phase A4（204–290）为这些通道设了回归锁，其中 284 / 290 两条标题就叫「**真实落点**」。
- 规则①.8 的白名单**保留 `alt` / `title` / `href` / `src` / `id` / `class`** —— 正好是上面这批正文衍生通道，于是隐形字符照样出站；方案自己列的 P1-5「Ctrl+C 泄漏 ZWNJ」被这版定性为「不修」，但按钮这条修了一半，等于把同一件事再登记一遍。
- 顺序坑：①.2 排在 ①.3 / ①.5 之前，而 ①.3 是把 **`data-title` 属性值**写成 `<p><strong>` 文本、①.5 是把 **`label` 属性值**写成 `[N]` 文本 —— 这两处新增文本节点天然绕开已经跑完的文本清洗。
- 结果：验收 #1 断言「不含 U+200C」和规则①.2 不可能同时成立（对照文档含 `![图注|200x100]` + 中文标点强调，正是 alt 通道）。

要 A 处置：①.2 改写为「文本节点 + **保留下来的属性**（`alt` / `title` / `href` / `src` / `id` / `class`）逐一过 `stripZwnj`（`zwnj.ts` 已收口非字符串）」；并在改法里把规则顺序写成硬约束：**结构规则 1–7 → 属性清洗 8 → ZWNJ 清洗（文本+属性）最后跑一遍**，保证后插入的文本也被扫到。删掉「整串 split/join 会连属性一起碰，不做」这句理由——属性**就是**必须碰的。

**🔴 2 — 验收 #1 末条「通用元素计数与归一前逐项相等」被改法自己推翻，按字面写测试必红**

**重要 3 — 规则①.8 白名单不含 `style`，与①.7 互相抵消，并静默丢掉 GFM 表格对齐**

要 A 处置：二选一并写进方案——(a) ①.8 收 `style` 但做**属性值白名单**（只允许 `text-align: left|center|right`），①.7 的 min-width 处理由它兜底；(b) ①.8 明确**跳过 `style`**，style 归 ①.7 独占。同时验收补一条断言：带 `:---:` 的表格列归一后仍含 `text-align`。

**重要 5 — ①.3 的 `calloutDisplayTitle(attrs)` 输入形态没定，而属性值与 NodeView 显示不同源，照字面实现会漂移**

证据：`extensions/callout.ts:43–46` 的 `renderHTML` 只写 `'data-callout-type': (attrs.calloutType) || 'note'`，**不调 `normalizeCalloutType`**（归一只发生在 `parseHTML:42` 和 NodeView `applyAttrs:104`）；`:52` 的 title 是 `attrs.title ? { 'data-title': attrs.title }`，**不 trim**，而 NodeView `:105–107` 是 `title.trim()` 后才写属性；显示文案在 `:118–123 syncTitleUI()`：`title || normalizeCalloutType(calloutType)`。归一层只有 DOM（拿不到 PM attrs），若按「`data-title` 非空则用 title」判，`title: "   "` 这种值会产出 `<p><strong>   </strong></p>`，而编辑器里显示的是类型名。
