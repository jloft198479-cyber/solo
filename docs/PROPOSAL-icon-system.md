# 图标系统统一方案（2026-10-17）

> 本文界定问题与方案。**第 1 步（建库）已执行**，界面零变化；第 2、3 步待执行。

## 一 · 一句话结论

问题不是"图标不好看"，而是**没有统一规格**：同一个界面里，线条实际粗细从 1.12px 到 1.80px，差 61%。统一成一套规格后，所有图标的笔画、端点、拐角才会看起来是"一个人画的"。

## 二 · 现状取证（全部实测，非估计）

### 2.1 三种"不统一"

| 维度 | 实际情况 |
|---|---|
| 画布尺寸 | **7 种**：24×24（11 处）、16×16（6）、15×15（6）、10×10（5）、12×12（2）、28×28（1）、10×1（1，最小化横线） |
| 线宽 | **8 种**：2（8 处）、1.5（7）、无描边（7，实心）、1.2（6）、1.3（1）、1.4（1）、1.6（1）、1.8（1） |
| 图标来源 | 内联 SVG 32 处（17 个文件）+ 系统字符 18 个（斜杠菜单 14、气泡菜单 4） |

关键点：**线宽数值不同不代表视觉不同，真正决定观感的是"线宽 × 显示尺寸 ÷ 画布尺寸"**。算出实际像素后差异就藏不住了：

| 界面位置 | 画布 | 线宽 | 显示尺寸 | 实际线条 |
|---|---|---|---|---|
| 状态栏「已复制」勾 | 16 | 1.8 | 16px | **1.80px** |
| 顶栏按钮 / 字体弹窗 / 主题弹窗 | 16 | 1.5 | 16px | 1.50px |
| 大纲折叠 | 12 | 1.4 | 12px | 1.40px |
| 状态栏复制 / 气泡菜单清除格式 | 24 | 2 | 16px | 1.33px |
| 命令面板 | 15 | 1.3 | 15px | 1.30px |
| 代码块 / 公式 / 图表按钮 | 24 | 2 | 14px | 1.17px |
| 搜索框 / 标题栏固定 | 15 | 1.2 | 14px | 1.12px |

### 2.2 最能说明问题的一处

状态栏的「复制全文」按钮：未点击时是 24 画布 / 1.33px，**点一下变成勾，立刻换成 16 画布 / 1.80px** —— 同一个按钮、同一个位置，切换状态时线条突然粗 35%。这不是设计，是两段代码各写了一遍。

### 2.3 字符图标（最不一致的一套）

斜杠菜单的 14 个图标是系统字符：`¶` `H1` `H2` `H3` `•` `1.` `☐` `❝` `▎` `<>` `—` `⊞` `∑` `◈`。它们由字体渲染，粗细、大小、对齐全部不可控，和旁边的 SVG 图标完全不是一种语言。气泡菜单里还有 4 个：`</>`、`A`（文字变浅）、`H1`、`H2`。

## 三 · 统一成什么规格

| 项 | 规格 | 理由 |
|---|---|---|
| 画布 | **24 × 24** | 业界标准（Lucide / Feather / Material 同尺寸），换库与抄 path 都零换算 |
| 线宽 | **2** | 在 24 画布下：显示 16px = 1.33px、显示 14px = 1.17px —— 正好落在现有图标的中位区间，改完最自然 |
| 端点 / 拐角 | `round` / `round` | 圆润收笔，符合 solo 的书卷气质；现已 27 处是 round，只差统一 |
| 颜色 | `currentColor` | 跟随文字色，主题切换自动适配，无需为深浅色各画一套 |
| 填充 | 默认 `none` | 描边风格；列表圆点、上下箭头等需要实心的单独保留（实心也走同一画布） |
| 尺寸 | 由使用处控制，组件不写死 | 同一图标在 14 / 16 / 20px 复用，不复制多份 |
| 例外 | 窗口按钮（最小化 / 最大化 / 关闭）保持 10px 细线 | 这是系统窗口控件惯例，跟应用图标混用反而怪 |

换算参照：24 画布下，显示 16px → 1.33px；显示 14px → 1.17px；显示 20px → 1.67px。**同一显示尺寸下必然一致**，这才是"齐"的本质。

## 四 · 怎么落地（三步，每步独立可回滚）

### 第 1 步 · 建库（不替换任何东西，纯新增）

- 新建 `src/components/icons/svg.ts`：**唯一的图源**，集中导出每个图标的 SVG 字符串（约 24–28 个）。
- 新建 `src/components/icons/Icon.vue`：轻量包装，`<Icon name="copy" :size="16" />`，内部用 `v-html` 渲染字符串。
- **为什么用字符串而不是纯 Vue 组件**：代码块 / 公式 / 图表按钮是在 `.ts` 里用 `innerHTML` 拼出来的，纯组件在那边用不了；如果一边写组件、一边写字符串，就会变成两套定义、日后必然漂移。字符串作唯一真理源，两边共用。
- **图标从哪来**：从 **Lucide**（ISC 开源许可，可商用、可修改）复制 path，不手绘。手绘的结果就是今天这个局面。实际取的是 `lucide-static@1.58.0` 的官方 svg，未经二次加工。
- 这一步不改任何调用点，界面**零变化**，跑全量测试必须全绿。

### 第 2 步 · 替换 `.vue`（可见变化最大）

涉及 13 个文件 25 处（不含窗口按钮）：

| 位置 | 处数 | 图标 |
|---|---|---|
| 设置按钮（状态栏） | 1 | 齿轮 |
| 命令面板 / 搜索框 | 6 | 放大镜、上/下、关闭 |
| 字体 / 主题弹窗 | 2 | 字体 Aa、调色板 |
| 状态栏复制全文 | 2 | 复制、勾（顺便修掉 1.33 → 1.80 的跳变） |
| 大纲 / 列表折叠 | 2 | 折叠箭头 |
| 气泡菜单 | 3 | 链接、无序列表、清除格式 |
| 主题卡 / 主题导入 | 2 | 删除、上传 |
| 侧栏 / 其他 | 7 | 其余小图标 |

完成后：所有按钮里的线条粗细一致、端点一致。

### 第 3 步 · 替换 `.ts` 与字符图标（✅ 已执行，落地记录见 §八）

- `.ts` 里 7 处 `innerHTML` 的 SVG（代码块复制/勾、公式与图表的删除/缩放）→ 改用第 1 步的字符串常量，同一份定义。
- 斜杠菜单 14 个字符图标 → 换成真图标。这一步需要菜单渲染支持结构化图标（当前 `icon: string` 直接当文字渲染），改动比前两步大。
- 气泡菜单 4 个字符图标（`</>`、`A`、`H1`、`H2`）→ 同上。

## 五 · 你会看到什么

1. 所有图标的笔画一样粗细，不再"有的重、有的轻"。
2. 状态栏点「复制全文」，勾不再突然变粗。
3. 斜杠菜单从"文字符号"变成真正的图标，和界面其它地方是同一套语言 —— 这是视觉变化最大的一块。
4. 部分图标会**略微变细或变粗**（向中位 1.33 收敛）：原 1.50 的变细一点，原 1.12 的变粗一点。这是统一的必然结果，不是退步。

## 六 · 风险与验证

| 项 | 说明 |
|---|---|
| 数据链 | **零接触** —— 纯 UI 渲染，不碰 parser / serializer / schema / 保存 / 剪贴板内容 |
| 出站影响 | 复制到外部时按钮会被剥离（现有逻辑），图标改动不会进入 .md 或导出内容 |
| NodeView 风险 | 代码块 / 公式 / 图表的按钮在 NodeView 内，替换后要跑 `nodeview-destroy.spec.ts` 确认销毁链路不受影响 |
| 验证方式 | 每步跑全量测试 + 目视对比截图（逐类目视：侧栏 / 状态栏 / 浮层 / 编辑器内 / 菜单） |
| 回滚 | 每步单独提交；第 2、3 步可单独 revert，互不牵连 |

## 七 · 拍板结果（2026-10-17）

用户拍板原话：「同意执行，分三次交付，确保安全，确保完成质量」。据此定：

1. **线宽 2** —— 按推荐值，等于现有图标的中位，改动最自然。
2. **斜杠菜单 14 个字符图标** —— 随第 3 步一起换（即第三次交付）。
3. **节奏** —— 三次交付：① 建库 ② 换 `.vue` ③ 换 `.ts` 与字符图标。每步单独提交、单独可回滚、每步跑全量。

## 八 · 执行记录

### 第 1 步 · 建库（2026-10-17 ✅ 已完成）

- 新增 [`svg.ts`](../src/components/icons/svg.ts)：**28 个图标**的 path 数据，取自 `lucide-static@1.58.0` 官方 svg，未二次加工。
- 规格唯一出口 `ICON_PROPS`：24 画布 / 线宽 2 / round 端点 / currentColor / `aria-hidden`。**改规格只改这一处**，组件与 `.ts` 侧都不重复声明。
- 新增 [`Icon.ts`](../src/components/icons/Icon.ts)：函数式组件，**不套任何包装元素**（直接渲染 `<svg>`），避免破坏使用处既有的 `svg { … }` 选择器；尺寸默认 16、可按需传。
- `.ts` 侧用 `iconSvg(name, size)` 取同一份图源字符串 —— 不存在第二套定义。
- **本步不接任何调用点，界面零变化。**
- 契约锁 [`icon-spec.spec.ts`](../src/components/icons/__tests__/icon-spec.spec.ts) **7 条**：清单稳定 / 内容合法（无外壳·无脚本·无事件属性·无硬编码颜色）/ 只用标准 SVG 元素 / 规格常量 / `iconSvg()` 产出 / 组件裸渲染无包装 / 默认尺寸。
- 验证：全量 **1901 passed / 0 failed**（基线 1894 + 新锁 7，数目对得上）；`vue-tsc` 0；`npm run lint` 132 warnings / 0 errors（与改动前持平）。
- 反向校准三组（**各自单独撤**）：改线宽为 1.5 → 3 条红；往图标塞 `<script>` → 3 条红；改默认尺寸 → 1 条红。还原即复绿。
- 回滚：删掉 `svg.ts` / `Icon.ts` / `icon-spec.spec.ts` 三个文件即可（未接调用点，零影响）。

### 第 2 步 · 换 `.vue`（2026-10-17 ✅ 已完成）

- **替换 22 处**内联 svg，涉 13 个 `.vue` 文件（标题栏 / 搜索面板 / 气泡菜单 / 状态栏 / 大纲 / 命令面板 / 字体弹窗 / 主题弹窗 / 主题卡 / 主题选择 / 设置弹窗 / 图片全屏 / 根组件）。窗口控制按钮 3 处按 §附 保留。
- **新增 8 个图标**（总数 28 → 36）：`eye` / `pin` / `chevronLeft` / `arrowDownUp` / `plus` / `grid` / `listTree` / `eraser`。
- **删掉两个「影子图标组件」**：`CloseIcon.vue` 与 `CheckIcon.vue`（各写死 24 画布 / 线宽 1.5），6 处引用改用 `<Icon name="close|check">` —— 否则「一份定义」永远不成立。
- **三处形态调整**（都是为了让 24 画布 / 线宽 2 在小尺寸下不失真）：
  - 搜索面板上/下三角（实心 10px）→ `chevronUp/Down` **14px**：24 画布配 10px 显示，实际线条只有 0.83px，会发虚。
  - 大纲收起箭头 12px → `chevronLeft` **14px**；搜索关闭 10px → `close` **14px**。
  - 导入主题的加号 28px → `plus` **24px**：28px 显示时线宽会到 2.33px，比别处粗一档。
- **两处状态样式跟着改选择器**（原来挂在内部子元素上，换图源后子元素变了）：
  - 置顶按钮激活态填充：`.pin-shape` → `.titlebar-pin-icon`（整枚填充，视觉同前）；旋转原点 7.5px → 12px（画布 15 → 24）。
  - 焦点模式眼睛的瞳孔：`.eye-pupil` → `.focus-eye-icon circle`（图源里瞳孔是唯一 `<circle>`）。
- **顺手消灭的老毛病**：状态栏「复制全文」点完变勾时，线条从 1.33px 突变到 1.80px（粗 35%）—— 现在两个状态同尺寸同线宽，永久不再发生。
- **新增使用锁** [`icon-usage.spec.ts`](../src/components/icons/__tests__/icon-usage.spec.ts) **2 条**：① 白名单之外任何文件内联 `<svg>` 即红；② 白名单内（窗口按钮 + 第 3 步待迁移的 7 处 `.ts`）**处数只许减不许增**。这是本方案真正的防复发机制 —— 没有它，过半年又会散。
- 契约锁 [`icon-spec.spec.ts`](../src/components/icons/__tests__/icon-spec.spec.ts) 增至 **8 条**（新增「外部 class 透传到根 `<svg>`」—— 使用处的尺寸样式全靠它）。
- 验证：全量 **1904 passed / 0 failed**（1901 + 新锁 3）；`vue-tsc` 0；`npm run lint` **119 warnings / 0 errors**（改动前 132，减少 13 —— 内联 svg 的多行换行警告随替换消失）。
- 反向校准两组：白名单外塞一处 svg → 第 1 条红；标题栏加到 4 处 → 第 2 条红。还原即复绿。
- 回滚：`git revert` 本提交即可（新图标共存，不依赖第 1 步之外的东西）。

### 第 3 步 · 换 `.ts` 与字符图标（2026-10-17 ✅ 已完成）

- **`.ts` 4 文件 7 处**全部改成 `iconSvg()`：代码块（复制 ×2 / 对勾 ×1）、公式块与图表块（删除 ×2 / 放大 ×1）、列表折叠箭头（×1）。`icon-usage.spec.ts` 白名单**已清空到只剩标题栏 3 处**。
- **新增 2 个图标**（36 → 38）：`lightbulb`（「重点」块）、`zoomIn`（图表放大）。图标库本来就有 `heading1/2/3`，第 3 步直接取用，不新增。
- **斜杠菜单 14 项：`icon: string` → `icon: IconName`**。这是本步的结构改动 —— 改前每项各填一个字符（`¶` `H1` `•` `☐` `❝` `▎` `<>` `—` `⊞` `∑` `◈` `1.`），混了排版符号 / 文字标签 / 伪图标三种性质，且没有规则约束；改后填错名字**编译期就红**，也不可能再退回「随手打个字符」。渲染侧只改一行：`{{ item.icon }}` → `<Icon :name="item.icon" :size="16" />`。
- **气泡菜单 3 处**：`</>` → `code`、`H1`/`H2` → `heading1`/`heading2`，与斜杠菜单**共用同一份键**（改前 H1/H2 两处各写一遍）。按钮补 `title`，`</>` 的 `font-mono` 内联样式随之删除。
- **气泡菜单标题按钮尺寸 32×32**：原来装 12px 文字（`padding: 4px 8px`，实际约 24px 高），换成图标后与同排 `bubble-menu-btn` / `bubble-menu-clear-btn` 拉齐，避免同排热区一大一小。
- **本步不需要改菜单渲染结构**（原方案预判「需小改以支持结构化图标」）：图标本身就是 Vue 组件，`<Icon>` 直接放进原位置即可。
- **新增契约锁** [`menu-icons.spec.ts`](../src/components/Editor/tiptap/extensions/__tests__/menu-icons.spec.ts) **3 条**：① 14 项的图标键都存在于图标库；② 键必须是 ASCII 标识符（挡回退成字符）；③ 气泡菜单不许再内联字符字形（`&lt;/&gt;`、`>H1<`），且必须使用 `heading1`/`heading2`。
- **新增渲染锁** [`slash-menu-render.spec.ts`](../src/components/Editor/views/__tests__/slash-menu-render.spec.ts) **1 条**：挂载菜单后 14 个图标格必须都是 `<svg>`、且**格内没有文字** —— 数据层对了、模板仍可能退回 `{{ item.icon }}`（屏幕上会印出 `paragraph` 字样），这条挡的就是那种回退。
- 验证：全量 **1908 passed / 0 failed**（1904 + 新锁 4）；`vue-tsc` 0；构建通过。
- 反向校准**四组，各自单独撤**：① 某项改回 `'¶'` → 锁 1、2 红；② 往 `.ts` 塞一处内联 svg → 使用锁 1 红；③ 气泡菜单改回文字 `H1` → 锁 3 红；④ SlashMenu 模板退回插值 → 渲染锁红。还原即复绿（已 `diff` 核对字节一致）。
- 回滚：`git revert` 本提交；锚点 `backup/20261017-1130-pre-batch3-step3`。
- **遗留观感待人工确认**：列表折叠箭头由 12 画布 / 线宽 1.6（11px 显示 ≈1.47px）换成 24 画布 / 线宽 2（≈0.92px），会略变细；嫌淡可单独把该处恢复为自绘（唯一例外）。

## 附 · 不在本方案范围

- 窗口按钮（最小化 / 最大化 / 关闭）：保留 10px 系统惯例，不纳入统一。
- H1–H6 的行首角标：那是 CSS 文字标记（`content: 'H1'`），属于结构提示不是图标，不动。
- 应用图标（`.ico` / `.png` 等安装包图标）：另一套资产，与本方案无关。
