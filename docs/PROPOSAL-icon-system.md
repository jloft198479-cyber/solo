# 图标系统统一方案（2026-10-17）

> **本文只界定问题与方案，未改任何代码。** 待你拍板线宽与范围后开工。

## 一 · 一句话结论

问题不是"图标不好看"，而是**没有统一规格**：同一个界面里，线条实际粗细从 1.12px 到 1.80px，差 61%。统一成一套规格后，所有图标的笔画、端点、拐角才会看起来是"一个人画的"。

## 二 · 现状取证（全部实测，非估计）

### 2.1 三种"不统一"

| 维度 | 实际情况 |
|---|---|
| 画布尺寸 | **7 种**：24×24（11 处）、16×16（6）、15×15（6）、10×10（5）、12×12（2）、28×28（1）、10×1（1，最小化横线） |
| 线宽 | **8 种**：2（8 处）、1.5（7）、无描边（7，实心）、1.2（6）、1.3（1）、1.4（1）、1.6（1）、1.8（1） |
| 图标来源 | 内联 SVG 32 处（17 个文件）+ 系统字符 18 个（斜杠菜单 14、气泡菜单 4） |

关键点：**线宽数值不同不代表视觉不同，真正决定观感的是"线宽 × 显示尺寸 ÷ 画布尺寸"**。算出实际像素后差异就藏不住了：

| 界面位置 | 画布 | 线宽 | 显示尺寸 | 实际线条 |
|---|---|---|---|---|
| 状态栏「已复制」勾 | 16 | 1.8 | 16px | **1.80px** |
| 顶栏按钮 / 字体弹窗 / 主题弹窗 | 16 | 1.5 | 16px | 1.50px |
| 大纲折叠 | 12 | 1.4 | 12px | 1.40px |
| 状态栏复制 / 气泡菜单清除格式 | 24 | 2 | 16px | 1.33px |
| 命令面板 | 15 | 1.3 | 15px | 1.30px |
| 代码块 / 公式 / 图表按钮 | 24 | 2 | 14px | 1.17px |
| 搜索框 / 标题栏固定 | 15 | 1.2 | 14px | 1.12px |

### 2.2 最能说明问题的一处

状态栏的「复制全文」按钮：未点击时是 24 画布 / 1.33px，**点一下变成勾，立刻换成 16 画布 / 1.80px** —— 同一个按钮、同一个位置，切换状态时线条突然粗 35%。这不是设计，是两段代码各写了一遍。

### 2.3 字符图标（最不一致的一套）

斜杠菜单的 14 个图标是系统字符：`¶` `H1` `H2` `H3` `•` `1.` `☐` `❝` `▎` `<>` `—` `⊞` `∑` `◈`。它们由字体渲染，粗细、大小、对齐全部不可控，和旁边的 SVG 图标完全不是一种语言。气泡菜单里还有 4 个：`</>`、`A`（文字变浅）、`H1`、`H2`。

## 三 · 统一成什么规格

| 项 | 规格 | 理由 |
|---|---|---|
| 画布 | **24 × 24** | 业界标准（Lucide / Feather / Material 同尺寸），换库与抄 path 都零换算 |
| 线宽 | **2** | 在 24 画布下：显示 16px = 1.33px、显示 14px = 1.17px —— 正好落在现有图标的中位区间，改完最自然 |
| 端点 / 拐角 | `round` / `round` | 圆润收笔，符合 solo 的书卷气质；现已 27 处是 round，只差统一 |
| 颜色 | `currentColor` | 跟随文字色，主题切换自动适配，无需为深浅色各画一套 |
| 填充 | 默认 `none` | 描边风格；列表圆点、上下箭头等需要实心的单独保留（实心也走同一画布） |
| 尺寸 | 由使用处控制，组件不写死 | 同一图标在 14 / 16 / 20px 复用，不复制多份 |
| 例外 | 窗口按钮（最小化 / 最大化 / 关闭）保持 10px 细线 | 这是系统窗口控件惯例，跟应用图标混用反而怪 |

换算参照：24 画布下，显示 16px → 1.33px；显示 14px → 1.17px；显示 20px → 1.67px。**同一显示尺寸下必然一致**，这才是"齐"的本质。

## 四 · 怎么落地（三步，每步独立可回滚）

### 第 1 步 · 建库（不替换任何东西，纯新增）

- 新建 `src/components/icons/svg.ts`：**唯一的图源**，集中导出每个图标的 SVG 字符串（约 24–28 个）。
- 新建 `src/components/icons/Icon.vue`：轻量包装，`<Icon name="copy" :size="16" />`，内部用 `v-html` 渲染字符串。
- **为什么用字符串而不是纯 Vue 组件**：代码块 / 公式 / 图表按钮是在 `.ts` 里用 `innerHTML` 拼出来的，纯组件在那边用不了；如果一边写组件、一边写字符串，就会变成两套定义、日后必然漂移。字符串作唯一真理源，两边共用。
- **图标从哪来**：从 **Lucide**（MIT 开源，可商用）复制 path，不手绘。手绘的结果就是今天这个局面。
- 这一步不改任何调用点，界面**零变化**，跑全量测试必须全绿。

### 第 2 步 · 替换 `.vue`（可见变化最大）

涉及 13 个文件 25 处（不含窗口按钮）：

| 位置 | 处数 | 图标 |
|---|---|---|
| 设置按钮（状态栏） | 1 | 齿轮 |
| 命令面板 / 搜索框 | 6 | 放大镜、上/下、关闭 |
| 字体 / 主题弹窗 | 2 | 字体 Aa、调色板 |
| 状态栏复制全文 | 2 | 复制、勾（顺便修掉 1.33 → 1.80 的跳变） |
| 大纲 / 列表折叠 | 2 | 折叠箭头 |
| 气泡菜单 | 3 | 链接、无序列表、清除格式 |
| 主题卡 / 主题导入 | 2 | 删除、上传 |
| 侧栏 / 其他 | 7 | 其余小图标 |

完成后：所有按钮里的线条粗细一致、端点一致。

### 第 3 步 · 替换 `.ts` 与字符图标

- `.ts` 里 7 处 `innerHTML` 的 SVG（代码块复制/勾、公式与图表的删除/缩放）→ 改用第 1 步的字符串常量，同一份定义。
- 斜杠菜单 14 个字符图标 → 换成真图标。这一步需要菜单渲染支持结构化图标（当前 `icon: string` 直接当文字渲染），改动比前两步大。
- 气泡菜单 4 个字符图标（`</>`、`A`、`H1`、`H2`）→ 同上。

## 五 · 你会看到什么

1. 所有图标的笔画一样粗细，不再"有的重、有的轻"。
2. 状态栏点「复制全文」，勾不再突然变粗。
3. 斜杠菜单从"文字符号"变成真正的图标，和界面其它地方是同一套语言 —— 这是视觉变化最大的一块。
4. 部分图标会**略微变细或变粗**（向中位 1.33 收敛）：原 1.50 的变细一点，原 1.12 的变粗一点。这是统一的必然结果，不是退步。

## 六 · 风险与验证

| 项 | 说明 |
|---|---|
| 数据链 | **零接触** —— 纯 UI 渲染，不碰 parser / serializer / schema / 保存 / 剪贴板内容 |
| 出站影响 | 复制到外部时按钮会被剥离（现有逻辑），图标改动不会进入 .md 或导出内容 |
| NodeView 风险 | 代码块 / 公式 / 图表的按钮在 NodeView 内，替换后要跑 `nodeview-destroy.spec.ts` 确认销毁链路不受影响 |
| 验证方式 | 每步跑全量测试 + 目视对比截图（逐类目视：侧栏 / 状态栏 / 浮层 / 编辑器内 / 菜单） |
| 回滚 | 每步单独提交；第 2、3 步可单独 revert，互不牵连 |

## 七 · 待拍板（三件）

1. **线宽**：2（推荐，等于现在的中位，改动最自然）还是 1.5（更细、更秀气，但 1x 屏可能发虚）。
2. **斜杠菜单的 14 个字符图标**：这轮一起换（工作量约占整批一半，但视觉变化最大），还是先换 SVG、字符图标另开一批。
3. **节奏**：一次做完三步，还是按 建库 → 换 .vue → 换 .ts/字符 分三次交付、每次你都能看到实物。

## 附 · 不在本方案范围

- 窗口按钮（最小化 / 最大化 / 关闭）：保留 10px 系统惯例，不纳入统一。
- H1–H6 的行首角标：那是 CSS 文字标记（`content: 'H1'`），属于结构提示不是图标，不动。
- 应用图标（`.ico` / `.png` 等安装包图标）：另一套资产，与本方案无关。
