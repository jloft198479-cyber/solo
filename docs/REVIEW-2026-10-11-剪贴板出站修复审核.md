## 3. ⚠️ 残留缺口：同类根因只封堵了一半（P1）

`stripZwnj` 收口只护住**序列化通道**；**NodeView 通道无人守卫**。探针（真实 schema + 真实往返）实测：`image.src / image.alt / image.title`、`wikilink.target / alias`、`mathInline.latex` 经 HTML 往返后**仍被 Tiptap `fromString` 强转成 number**（`image`、`wikilink` 的这三个属性都**没有自定义 `parseHTML`**，只有 `width/height` 有）。

其中**两处消费点会真崩**（探针调用真实函数实测）：

| 位置 | 表达式 | 探针结果 | 触发场景 |
|---|---|---|---|
| `image.ts:421` | `attrs.src.startsWith('https://asset.localhost/')` | **TypeError: src.startsWith is not a function** | 图片 src 为纯数字（如 `![](1)`）经复制粘贴 |
| `image.ts:453 → :68` | `formatImageMarkdown(attrs)` → `escapeImageAlt(attrs.alt \|\| '')` → `.replace` | **TypeError: alt.replace is not a function** | **图片 alt 为纯数字**（如 `![1](a.png)`）经复制粘贴 ⇒ NodeView 非编辑态渲染即崩 |
| `image.ts:70` | `attrs.title?.replace` | **TypeError: title.replace is not a function** | 图片 title 为纯数字 |

**已确认安全**（不必改）：`isRemoteImageSrc` / `isLocalRelativePath`（正则隐式 String 化）、`extractPathFromAssetUrl`（`new URL` + try/catch）、`callout.title`（3 处 `typeof` 守卫）、`math-inline`（`typeof` 守卫）、`serializer` 的图片/链接/加粗消费点（均经 `stripZwnj` 收口）、`useEditorSearch`（`String()`）。

> 严重度：与 P1-1 同级、同一根因，但后果不同——P1-1 是「存不了盘」，这里是「**粘贴后 NodeView 直接抛错**」（更靠前，无需存盘）。触发概率取决于 alt/src 是否纯数字，**alt 纯数字并不罕见**。

## 4. 修复建议（供拍板）

1. **治本（推荐）**：给 `image.alt/src/title`、`wikilink.target/alias` 补显式 `parseHTML: (el) => el.getAttribute('x') ?? ''`（与本次脚注同一手法、纯加法）。**更彻底的一步**：把「所有字符串属性统一走显式 `parseHTML`」固化成一个约定/工具，避免同类第三次复发。
2. **不建议**在 NodeView 各消费点散加 `typeof` 守卫——按禁令 #11，那是加法扩散；只在治本落地前作为临时兜底。
3. `zwnj.ts` 收口处建议登记一行指针：「`fromString` 强转的完整消费点清单」——收口放宽为 `unknown` 的代价正是「类型系统不再提示哪些通道可能非字符串」，需要文档补位。
4. P1-4 / P2-1 维持「另案拍板」；本轮 commit 处置正确。
