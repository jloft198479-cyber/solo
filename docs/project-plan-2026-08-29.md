# solo 产品演进计划（建议稿）

> **日期**：2026-08-29
> **性质**：本文是**建议清单，不是强制任务**。每条都可执行、也可不执行；部分条目可能因优先级或方向变化而搁置。请勿将其视为死命令。
> **定位基线**（已与简乐共识，详见项目记忆 MEMORY.md）：solo 是个人化的**阅读 + 写作**工具，**无协作因素**，**不追超长文档**（超长用其他工具）。内核保持 ProseMirror（Typora 式纯净观感是核心卖点，不换 CodeMirror 6）。

---

## 〇、为什么是这份清单（背景）

本轮讨论澄清了两件事，整份计划都建立在它们之上：

1. **不换内核**。上一轮曾建议用 spike 验证 CodeMirror 6，但在「不追超长文档」定位下撤回——PM 的「全量 DOM」劣势不在射程内，而换 CM6 要牺牲纯净观感，不划算。
2. **不删功能**。20 个扩展经逐一核查均有价值（尤其从别处复制内容来 solo 阅读时，公式/流程图/脚注/双链/代码块必须能正确显示）。`dim` 是 2026-08-21 正式提交的功能（带气泡菜单+命令面板+1035 项测试），非死代码。**任何功能都只在「磨手感」层面优化，不删。**

> 纪律红线（来自《丝滑体验优化复盘》）：**绝不用 JS 拦截原生滚动**；**一次只改一个维度、独立可回退**；**体感必须简乐亲自实测前置**。反对「一次性打包多维度优化」——那次正是全面回退的根因。

## 一、必做类（Bug / 保命，与方向无关，独立可测）

### 1. 关闭时误提示保存
- **现象**：未打开或修改任何文档，直接关闭窗口也弹「是否放弃更改」。
- **证据链**：
  - 关闭入口 `useAppWindowSession.ts:133 handleCloseRequest` → `options.isDirty()`
  - `useDocumentSession.ts:117 evaluateDirtyFromEditor()` 在关窗时**无条件** `getContent()` 重新序列化，再 `syncEditedContent`
  - `file.ts:57-66 syncEditedContent` 仅规整末尾换行后做字符串比较
  - `useDocumentSession.ts:124-139 confirmDiscardUnsavedChanges` 早返回条件：`!path && !content.trim()` 才跳过——只要 content 非空（如启动默认文档 / 上次自动载入的文件）就会进入比较
- **根因假设（待实测验证）**：磁盘原文经「解析→编辑器→序列化」后**与原文非逐字节一致**（Markdown round-trip 常见），导致零编辑也被判脏。属 `file.ts:53` 注释所指「误标脏」同类问题。
- **建议方向**：关窗评估脏态时，优先用「载入时记录的基线哈希 / docVersion」判断，避免重新序列化比对；或载入后即把基线设为序列化产物而非原始磁盘文本。

### 2. 大文档关闭卡死 / 强制序列化
- **现象**：打开 4–10MB 文档，关窗瞬间卡死甚至关不掉。
- **证据**：`useDocumentSession.ts:117-122 evaluateDirtyFromEditor` 在未改动时也调 `getContent()` 全量序列化；与条目 1 同源。
- **建议方向**：加 `docVersion` 版本号，未改动则不序列化；关窗加「逃生舱」强制关闭通道；粘贴超阈值时温和提示（而非等卡死）。详细热点与分阶段方案见 `docs/large-document-performance.md`（该文档以「追超长文档」为前提，本计划下**仅 P0 保命部分适用**，分块装载等 P2 项已搁置）。

## 二、信任感层（从「能用的编辑器」到「敢每天打开的写作工具」）

> 以下四条是**信任问题**，不是优化。一个人只有确信「它不丢字、它记得我读到哪」，才会把重要东西交给它。

| 条目 | 现状证据 | 说明 |
|---|---|---|
| 阅读位置记忆 | `MarkdownEditor.vue:229` 打开即 `focus('start')` | 每次打开回到开头，长篇阅读硬伤 |
| 崩溃恢复 / 自动备份 | 全项目无备份机制 | 写作工具最怕「字会不会丢」 |
| 最近文件列表 | 无 | 个人工具靠文件管理器找文档，割裂 |
| 跳转历史 / 标题折叠 | 无 | 大纲跳过去回不来；长文缺基本导航 |

**建议**：先做「阅读位置记忆」+ 关窗保命（条目 1、2），做完一步简乐实测一步。

## 三、手感层（每天碰几千次，单条不起眼、累积定体验）

- 中文输入法手感（IME  Composition 稳定性）
- 排版质感：字号 / 行距 / 字体落点的视觉舒服度
- 滚动：严守「CSS-only，绝不用 JS 拦截原生滚动」
- 焦点模式（`paragraph-focus`）：已存在，可再深挖「只照亮当前段、其余变暗」的观感与性能

> 此层**不加新功能**，只把已有的打磨到位。再支持第 18 种代码语言对一天体验影响为零；把光标移动手感调顺，影响是几千次。

## 四、字体源迁移（国内服务器）

- **现状**：`fontLoader.ts:7` 写死 `https://github.com/jloft198479-cyber/solo/releases/download/fonts-v1`（GitHub releases，国内访问慢/不稳）。
- **目标**：迁到国内 CDN（七牛 `solo-fonts` 桶 `fonts-v1/`）。
- **已知阻塞**（来自项目记忆，2026-08-23 用户置顶·当前搁置）：
  - 七牛绑定域名 `vip.weimabbs.com` 解析仍指向旧服务器 `111.172.233.113`，访问 `https://vip.weimabbs.com/fonts-v1/<字体>` 返回 404；七牛默认测试域名 SSL 报错，生产不可用。
  - 5 个字体已上传七牛桶内（大小核对无误），但域名未生效。
- **已调研可行方案**（曾获「改吧」授权，受「搁置」指令未实施）：`fontLoader.ts` 改「七牛优先 + GitHub 兜底」双源重试；Rust `fetch_font_data` 用 URL 末段作缓存名，两源末段一致可复用缓存。
- **前置条件**：先解决 CDN 域名生效（CNAME+HTTPS 实测 200），再改代码。

## 五、明确不做（边界，防范围蔓延）

- ❌ 换编辑器内核（CodeMirror 6 / 虚拟滚动）
- ❌ 删减任何现有功能扩展
- ❌ 协作功能（明确无协作因素）
- ❌ 插件市场 / 通用 API 扩展点（与「极简」天然冲突；极简靠「拒绝」而非「可拓展」维持，产品精神文档已定调）
- ❌ 追超长文档的分块装载 / 只读渲染器（超长用其他工具）

## 六、优先级与依赖（建议排序，非锁定）

| 序 | 条目 | 性质 | 依赖 | 工时估算 |
|---|---|---|---|---|
| 1 | 关闭误提示保存（一.1） | Bug | 无 | 0.5–1 天 |
