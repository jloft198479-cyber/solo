# solo 互链方案

> **状态**：v4。在 v3（外部审计逐条独立复核 + 用户拍板"拖入=看落点方案 B"）基础上，**回到 solo 立项原点做了一次第一性原理校准**——据此修正了"向主流看齐"的含义，并把"引入院子(vault)"从路线图项降级为"默认不做"。**待你确认最后一项（C 档是否先真机眼验）**，未动源码。正文大白话讲逻辑；附录留给执行的人看技术指针。

---

## 第一性原理校准（对照 solo 产品精神）

读完 `docs/solo产品精神.md` 与 `docs/architecture：产品开发总原则.md`，先回到"这产品为什么存在"，再判方案每一步该不该做。

**solo 的立项原点**（作者原话大意）：他体验过 Typora、Obsidian，觉得"都不太舒服"；**他明说 Obsidian 是拿来做知识库的，而他真正想要的是"像 Windows 记事本那样轻巧的单文件 Markdown 编辑器"——随手在桌面建一个 `.md`、就地改、随处存，不要知识库那种侧边栏和复杂功能；起名 Solo，取"心流"，随时开关、不给人压力负担。** 由此推出三条硬约束，正好用来卡这个方案：

- **极简 = 做减法不做加法**（决策阶梯第一级：推测性需求 = 不做）。
- **极速 / 资源节约**：不引入"递归扫目录、建库常驻索引"这类负担。
- **优雅 / 心流**：操作凭直觉、零记忆、无被打断感。

**据此校准三点：**

1. **"向主流看齐"要先看清看齐什么。** 我们看齐主流的**手法**（相对短路径链接、拖进来即在光标处成链接、目标不存在能一键建、不静默失败），但**不搬主流的地基（vault / 知识库）**——因为 solo 恰恰是为了"不变成 Obsidian"才被造出来的。所以"引入院子"不再是默认的二期目标，而是**另一层与立项初衷相冲的产品决定，默认不做**。

2. **"互链只圈同一目录"不是妥协，是正解。** solo 没有目录树、没有"我的库"，它天然的链接范围就是"这篇文件所在的那个文件夹"（人本来就把一簇相关笔记放一个文件夹）。这既守极简与资源节约，又刚好覆盖"就地引用旁边那篇"的真实诉求——是"停在决策阶梯最靠上那层"，不是功能缺失。于是 `[[` 候选"只列同目录"也顺理成章是**对的**，不是要补齐的短板。

3. **只修"会坏"，慎补"没做"。** B 档（`[[` 不弹、`![` 误吃）是**违反契约 / 退化安全的真 bug**（静默失败、把好输入毁成残骸），必修；C 档那些"敲了没反应"先真机眼验，且**即便没反应，补不补也先过 YAGNI + 极简**——单纯为对齐 Typora"人人都有"而加功能，违背产品精神，默认不加。

## 背景：这次要解决两件事

1. **敲 `[[` 弹不出文件候选**——你实测"任何状态下都不弹"。查清：一个"值没递到判断跟前"的接线遗漏，从 v1.2.43 起就一直死。顺带把所有"敲符号→变格式"的入口挨个体检，别只修一处、别漏同类。
2. **把一个文档拖进来，变成一条链接**——不是现在这样"换掉当前这篇、打开拖进来的那篇"。**不拍脑袋定规矩**，照主流笔记软件成熟做法来。

三条底线：**要安全、要丝滑、绝不引发新的 bug。**

## 问题一：修 `[[` 触发 + 符号入口体检（B 档已从 1 条扩到 2 条）

### 1. `[[` 补全为什么坏了（大白话）

开工前有一道"该不该弹"的判断，其中一条要"知道当前这篇存在哪儿"，才知道要链接的兄弟文件在哪个文件夹。判断本身没错，问题是**这个"存放位置"的值压根没被递到这道判断跟前**——它手里一直攥着空白，于是永远判"不弹"。旁边好几处（比如粘贴图片存盘）都递了，**就互链这个忘了**。

**修**：把这个值像别的功能一样正式递过去，一行接线。**护栏**：补一条"组装好之后、模拟敲 `[[` → 断言菜单真的弹出"的**集成锁**——上次栽在"零件测全绿、拼装那根线没人测"，别再犯。

### 2. 审计复核揪出的第二个真 bug：`![说明](路径)` 会被"链接直输"吃错

外部审计报了一条我上一版漏判的线索，我**独立复核过**——用 node 直接跑一遍那段正则：输入 `![说明](路径)`，匹配到的是 `[说明](路径)`（从第二个字符开始），然后链接直输的转换会把"说明"变成一条链接、`![说明](路径)` 变成 `!` + 链接（`href="路径"`）。**结果不是"图片没做"，是"图片语法被毁成一条不完整的链接、还留一个光秃秃的感叹号"**。

这属于**边敲边坏**，不是"缺功能"。修法也简单：给链接直输加一条"前面不能是 `!`"的守卫——**这个模式项目里已经有了**，`[[` 补全的守卫 (`suggestion-guard.ts:93`) 早就专门为 `![[` 加过同款守卫，证明作者知道 `!` 敏感，唯独漏了 `![`。

**结论**：`![...](...)` 从上一版的 C 档"待眼验"上调到 B 档"确认坏"。修 = 一行守卫 + 一条集成锁。

### 3. 顺手体检：所有"敲符号→变格式"的入口清单（三档）

**A 档｜代码里已确认"敲了就能变"，正常**：标题 `# `；加粗 `**`；斜体 `*(或下划线)*`；删除线 `~~`；行内代码 `` ` ``；高亮 `==`；上标 `^x^`、下标 `~x~`；普通链接 `[文字](地址)`（注意：受上面第 2 条影响，前面带 `!` 的图语法会坏）；无序 `- `、有序 `1. `、引用 `> `、分割线 `---`；公式块 `$$ `、流程图 ` ```mermaid `；以及**把整串 `[[文档名]]` 打完变链接**（这条与"弹候选"是**两个入口**，整串打是好的，坏的只是弹候选）。

**B 档｜确认坏（真 bug，两处）**：`[[` 弹候选（1）；`![说明](路径)` 被链接直输吃成残骸（2）。**都已定位到具体一行**。

**C 档｜代码里只看到"粘贴/打开时能认"、没看到"敲着能即时变"，需要真机眼验，别急着算 bug**：
- 表格：敲 `| 名称 | 数量 |` 能不能长成表格？（多半只吃粘贴或命令插入）
- 彩色提示块：敲 `> [!注意]` 能不能变？
- 脚注：敲 `[^1]` 能不能挂上？
- 待办勾选：敲 `- [ ]` / `- [x]` 能不能变复选框？

**判否（结构性事实，不算 bug、无需眼验）**：
- **元数据头 `---`**：敲头一行 `---` 会被**分割线抢走**（StarterKit 的 horizontalRule 输入规则生效），`Frontmatter` 又没有敲入侧规则——**编辑态根本不可能敲出元数据块**，只能靠粘贴/打开时识别。这是"为什么设计成这样"的事实，不列 bug、不必验。

## 问题二：拖进来即成链接（一期收紧到"同目录 + 看落点"）

### 主流标准答案（照抄不重造）

- 主流（Obsidian 为样板）的做法：**先有一个"大院子"（叫仓库/保管库）**，链接只写"文件名/院内最短的一条路"，从不写绝对门牌地址。"不同文件夹"就根本不是难题：只要还在院里的，就还是院内短路。
- 绝对门牌地址：主流**明知故避**——一动就断、还泄隐私。**所以"不同文件夹用绝对路径"这条我们不做**，那是别人踩烂了绕着走的老路。

### 但我们的实情卡在一个前提上

主流那套长在"有院子"上。**solo 是刻意没有院子的**——它是"一个文件就是一个文件"，作者当初就因嫌 Obsidian 知识库式侧边栏/结构太重才另做这款。所以"照主流做"照的是**手法**、不是**地基**：一期只做**不必院子也成立**的那块（同目录互链 + 拖入即插）；"要不要变成有院子"是另一层与立项初衷相冲的产品决定，**默认不做**（见"第一性原理校准"第 1 条）。

### 一期范围：只同一目录

**外部审计发现我上一版方案有个内部不一致**——"敲 `[[` 弹候选"这一入口，Rust 层只列同目录、不递归子目录（源码就一句 `fs::read_dir`，测例名字写着 "same dir"）。而我上一版"拖入一期"却承诺"往下子文件夹也能变链接"——**两条入口范围不对称**，会撞上"拖进来的能点，想用 `[[` 找却找不到"。

修法：**一期两条入口一律只圈"同一目录"**。
- `[[` 弹候选：只列同目录（本来就这样）。
- 拖入即链接：**只处理被拖的 .md 与当前这篇在同一个目录**；跨文件夹（含往下子目录）仍"打开"。
- **往下子目录能链接 + Rust 递归 + 候选上限重定 → 一起放二期**，一次守住两条入口的对称性。

### 一期判定方式：**看松手位置（方案 B，你已拍板）**

把"要变链接"还是"要打开"绑在**你松手的地方**，零记忆、最跟手，也是主流做法：

- **松手在正文里** → 把拖进来的 .md 变成一条链接，插在**当前光标处**。
- **松手在正文外（窗口边框 / 空白处）** → 仍按老规矩"打开"。

关键取舍（回应审计第 5 条）：只要"插到当前光标处"（沿用现在图片拖入的同一种做法），落点判定就**只是一个"是否落在正文里"的是 / 否判断**，**不需要**"屏幕坐标→文档精确位置"那步复杂映射。审计的顾虑因此绕开。剩下唯一要**真机验一次**的是高分屏 / 系统缩放下坐标换算准不准——这是**一期开工的第一件事**，验过就定。

**兜底**：万一真机发现命中判定在某些缩放下误判，回落到方案 A（按住 Alt 才变链接）作安全网；B 走通就按 B。

**一期不做悬停提示**：事件层现在只转发"松手"这一件事、不转发"进入 / 悬停 / 离开"（`events.ts:35`）——要做悬停得先扩事件层，是新增改动、与落点判定无关，推到二期。

### 二期（可选延伸，且都不越"极简"的线）

- **子目录**：`[[` 候选与拖入一起支持"当前文件夹往下若干层"——用**按需有限递归读目录**（仍不建常驻索引 / 文件树），候选上限语义重定。是"就地这一簇"的自然延伸，不违背极简。
- **拖拽悬停提示**：先扩事件层转发 `enter/over/leave`（属加法、非必需，真需要再做）。
- **明确不做**：完整 vault、跨盘绝对路径、反向链接/图谱面板——它们要么撞"只读某几处"那道安全闸门，要么把 solo 推向它**刻意避开**的知识库形态（见校准第 1 条）。真有此类刚需，另起一次产品级讨论，不塞进本方案的默认路线。

## 三条底线怎么落到实处

**要安全**：一期不放开"只肯读某几处"那道闸门；不做绝对路径；生成的链接仍走已验证过的"存在性检查 + 目标不存在一键创建"链路（`MarkdownEditor.vue:180-229`，实测存在）。

**要丝滑**：把文档拖进正文一松手，立刻是"能点、能跳"的完整链接——**不用记任何按键、不用第二步**；两条入口（`[[` 与拖入）产出同一种链接对象，不搞两套；一期不做闪烁 / 遮挡式悬停反馈。

**不引发新的 bug**（你最担心的、也最要紧）：
- 每一步都是**可回滚的小提交**：修 `[[` 接线 → 修 `![` 守卫 → 拖入一期。出问题单独退回。
- 测试**补上"拼装后"这一层**（不只测零件）：`[[` 能弹、`![` 不误吃、拖入正文=插链接、拖入正文外=仍打开——各一条集成锁。
- **落点坐标真机验一次**（一期第一步）：不稳即回落 Alt 兜底，不带病上。
- C 档符号入口**先真机眼验再定改不改**，不凭推测乱动。
- 改完按项目规矩同步文档：使用手册、架构、已知问题、更新日志各回写一处。
- 涉及真机才准的（比如坐标），验前一律标"未验证"，不写"已提升体验"。

## 附录 A：技术指针（给执行的人看）

### `[[` 弹候选失效根因
`WikilinkSuggest` 的 `allow` 读 `this.options.getDocumentPath`（默认 `()=>null`），但 `editor-extensions.ts:304` 的 `WikilinkSuggest.configure({ suggestion:{…} })` **未把 `getDocumentPath: options.getDocumentPath` 递到扩展顶层**（对照同文件 `MarkdownPaste.configure :192-195` 已正确传）。漏递自 `6a28edd`（v1.2.43）起未修，HEAD v1.2.50 仍在。修 = 顶层补这一行 + 集成测试锁"敲 `[[` 能弹"。

### `![说明](路径)` 被链接直输误吃
`markdown-input.ts:447` 的 `linkInputRegex = /\[([^\]\n]+)\]\(([^()\s]+)\)$/` 无 `!` 前缀守卫；node 复测 `exec('![说明](路径)')` → `match[0]='[说明](路径)' index=1`。修 = 在 `convertPendingLink` 里判"起点前一字符若为 `!` 则跳过"，与 `suggestion-guard.ts:93` 的 `![[` 守卫同款。加集成锁"敲 `![alt](url)` 不吃链接、留字面文本或走图片路径（若一期支持）"。

### `[[` 补全候选不递归（一期收紧同目录的依据）
Rust `list_markdown_files`（`src-tauri/src/commands/document.rs:81-`）用 `fs::read_dir(dir)` 单层遍历，不递归；测例 `list_markdown_files_returns_sorted_md_names_in_same_dir` 明确"same dir"。**一期拖入范围与之对齐 → 同目录**。二期若要放开子目录，同步改 Rust 递归 + 上限 500 语义重定 + 前端 filter 支持 `sub/name`。

### 事件层只转发 drop（一期不做悬停提示的依据）
`events.ts:35` 里 `if (event.payload.type === 'drop' …)`，`enter/over/leave` 全丢。要悬停反馈，先扩 `subscribeDragDrop` 转发这三态并给 handler 签名兼容——是新增改动、非装饰，一期不做。

### 拖入现状与路由方案（一期 = 落点判定 B）
`subscribeDragDrop` 广播给所有 handler；`useAppWindowSession.ts:209-214` 无条件 `openDocument(首个.md)`、**不看 `position`**；`editor-image-drop.ts:41` 遇 `.md` 让路。一期做法 = 抽一个**单一路由判定（SSOT）**：拿 `payload.position` 做一次 `elementFromPoint` 命中测试——落在编辑区（`.tiptap-editor` 内）判"插链接"、否则判"打开"；Tauri v2 的 `position` 若为物理像素，用 `getCurrentWindow().scaleFactor()` 换算成逻辑坐标（**一期开工第一件事就是真机验这步准不准**）。判"打开"→ 交给现窗口 handler；判"插链接"→ 编辑器侧订阅者在**当前光标处**插 `wikilink` 节点（`replaceSelectionWith`，与图片 drop 同法，target=basename 去后缀、复用 `resolveWikilinkTarget`），走"存在性检查 + 一键创建"现成链路。**因只需是/否命中、不映射精确 doc pos，规避了审计的"屏幕→文档坐标"顾虑**；若真机发现命中不稳，回落 `event.altKey` 分流（方案 A）作兜底。

### 附带发现复核（不成立）
审计报 `resolveWikilinkTarget`（`wikilink.ts:35`）的 `/\.[^\\/]+$/` 会把 `v1.2/B` 误判"已有扩展"、不补 `.md`。我用独立测试脚本跑过：`v1.2\B`（Win 归一后）与 `v1.2/B`（posix）**均返回 false**（即"没有扩展"），`.md` 会正确追加。**理由**：字符类 `[^\\/]` 明确排除斜杠与反斜杠，点号后一旦遇到分隔符就终止匹配、`$` 不成立。**唯一命中的边界** = 最后一段本身就是 `.<后缀>`（如 `mynotes/v1.2` 或 `draft.v2`）——但那正是"看像扩展就不重复追加 .md"的合理设计。**结论**：不改方案，不登记 KNOWN-ISSUES。
