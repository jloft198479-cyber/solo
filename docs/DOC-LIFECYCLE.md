# 文档生命周期规则

> 一页纸。写文档前先读这一页，不必通读 DOC-STANDARD（那份管格式，本份管命运）。
> 依据：Diátaxis 四分类 · 文档五大死因 · ADR 不可变原则 · Atlas「归档而非删除」。

## 一、四区：位置决定命运

**放进哪个目录，就决定了它的命运，不需要每次判断。**

| 区 | 目录 | 放什么 | 维护 | 上传开源库 |
|---|---|---|---|---|
| **契约区** | `docs/` 顶层、`wiki/` | 长期有效的规则、指南、参考 | 常青，改代码要同步 | ✅ 传 |
| **决策区** | `docs/adr/` | 重大取舍（ADR），一页以内 | **只增不改** | ✅ 传 |
| **档案区** | `docs/archive/` | 一次性审核 / 排查 / 方案 / 交接件 | **写完即冻结** | ❌ 不传 |
| **阁楼区** | `docs/archive/_attic/` | 过期作废，只读 | 永不维护 | ❌ 不传 |

硬指标：**契约区「改代码前必读」的文档不超过 10 份**，超了就说明有东西混进来 —— 要么提升为契约，要么降级去档案区。

## 二、三标记：每份文档头顶写清

```
doc-life: evergreen | frozen
review-by: YYYY-MM-DD（常青才有；冻结写 —）
owner: 简乐
```

理由：业界判定「过期但看起来很新」是**最危险的文档状态**（比没文档更糟，会主动误导）。唯一解法是让它**看起来就旧**。

## 三、五动作：日常怎么运转

1. **提笔前先选区** —— 位置即命运，先决定归哪个区再写
2. **AI 产物默认落档案区** —— 我生成的审核 / 方案 / 交接件一律先进档案区；验证属实后才「提升」进契约区。这一条直接止住膨胀
3. **一次性产物命名带日期** —— 看到日期就知道是快照，不是契约
4. **季度归档 pass（15 分钟）** —— 扫契约区：还有效的留，过期的 `git mv` 进阁楼区（用 `git mv` 保住历史）
5. **文档更新跟着代码走** —— 改了代码就顺手改契约，不单独开「补文档」任务（单独开必然烂尾）

## 四、归档三规矩（Atlas 规则，直接采用）

- **归档而非删除**：过期文档移到 `docs/archive/[YYYY-MM]-描述/`，归档后**不改内容**
- **正式文档禁止链向阁楼区**：需要引用就抄结论进契约区，不链过去
- **AI 生成的实验性文档先落档案区**，验证后才提升

## 五、一句话规则

**问「这份文档该不该传 / 该不该删」之前，先问「它在哪个区」。**
区定对了，答案自动出现，不用每次重新讨论。
