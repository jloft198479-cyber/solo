## 三、🔴 [Major] G-1 `href` / `src` 仍是属性通道落点（本轮清单第三次漏一维）

- **位置**：`serializer.ts:388`（`mark.attrs.href` → `escapeLinkDestination`，未剥）、`serializer.ts:673`（`node.attrs.src` → 同一个函数，未剥）。
- **实测**（探针 C）：

  | 输入 | 内存脏属性 | 落盘 |
  |---|---|---|
  | `[x](u，**b)` | `mark.link.href` | `[x](u，[ZW]**b)` 🔴 |
  | `![i](p，**q.png)` | `image.src` | `![i](p，[ZW]**q.png)` 🔴 |
  | 存量 `[x](u\u200Cb)`（文件里本就有 ZWNJ） | `mark.link.href` | **原样写回，不清洗** 🔴 |
  | 存量 `![i](p\u200Cq.png)` | `image.src` | **原样写回，不清洗** 🔴 |
  | 同批对照：存量 `[[a\u200Cb]]` / `![ZW]图](x)` / `[^a\u200Cb]` | 脏 | **已剥干净** ✅ |

- **为什么又漏**：这一轮枚举的口径是「**看起来像文本的** attrs」（alt / title / label / target / alias），URL 型 attrs 不在直觉名单里。但触发机制完全同族——未闭合 `**` + 非 ASCII 标点，规则匹配的是 `(\*+)` 而非成对。**同一个不变量，判据又按语义分类切了一刀，就还会漏。**
- **可达性（如实说，别夸大）**：能落进 `href`/`src` 且带 `*` 的，主要是**远程 URL** 或含非 ASCII 标点的路径；Windows 本地文件名不允许 `*`，所以本地图片命中概率低。**但「存量脏不清洗」这一条不需要任何运气**：只要用户文件里已有这个字符，其他 attrs 都会被动洗干净、唯独 `href`/`src` 永久保留 ⇒ **同类行为不一致，且这是可稳定复现的**。
- **修复（一处顶两处，且天然防第四次漏）**：`href` 与 `src` **都只经过同一个函数** `escapeLinkDestination`（定义在 `serializer.ts:899`，全仓仅这两个调用点）：

  ```ts
  export function escapeLinkDestination(src: string): string {
    // stripZwnj：href / src 同属属性通道，解析期插的 U+200C 会落进来（台账 §二 #32）
    return stripZwnj(/* 原函数体 */);
  }
  ```

  改一处即覆盖两个写出点 + 顺带覆盖剪贴板 markdown 槽里的同类出站（那条路也调这两个点）。

## 四、🔴 [Major] G-2 修法层次不对称：attrs 只锁了「落盘」，没锁「内存态 / 渲染」

这一点是**他们自己定过、也写过注释、但这轮没推广**的：

- math 那一处的注释是：「入口剥一次 ⇒ **内存 / 渲染 / 落盘 / 剪贴板全部自动干净**（也顺带清洗存量脏文件），故序列化侧不重复剥」（`plugins/math.ts:11-19`）。
- attrs 这一轮做的是：**在各序列化写出点分别剥**（8 处改动 / 11 写出点）。
- 实测后果（探针 C 的「内存脏属性」列，修复后仍非空）：`[[a，**b]]` → `wikilink.target` 脏；`> [!note] 甲，**乙` → `callout.title` 脏；`![ZW]图](x.png)` → `image.alt` 脏 —— **markdown 落盘干净，但 doc 里的 attrs 依然带着隐形字符**。

**为什么这不算无事**：attrs 的消费方不止 markdown 序列化，实测存在的还有

- `extensions/wikilink.ts:66-67`（`const display = alias || target` → **直接进 DOM 渲染**）；
- `extensions/image.ts`（alt/src 进 `<img>` 的 DOM 属性，读屏与复制为 HTML 都取它）；
- 脚注 label 作为跳转配对键（HTML 侧的 `id`/`href`）。

⇒ 「打开一份带这形态的文件 → 互链显示的文字里躺着隐形字符 → 用户复制出去 / 搜索定位不到」这条链**这一轮没有断**。而且他们上一轮针对**正文**做的恰恰是「读出点各自剥」（字数、大纲、剪贴板），针对 **attrs** 却只做「写出点剥」——**同一个不变量在两处用了两种强度**。

**建议（二选一，我倾向前者）**：

1. **把 math 的做法推广到 attrs**：在解析期构造节点时剥一次（`wikilink.ts` 的 `create`/handler、`image` 的 alt 解析、`footnote` 的 label handler、`callout` 的 title 提取）。一处入口 ⇒ 内存 / DOM 渲染 / markdown 落盘 / 剪贴板 / 存量清洗**同时干净**，还顺便让 G-1 不再需要单独补 `href`/`src`（URL 也走同一入口）。
2. 若维持「出口剥」路线（改动面更小、不碰 parser），则**至少补 `escapeLinkDestination` 一处**（G-1），并在敏感区 #23 明写「**attrs 路线只保证落盘干净，内存态与 DOM 侧不保证**」——把这个已知边界写死，别让下一个人以为已经全净。

## 五、🟡 [Minor] G-3 新增的 ZWNJ 硬断言对 G-1 全盲（不是断言写错，是它管不到）

- **实测**：`SOLO_FIDELITY_SCAN=1` 跑 → 「扫描 110 份 md，ZWNJ 不出站 0 命中，断言绿」。而同一时刻 `href`/`src` 的漏洞确实存在。
- **原因**：断言① 判据是「**真实文档**落盘结果含 U+200C 即红」。仓库 110 份文档里没有 `](u，**b)` 这种 URL ⇒ 语料不覆盖，断言自然通过。
- **所以**：这条断言该留（它锁住了 alt/title/label 这类**真会在文档里出现**的形态，成本为零），但**不能把它当属性通道的兜底**。属性通道的兜底只能是 Phase A4 那种**直接构造**的锁——而那批锁本轮同样没覆盖 `href`/`src`。
- **建议（与仓库既有先例同构）**：`mark-delimiter-coverage.spec.ts` 已经证明「**全量集合比对，无需先登记**」这类锁在此项目行得通（台账 §一 #31 就是这么堵住「新增 mark 忘接载体」的）。照搬同一形状做一条 **attrs 通道全量锁**：

  > 遍历 `schema.nodes` + `schema.marks`，取每个 `spec.attrs[k].default` 为**字符串**的属性，逐个构造「该属性 = `甲\u200C**乙`、其余默认」的节点，序列化，断言输出不含 U+200C。任一新出现的字符串 attr 若出口没剥，**当场变红，不需要有人先想到它**。

  这样 G-1 属于「加进去就红」，而不是「等第三轮审核再人肉发现」。**唯一要注意**：`default: null` 的字符串属性（如 image `title`）无法从默认值判类型，需一份小清单兜住——这点在 spec 注释里写明即可。
- 棘轮基线那条（`RATCHET_BASELINE = 20`，注释「用实跑值，别抄历史数字」）**采纳了我 F-6 的口径**，实现正确；但注意它按 `> 基线` 才红，**噪声从 20 涨到 21 会红，涨到 19 需要人手动下调**——注释已交代，无问题。

## 九、一句话总账

这一轮把「出口收口」做成了**会红的锁**而不是散文，方向和质量都在线，我也确实在「未闭合 `**`」这一维上被实测打了个反证；但属性通道这条链**仍差 `href`/`src` 两个口**，而更根本的是：**同一个不变量，正文走读出点、math 走入口、attrs 走写出点，三处三种强度**——只要口径还是人肉列举，第四次漏只是时间问题。所以真正该补的不是第 12 个 `stripZwnj`，而是一条**遍历 schema 字符串属性、逐个构造脏值断言落盘干净**的集合锁：把「谁都得剥」变成机器的事。
