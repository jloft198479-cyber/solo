## 一、现象与判据（先确认是不是这个病）

打字时**输入法候选窗不跟光标，飘到屏幕角落**（微软拼音在右下角附近）。

- **不是 bug 的信号**：候选框贴在光标下方 = 正常（OK）
- **是 bug 的信号**：候选框飞到屏幕角 / 远离光标 = 失锚（HIT）
- **关键判据**：**角位恒定** —— 不是"偏了一点"，而是每次都落同一个角。这是输入法拿不到有效 anchor 时的**无锚点回退位**（韩文输入法在左上角，上游 issue 也报左上；「我们右下 / 上游左上」是同一机制，不是矛盾）。
- ⚠️ 该问题**概率性出现、无法按需复现**。判定"修好了"必须有对照，否则是假结论。

## 二、根因（一句话）

**上游 WebView2 缺陷**（`MicrosoftEdge/WebView2Feedback#5675`），stock Tauri 默认配置 + 裸 `<input>` 即可复现。**solo 进程内不可达**，等微软修。

## 三、有效绕法（已落地）

窗口**移动 / 缩放**稳定后（防抖 **120ms**）把可编辑元素**重锚一次**：

```
blur()  →  隔 60ms  →  focus()  +  还原选区与滚动
```

| 项 | 值 |
|---|---|
| 来源 | `observer130/lanmark` commit `ba451f0`（2026-10-07），同源项目、同一上游 issue、技术栈逐字相同 |
| 代码 | `src/components/Editor/tiptap/ime-anchor.ts`（接线在 `MarkdownEditor.vue` 的 `installImeAnchorGuard`） |
| 参数 | `IME_ANCHOR_DEBOUNCE_MS = 120`、`IME_ANCHOR_FOCUS_DELAY_MS = 60` |
| 触发面 | Tauri 原生 **`onMoved` + `onResized`** |
| 逃生阀 | `localStorage.setItem('solo:imeAnchorGuard','off')` 即时停用护栏（做 A/B 时用） |

⭐ **为什么必须挂 `onMoved`**：Windows **拖动窗口不发 `WM_SIZE`** ⇒ 不发 `Resized`，**只发 `Moved`**（`tao/src/platform_impl/windows/event_loop.rs:1210/1227`）。早期只挂 resize 所以没生效。用户反馈"**移动才是主因**"与源码事实吻合。

## 四、🚫 已证伪的死路（**最值钱，别重走**）

1. **合成鼠标事件注入** —— v1 `2ab8776`（触发器没接 `Moved`，从未开火）→ v2 `bed5f3b`（开火但**事前注入防不住**）→ v3 `001f358`（组字期 +250ms/+900ms 注入，**日志铁证：全部 ok=true 仍钉死**）。**三版全败**。结论：合成输入治愈不了，**手动真晃可以** ⇒ 依赖硬件级输入，进程内不可达。**此路已封死。**
2. **只 `focus()` / 同步 `blur+focus` / `setTimeout(0)` / 只挪选区** —— Lanmark 证明**全部无效**。必须有**真实焦点转移**且两次状态变化**拉开间隔**。
3. **换输入法** —— 用户换豆包输入法后症状**完全相同**，排除。
4. **JS 层抑制 DOM 变更（组字期保持 DOM 干净）** —— `composition-freeze.ts` 对"组字期 DOM 干净"有效，但对**飘角不是解药**（`#5625` 已证 JS 侧缓解无效）。
5. **"偏移一个位移量"类假说**（坐标缓存过期等）—— 解释不了**角位恒定**，已排除。
6. 其余已排除项：contentEditable、DOM 复杂度、DPI（100% 单屏也发作）、依赖升级、`MoveFocus(PROGRAMMATIC)`、`NotifyParentWindowPositionChanged()`、`EditContext`、透明输入代理层（裸 `<input>` 也复现）。

## 五、当前状态（如实记录）

- ✅ **2026-10-12 定案**：用户长期使用（10-09 起）**未再发作**，判定有效。已按修复档案阶段 4 清理临时设施 —— **删除** `ime-anchor-probe.ts`（被动探针）与 DEV-only 的 A/B 开关，护栏转为**常态功能**。
- ⚠️ **有效性是"体感级"证据，不是严格 A/B**：判据要求"关 = HIT 且 开 = OK"，但该问题概率性发作、"关"的样本凑不出来。真实结论是**装上后用户长期使用不再发作**。将来若复发，别急着否定护栏，先查上游。
- ⚠️ 已删的 A/B 开关**不可恢复**：如需重新对照，得临时改代码（模块内 `isDisabledBySwitch` 已移除）。

## 六、复发时怎么办

1. 先确认是不是同一个病（见 §一，重点看**角位是否恒定**）。
2. 查上游：`#5675` / `#5625` / `#1611` / `#2241` 有没有被微软修 —— 有则**直接删护栏**（它是绕法，上游修了就该拆）。
3. 若上游未修且症状变了：从 §四 的死路清单反推，**别重复投入**。
4. 需要重新做 A/B 时，用 §三 的逃生阀开关，别再写新的注入补丁。
