# 主题系统整改方案（推荐版）

> 前置：`AUDIT-2026-10-20-主题可定制性.md`（问题清单）、`REVIEW-2026-10-20-主题模板保真排查.md`（起因）
> 本文只给**一个推荐方案**，附带依据与取舍理由。有异议再改。

---

## 一、结论先行

**三条决策，其余全部随附：**

| # | 决策 | 一句话理由 |
|---|---|---|
| 1 | **排版与配色解耦**：全文级排版参数退出主题，局部视觉参数保留并校正 | 这是 VS Code / Obsidian 的共同做法：主题管"长什么样"，设置管"多大" |
| 2 | **补齐 6 个"零件色"**（圆点 / 表格线 / 引用边框 / 分割线 / 选中底 / 次级容器底） | Obsidian 的 CSS 变量清单里这 6 个全部独立成项，是 Markdown 主题的事实标准 |
| 3 | **8 个假开关分流**：2 个接通、6 个从模板移除 | 有 UI 对应却漏接线 → 接上；根本没有对应 UI → 别拿来骗用户 |

## 二、依据：两家业界基准怎么做的

### 2.1 VS Code —— 主题不碰字体尺寸

> 「VSCode 主题不控制字体，只管配色；字体大小需分别设置」
> 「主题（workbench.colorTheme）只定义侧边栏、状态栏、菜单等区域的背景色、文字色、图标色，
> **它不碰任何字体大小或字体族**」
> —— 多个来源一致【高】，例：https://m.php.cn/faq/2482261.html

VS Code 把「配色」和「排版」切成两个独立配置域：`workbench.colorTheme` vs
`editor.fontSize / editor.lineHeight / editor.letterSpacing`。改主题绝不会改变版式。

**这正是用户要的：「刷墙不能长高」。**

### 2.2 Obsidian —— 变量按"零件"组织，粒度极细

官方主题指南明确推荐「只覆盖内置 CSS 变量」，其变量清单【高，来源：Obsidian 官方开发者文档
https://docs.obsidian.md/Themes/App+themes/Theme+guidelines 及 CSS variables 参考】里：

| Obsidian 变量 | 管什么 | solo 现状 | 判定 |
|---|---|---|---|
| `--list-marker-color` | **列表圆点颜色** | 绑在 `text-secondary` | **缺，要补** |
| `--table-border-color` | **表格线** | 绑在 `border-color` | **缺，要补** |
| `--blockquote-border-color` | **引用块左边框** | 绑在 `primary-color` | **缺，要补** |
| `--blockquote-border-thickness` | 引用边框粗细 | ✅ `quoteBorderWidth` | 已有 |
| `--hr-color` | **分割线** | 绑在 `border-light` | **缺，要补** |
| `--selection-background` | **选中文本底色** | `primary 18%` 硬算 | **缺，要补** |
| `--metadata-background` | **frontmatter 底色** | 绑在 `sidebar-bg` | **缺，要补**（solo 一并并进 surfaceAlt） |
| `--code-background` | 代码块底色 | ✅ `codeBg` | 已有 |
| `--h1-size`…`--h6-size` | 标题字号梯度 | ✅ 接口里有，模板给了 | 已有 |
| `--nav-collapse-icon-color` | 折叠箭头色 | 绑在 `muted-color` | 收益小，**不做** |
| `--checkbox-color` / `-marker` | 勾选框 | ✅ `accent-color` 统一 | 够用，**不做** |
| `--h1-color`…`--h6-color` | 每级标题独立色 | 全继承 `text-color` | **不做**（见 §五） |
| `--table-header-background` / `--row-alt-background` | 表头底色 / 斑马纹 | 无 | 属**加功能**，留待后续 |

**注意一个关键区分**：Obsidian 给主题开放的排版参数是**局部尺寸**（引用边框粗细、标题字号、
表格行高），而全文行高 / 正文字号归「设置 → 外观 → 字体大小」。社区主题（如 AMOLED Serenity）
实际调的就是这些局部项，没有一个去改全文行高。

⇒ **局部视觉参数可以归主题，全文级排版不该归主题。** 这就是方案 1 的依据。

### 2.3 solo 已有的两个事实，也指向同一结论

- `settings.ts` 里已经有独立的 `fontSize` / `lineHeight` 设置项，且
  `applyCurrentTheme()` 会在主题注入后**再覆盖一次**这两个值（第 277-284 行）。
  ⇒ 产品实际上已经在走"排版归设置"的路线，只是模板没跟上，制造了双重真相。
- 9 套内置主题 `typography` 全部为空。
  ⇒ 产品的既定语义就是"主题 = 配色"。

## 三、方案细目

### 3.1 排版：4 进 4 出

模板 `typography` 段（现在 11 个字段，且 6 个值是错的）：

| 字段 | 现模板值 | 默认值 | 处置 | 理由 |
|---|---|---|---|---|
| `lineHeight` | 1.9 | 1.6 | **移除** | 全文级，归设置 |
| `fontSize` | 16px | 16px | **移除** | 全文级，归设置 |
| `letterSpacing` | 0.02em | 0 | **移除** | 全文级，归设置 |
| `paragraphSpacing` | 0.75em | 1em | **移除** | 全文级，归设置 |
| `heading1Size` | 1.875em | 1.6em | **保留·校正为 1.6em** | 局部视觉性格 |
| `heading2Size` | 1.5em | 1.3em | **保留·校正为 1.3em** | 同上 |
| `heading3Size` | 1.25em | 1.2em | **保留·校正为 1.2em** | 同上 |
| `heading4Size` | 1.1em | 1.05em | **保留·校正为 1.05em** | 同上 |
| `heading5Size` | 1em | 1em | **保留** | 值已正确 |
| `heading6Size` | 0.9em | 0.9em | **保留** | 值已正确 |
| `quoteBorderWidth` | 2px | 2px | **保留** | 局部尺寸，值已正确 |

- `ThemeTypography` 的另外 15 个字段（标题行高 / 标题 margin / 标题字间距 / 高亮圆角）
  **不进模板**，代码通道保留（`injectTypography` 不删）—— 高级用户已知字段名仍可手写。
- **不删 `injectTypography` 通道**：Obsidian 证明"主题带局部排版"是合理设计，
  通道留着，只是不把全文级参数摆到用户面前。

### 3.2 颜色：补 6 个零件色（新增 token）

全部按"带 fallback"写，不声明就退回今天的行为：

| 新增字段 | 新变量 | CSS 改法 | 现状色源 |
|---|---|---|---|
| `listMarkerColor` | `--list-marker-color` | `li::marker { color: var(--list-marker-color, var(--text-secondary)) }` | `text-secondary` |
| `tableBorderColor` | `--mk-table-border` | `th, td { border-color: var(--mk-table-border, var(--border-color)) }` | `border-color` |
| `quoteBorderColor` | `--mk-quote-border-color` | `blockquote { border-left-color: var(--mk-quote-border-color, var(--primary-color)) }` | `primary-color` |
| `hrColor` | `--mk-hr-color` | `hr { border-top-color: var(--mk-hr-color, var(--border-light)) }` | `border-light` |
| `selectionBg` | `--mk-selection-bg` | `::selection { background-color: var(--mk-selection-bg, color-mix(in srgb, var(--primary-color) 18%, transparent)) }` | 硬编码 18% |
| `surfaceAltColor` | `--surface-alt` | 代码块工具条 / 数学块 / frontmatter / 图片占位 / 斜杠菜单图标 / 设置底栏 6 处改引用 | `sidebar-bg` |

`surfaceAltColor` 的默认值 = 当前 `sidebar-bg` 的值（`#efe7d8` / `#1b232b`），
**改完视觉零变化**，只是把 7 路兼职切掉。`sidebarBg` 从此只管右侧大纲面板。

### 3.3 颜色：把已有但没暴露的 3 组补进模板

| 补什么 | 现状 | 为什么 |
|---|---|---|
| `markBg` | 接口有、模板无、**真实生效** | 高亮底色是最高频的定制诉求 |
| `accentColor` | 接口有、模板无、**真实生效**（3 处） | 9 套内置主题都声明了，模板不该独缺 |
| 6 种 callout（12 字段） | 接口有、模板无、**真实生效** | 13 种 callout 只给 6 种，用户会以为剩下 7 种不能改 |

### 3.4 8 个假开关：分两类处理

**A 类 · 有 UI 对应、只是漏接线 → 接通（各 1 行）**

| 字段 | 现状 | 接通方式 |
|---|---|---|
| `codeBorder` | `pre` / 代码块工具条边框写的是 `border-color` | 改成 `var(--code-border)` |
| `btnGhostBg` | `.ghost-icon-btn` 背景硬编码 `transparent` | 改成 `var(--btn-ghost-bg)` |

> `injectColors` 补齐 `removeProperty` 后，预设里的值会正常注入；两处改完即生效。

**B 类 · 根本没有对应 UI → 从模板移除，代码保留**

| 字段 | 为什么移除 |
|---|---|
| `tagBg` / `tagColor` | solo **没有标签功能**，只在主题缩略图里当装饰条 |
| `successBg` / `infoBg` | 没有 toast / 成功提示类 UI（`warning-bg`/`error-bg` 有真实用途，保留） |
| `shadowLg` / `shadowXl` | 弹窗走 `modalShadow`、浮层走 `popoverShadow`，这两级阴影无消费 |

**C · 4 个 radius 死字段** → 直接删（接口里不存在，且数值与真实刻度 2/3/4/8px 对不上）

### 3.5 汇总：模板字段数变化

| | 改前 | 改后 |
|---|---|---|
| colors 有效字段 | 64（68 含 4 个死字段） | 64 − 6（B 类）+ 6（零件色）+ 1（markBg）+ 1（accentColor）+ 12（callout）= **78** |
| typography 字段 | 11（6 个值错） | **7**（值全对） |
| **合计** | **75（12 个无效）** | **85（0 个无效）** |

## 四、明确「不做」的东西（避免过度工程）

| 不做 | 理由 |
|---|---|
| 拆 `mutedColor` 的 28 个消费点 | 拆成 6 个字段会让模板涨到 90+ 项；Obsidian 也是用一个大类变量兜住这些次要元素。**语义复用是设计系统的正确做法** |
| 每级标题独立颜色（`--h1-color`…） | Obsidian 有但社区主题极少用；solo 定位是极简写作工具，标题统一色更稳 |
| 拆 hljs 8 类语法色 | 已映射到功能色（主色/成功/警告/信息），拆开要加 8 个专属字段，投入产出比极低 |
| 滚动条独立色 | 收益小，`border-color` 派生已够 |
| 表格表头底色 / 斑马纹 | 这是**新功能**不是修 bug，单独排期 |
| 删除 `injectTypography`、删除 8 个预留变量 | 仓规明确「预留槽位勿当僵尸清理」。只是不给用户，不是不存在 |

## 六、验收口径

1. 下载模板 → **一个字不改** → 上传应用 → 屏幕上的行距、标题、圆点、所有颜色与当前主题**完全一致**
2. 只改 `primaryColor` → 链接 / 光标 / 语法关键字 / 勾选框变色；**表格线、分割线、代码块边框不变**
3. 改 `sidebarBg` → **只有右侧大纲面板变**；代码块工具条、数学块、frontmatter、设置窗口底栏不变
4. 改 `listMarkerColor` → **只有列表圆点变**
5. 改 `markBg` → 高亮底色变（今天做不到）
6. 改 `codeBorder` / `btnGhostBg` → 代码块边框 / 幽灵按钮背景真的变（今天做不到）
7. 模板里 85 个字段，**每一个改了都能在屏幕上找到对应变化**

## 8.3 与方案的偏差（4 处，均需知情）

| # | 方案说的 | 实际做的 | 原因 |

| 1 | `codeBorder` 接通「2 处」 | **3 处**（`code` / `pre` / 代码块工具条） | 工具条边框也是代码块的一部分，只改 2 处会露半截旧边 |
