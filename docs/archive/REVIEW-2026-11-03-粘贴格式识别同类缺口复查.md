### 本轮修复引入的 4 个副作用（复审实测，本报告确认）

| 编号 | 现象 | 后果 |
|---|---|---|
| N1 | 短路条件 `text.includes('\n\n')` 对 **CRLF**（`\r\n\r\n`）与「空行含空格」都不成立 | Windows 来源的表格**修复无效** —— 修了等于没修 |
| N2 | 表体循环跨空行继续吃含 `\|` 的行 | 表格后紧跟的「我选 A \| B 都行」被吞成表格最后一行（实测 rows 3） |
| N3 | 同上机制 | 相邻两张表（隔一空行）被并成一张（实测表数 1、5 行） |
| N4 | 不识别代码围栏 | 围栏内示范 markdown 表格时，空行被悄悄删掉（codeBlock 内容被改写） |

**这 4 条是我这次改动引入的静默改内容，属本项目最贵的事故类型，必须优先修。**

## 一句话结论

表格只是**最显眼的那一格**。同样的「门太窄」问题还有 7 处，分两类：  
**纯文本路径看漏**（链接 / 斜体 / 高亮 / 单行列表 / 缩进代码 / setext 标题 / 单行任务项）和  
**HTML 路径救不回**（塌方判定被一个 `<strong>` 短路 + 救援判据不认表格）。

## 一、纯文本路径：门在哪、漏什么

链路顺序（`markdown-paste.ts::tryParseClipboardMarkdown`）：表格 → 结构化 → 专有语法 → 整段 URL → 行内标记。  
**任何一道门全部落空 ⇒ 走 PM 默认纯文本粘贴 ⇒ 一行一段、markdown 符号原样留着。**

| # | 门的判据                                                            | 漏网形态（真实会遇到的）                              | 后果                                             | 严重度   |
| - | --------------------------------------------------------------- | ----------------------------------------- | ---------------------------------------------- | ----- |
| 1 | `hasInlineMarkdownSyntax`（:346）只认 `**粗**` / `` `码` `` / `~~删~~` | 只含 `[文字](https://…)` 的一段（AI 回答里最常见）       | 粘进来是字面 `[文字](https://…)`                       | **高** |
| 2 | 同上                                                              | 只含 `![](a.png)` 的图片引用（Obsidian 笔记复制）      | 字面文本，图片不显示                                     | 中     |
| 3 | 同上                                                              | 只含 `*斜体*` 的一段                             | 字面星号。⚠️ 单星号是**故意排除**的（防 `5 * 3` 误判）——属取舍，不是纯缺陷 | 低     |
| 4 | 同上                                                              | 只含 `==高亮==` / `^上标^` 的一段                  | 字面符号（solo 两种语法都支持，却没进门）                        | 中     |
| 5 | `looksLikeMarkdownSource`（:192）列表要&#x6C42;**≥2 行**              | 只复制**一条**清单项（`- 项` / `1. 项` / `- [ ] 待办`） | 字面 `- 项`，不成列表                                  | 中     |
| 6 | 同上，无「缩进代码块」判据                                                   | 4 空格缩进的代码段（部分编辑器复制出来是这种）                  | 字面文本，代码块不成立                                    | 低     |
| 7 | 同上，`---` 分支要求**文本以 `---` 开头**                                   | setext 标题（`标题` 上一行、`===` 下一行）             | 字面 `===`，标题不成立                                 | 低     |

补充一条**同一片区域但方向相反**的：`hasMarkdownOnlySyntax`（:224）的 `$…$` 要求**内部无空格**，所以 `$a + b$` 这类带空格的行内公式也不进门（纯文本粘贴会被当字面）。

## 二、HTML 路径：救援机制的两个洞（比上面更要紧）

大厂软件（Excel / Word / 网页 / 飞书 / 公众号）粘贴都走 HTML 路径。这条路上有一层「塌方救援」（`transformPasted` :663）：装饰性 HTML 被 ProseMirror 拍平成纯段落时，拿 `textContent` 反查 markdown 源救回来。它有两个洞：

| # | 洞                                                  | 触发形态                                                      | 后果                        | 证据                                                                     |
| - | -------------------------------------------------- | --------------------------------------------------------- | ------------------------- | ---------------------------------------------------------------------- |
| 8 | `isLowQualityParse`（:767）判据是「有**任意**行内 mark 就不算塌方」 | 来源把 markdown 当纯文本渲染（`<div>` 逐行 + `<strong>`），块级结构全丢但有一个加粗 | **不救援** ⇒ 表格/列表/标题全变成一行一段 | 已由既有测试锁现状（「段落含加粗 mark → 不塌方」）；台账 §一 #13 只登记了 font-weight 那一格，这是更宽的同款洞  |
| 9 | 救援判据只用 `looksLikeMarkdownSource`，**不含表格**          | 上面第 8 条命中（真塌方）且原文里有表格                                     | 判成塌方也救不回来，表格仍丢            | `markdown-paste.ts:663-676`，本轮新修的 `looksLikeMarkdownTable` **没有接进这条链** |

> ⚠️ 第 9 条是**本轮改动的未闭合口子**：纯文本路径修好了，HTML 路径的救援仍不认表格。

| #  | 现象                                                     | 判据                                                                                                                                                       | 后果                                    |

| 10 | **有序列表起始编号丢失**：`5. 甲 / 6. 乙` 打开变 `1. 甲 / 2. 乙`，保存即改写文件 | `parser.ts:502-503` 认真读了 `start` 并传给 `orderedList`，但 `editor-extensions.ts:326` 的 `OrderedList.extend` **没加 `start` 属性**，serializer 也不写 ⇒ 载体会被 schema 丢弃 | 用户写的编号跨度过一轮就没了（属「首存即改文件」家族，**台账未登记**） |

## 四、核实后「不是问题」的（免得后面重复怀疑）

- **`<del>` 删除线**：`paste-compat-decision.md` 里「只认 `<s>`」的旧结论**已过期**——`@tiptap/extension-strike` 实测 parseHTML 含 `s` / `del` / `strike`（读 `node_modules` 得证）。
- **下划线 `<u>`**：`editor-extensions.ts:247` 显式 `underline: false`，理由写在注释里（Markdown 无语法 + serializer 无 case，放开就是静默吞）。**设计取舍，不是缺陷。**
- **`<caption>` 表题 / `<dl>` 定义列表 / `<details>` 折叠块**：GFM 无对应表达，落下就是落下了（业界同）。**表达力天花板，不修。**
- **>2MB HTML 降级为纯文本**：体积熔断保命，设计如此。

| **P0** | 第 9 条救援链：**两处门一起改**（`transformPasted` 的判据 + `parseGeneralMarkdownPaste` 内部那道 `looksLikeMarkdownSource`），或让救援直接走 `parseMarkdownTablePaste` | 实测只改救援入口，纯表格文本仍 `null`（tables=0） |
| P1 | 第 1/4 条：行内门补 `[链接](url)` / `==高亮==` / `^上标^` / `~下标~` | 只在「纯文本且系统剪贴板无 HTML」时才丢；成本低 |

| **并入** | 第 8 条 → 台账 **§二 #13** | 同一根因（`isLowQualityParse` 被行内 mark 骗过），不单独立项 |
