# 阶段 0 · 文件字节体检报告

> 对应 `docs/PROPOSAL-file-fidelity.md` §2.2 的 5 个场景。**本轮没有改动任何实现**，只写测试。
> 所有数字以你自己跑出来为准（命令见文末）。

## 一句话

**W1 该做，范围不变。** 现状能做到「不改就不写盘」，但做不到「写过还能还原本来的字节」——因为归一发生在**打开那一刻**，不在保存那一刻。

## 二、五个场景实测

| # | 场景 | 结果 | 判定 |
|---|---|---|---|
| 1 | LF 文件 → 打开不动 → 保存 | 不写盘 | ✅ 安全 |
| 2 | CRLF 文件 → 打开不动 → 保存 | 不写盘，**但成立靠一条没写进任何文档的约定** | ⚠️ 脆弱安全 |
| 3 | CRLF 文件 → 打开静置（跨过自动保存） | 不写盘 | ✅ 安全 |
| 4 | 带 BOM 文件 → 打开不动 → 保存 | 不写盘，BOM 保住了；**只改一个字再存就永久丢** | ⚠️ 编辑即丢 |
| 5 | UTF-16 文件 → 改一个字 → 保存 | 文件变成 UTF-8 无 BOM（编码换了族） | ⚠️ 静默换族 |

**每条的依据**

| # | 证据 |
|---|---|
| 1 | `saveCurrentDocument` 的短路 + `markSynced()` 锚定代际 |
| 2 | 承重测试绿（`useDocumentSession.spec.ts`）；**反证测试**证明：基线换回磁盘原文，同一短路立刻失效 → 判脏 → 落盘 |

## 三、三个额外发现（比 5 个场景更重要）

### 发现 1：换行是在「打开」那一刻没的，不是「保存」那一刻

实测：`'# a\r\n\r\nb\r\n'` 进 `parseMarkdown` → `serializeMarkdown` 出来是 `'# a\n\nb\n'`。归一是 markdown-it 做的。

**这句话的价值**：如果以为是「保存时忘了回写换行」，那修法就是「保存时把 LF 换成 CRLF」——照着做会发现没数据可用，因为内存里 CRLF 早没了。**必须在打开时把磁盘的换行方式另存一份**，这正是方案 §2.1 的 `layout`。方案的设计方向在此被证实是对的。

### 发现 2：solo 的「基线」存的不是磁盘原文，是序列化产物

`MarkdownEditor.vue` 载入时做的是：

```
baseline = serializeMarkdown(解析后的文档)   // 不是磁盘原文
fileStore.setContent(baseline)
markSynced()
```

注释写明原因：存原文会让零编辑文档的比对永远不等，Windows 下 CRLF 必然误提示保存。

**这是「不改就不写盘」能成立的真正原因**，也是唯一让它成立的机制。**方案里没写这一条** —— 不写清，将来有人把基线改回存原文（看起来更「诚实」），W1 会静默失效，而且没有测试会红（原来的 M-03 回归锁是弱锁，见发现 3）。

### 发现 3：原有的 M-03 回归锁是「弱锁」

`useDocumentSession.spec.ts` 里那条「未修改时不写盘：Ctrl+S 不再把 CRLF 文件静默改成 LF」——**它既没给 `getContent` 也没给 `isSyncedWithStore`**。短路成立的原因是「拿不到编辑器内容」，不是「基线与编辑器一致」。把基线换回 CRLF 原文，它照样绿。

这就是记忆里记着的「假锁」：输入里没有病灶形状。已补两条承重的（一条正、一条反证），原有那条保留不删并标注。

## 四、对方案的影响

| 方案条目 | 体检结论 |
|---|---|
| F4「未编辑不写盘已成立」 | ✅ **成立**（rev1 降级为「待钉测」偏保守，现可改回「已证实，但依赖两行契约」） |
| §2.1 layout 由 Rust 收口并随 store 传递 | ✅ 方向被证实是唯一出路 |
| §2.2 验收第 3 条「什么都不改文件不变」 | ✅ LF / CRLF 都成立，**前提是发现 2 那个机制不被动** |
| §2.1 UTF-16 归一为 UTF-8 | ✅ 现状就是如此（静默），W1 要把它变成「明说」 |
| W1 范围 | **不变**（不需要先修脏态。原担心「打开后有任何事务就判脏」未发生） |

**新增必须进方案的一条（F7）**：基线存序列化产物 + `markSynced()`，是「不写盘」的唯一支点。W1 改 `save_document` 签名时**不能碰**这两行，并且要加一条锁：载入后 `isSyncedWithStore() === true`。
