# solo 全仓「无效工作 / 整篇重扫」审计（2026-10-19）

> 缘起：list-fold 修完「每键全量重扫」后，简乐问「之前修过多次还有漏网之鱼，类似的重扫 / 冗余 / 无效行为还有多少」。
> 方法：三路并行只读扫描（编辑器事务热路径 / Vue 响应式层 / Rust IO 层）+ 本方逐条核实代码 + 关键项实测。
> 原则：**只报能在代码里指到「谁触发 → 每次做多少工作」的**；查过没问题的地方也列出来，避免下次重复劳动。

---

## 一、结论先说

1. **编辑器事务热路径基本干净**。5 个装饰插件（list-fold / paragraph-focus / code-block / markdown-input / search-highlight）的 `apply` 全是 `map` 平移 + 局部处理；2 个 `appendTransaction` 的扫描都按变更区间限定。上一轮修的 list-fold 不是孤例遗留，这一层已经被系统性收拾过。
2. **漏网的头号问题是「光标行号」**：每 100ms 跑一次 O(光标前块数) 遍历，而算出来的行号**全仓没有任何地方读**（状态栏只显示「N 字选中」和字数）。实测 107KB 文档 1.42ms、282KB 文档 5.03ms，纯白烧。而且它的注释写着「复杂度从 O(光标前所有节点数) 降为 O(树深度 × 平均兄弟数)」——**跟 list-fold 那次一模一样的病：注释宣布优化了，代码没做到**。
3. **其余是量级更小的重复动作**：Mermaid / 公式块退出编辑时同一张图渲两遍（还不判内容是否真变了）、App 壳层被绑到一个每 500ms 变一次的内容快照上、Rust 侧两次「全目录扫」只在结果里取前 500 条。

## 三、发现清单（按严重度）

### P1 · 每 100ms 一次 O(文档) 计算，结果没人用

**`src/components/Editor/tiptap/editor-metadata.ts:62-85`（`getEditorCursorInfo`）**

```ts
for (let depth = $from.depth; depth > 0; depth--) {
  const parent = $from.node(depth - 1);
  const indexInParent = $from.index(depth - 1);
  for (let i = 0; i < indexInParent; i++) {
    const sibling = parent.child(i);
    if (sibling.isBlock) {
      line++;
      sibling.descendants((node) => { if (node.isBlock) line++; });  // ← 每个前序顶层块再全遍历一次
    }
  }
}
```

- **触发**：`onSelectionUpdate` → `useEditorSync.handleSelectionChange` → 100ms 防抖 → `getEditorCursorInfo`。写字时每次击键都重置防抖，**停笔 100ms 就来一次**；连续打字时几乎每键一次。
- **代价**：`depth === 1` 时 `parent` 就是 doc，循环遍历光标前**所有顶层块**，并对每块 `descendants` 数块级后代 ⇒ O(光标前全部节点)，实测见上表。
- **没有消费方**：`stats.cursor` 只在 `useAppEditorState.ts:39` 被写入；App.vue 状态栏只读 `stats.selectionLen`（`App.vue:405`）与 `stats.wordCount`（`:417`）。全仓 grep 不到读取 `stats.cursor` 的地方。
- **同函数的 `selectionLen` 是有用的**（状态栏「N 字选中」），不能整函数删。
- **修法**（择一）：
  - A（推荐，最简）：删掉 line/col 计算，只保留 `selectionLen`；`EditorCursorInfo.cursor`、`AppEditorUpdatePayload.cursor`、`stats.cursor` 一并清（死字段）。
  - B：行号改成「有人要看时才算」（比如将来做「跳转到行」再算，按需 O(N) 可接受）。
- **顺带**：注释「降为 O(树深度 × 平均兄弟数)」与实现不符，改 A/B 任一条都要把注释改对。

### P2 · 同一张图渲两遍 + 无变化也发事务

**`mermaid-block.ts:425-442` + `:508-514`；`math-block.ts:168-182` + `:228-235`（同构）**

```ts
editor.view.dispatch(tr);   // ← 同步触发 NodeView.update() → renderMermaid(node.textContent)
...
renderMermaid(newSource);   // ← 又一次全量解析/布局，结果把上一次的覆盖掉
```

- **触发**：每次退出 Mermaid / 公式块的源码编辑（点空白、Esc、Ctrl+Enter）。
- **代价**：`mermaid.render` 是解析 + 布局（复杂图 5–20ms 级，实测口径未测，量级来自其同步 API 特性）；KaTeX `renderToString` 同理。第二次结果因 `renderVersion` 自增被丢弃。
- **附带问题**：`exitEdit` 不比较 `textarea.value` 与原 `node.textContent` ⇒ **点进图表什么都不改再点走，也会发一个 docChanged 事务**，走满 5 个插件的 apply + `onUpdate` 深链（这条链在 107KB 文档上约 7ms，见 list-fold 报告口径 B）。
- **修法**：① 内容没变就不 dispatch；② 变了只 dispatch，删掉后面那次显式 render（`update()` 已经会渲）。两处都是 3 行内改动。

### P3 · App 壳层被绑到「每 500ms 变一次的内容快照」

**`App.vue:372`**

```html
:initial-content="fileStore.currentFile.content"
```

- **触发**：编辑停顿 500ms（持续打字时 2s 兜底）→ `syncEditedContent` 写 `currentFile.content` → App 模板依赖命中 → App 壳层（标题栏 / 状态栏 / 大纲 / 设置入口）整模板重渲染，并把新 prop 传给编辑器组件。
- **为什么是纯冗余**：子组件里 `createEditor(fileStore.currentFile.content || props.initialContent || '')`（`MarkdownEditor.vue:762`）——`fileStore` 分支永远优先，这个 prop **从未生效过**。
- **修法**：删掉该 prop 与 `MarkdownEditor` 的 `initialContent`（子组件内部已直接读 store）；或传一次性初始值不走响应式。

### P3 · Rust 两次「全目录扫，只取前 500」

**① `document.rs:126-152` `list_markdown_files`**（每次打开文档 + 每敲一次 `[[`）

```rust
let mut names: Vec<String> = fs::read_dir(dir)? ... .collect();   // 整目录
names.sort_by(|a, b| a.to_lowercase().cmp(&b.to_lowercase()));    // O(N log N)，每次比较 2 次堆分配
names.truncate(SAME_DIR_DOC_LIMIT);                              // ← 500 上限在最后才生效
```

- 上限只限制「返回值」，不限制工作量：1 万文件 ≈ 1 万次 String + 约 28 万次小写分配（仅排序），最后丢掉 99.5%。
- 修法：边读边收集、满 500 即停（排序仍需要全量？若要「前 500 个按名排序」就必须全读——**先确认产品语义**：是「按名取前 500」还是「任意 500 个排序」。若要前者，可用 `sort_by_cached_key` 减半分配）。

**② `document.rs:98` → `:791-834` `cleanup_stale_tmp_files`**（每次打开文档）

- 每次 `read_dir(父目录)`，且**在过滤前**就对每个条目 `to_string_lossy().to_string()` 分配。1 万条目录 = 每次打开 1 万次分配，只为找一个可能根本不存在的 `.xxx.tmp`。
- 修法：先按 `entry.file_name()` 的字节前缀零分配过滤；或把清理挪到「本进程写过 tmp」才触发 / 启动时一次。

**③ 其他（量级更小，登记备查）**
- `document.rs:48-54`：带 BOM 的 UTF-8 打开时整份 `to_vec()` 多一次全文件拷贝。
- `document.rs:581-604`：粘贴图片 base64 `to_string()` 多一次全长拷贝（切片完全够用）。
- `document.rs:395-446`：改名同步互链 dry_run 与应用各读一遍全目录全文（2× IO，低频）。
- `document.rs:311-324`：改名改写时**每行** 6 次小分配 + 4 次 `replace`（整行新 String），哪怕该行没有 `[[`。
- `document.rs:164-191`：一次保存 3–4 次 stat，其中 `parent.exists()` 纯冗余（`create_dir_all` 幂等）。

## 四、核查过、确认没问题的（避免下次重复劳动）

- **5 个装饰插件**：`list-fold`（结构变化才重建 + 局部窗口）、`paragraph-focus`（只 swap 两个块的装饰）、`code-block`（按 step 区间取受影响块 + 分批补算）、`markdown-input`（`map` + 变更区间 + doc 级 WeakMap 缓存）、`search-highlight`（引用比较短路，只 map）。
- **2 个 `appendTransaction`**：`scanHeadings` 只在 forceCheck（低频）走全文；正常编辑走 `scanChangedRanges`（区间）；`convertPendingInlineMarks` / `convertPendingLink` 只看光标所在文本块。
- **同步中枢** `useEditorSync`：字数 150ms / 大纲 500ms / 序列化 500ms + `requestIdleCallback`（2s 兜底重排）/ 光标 100ms 四层分离，且字数与大纲对 heavy 档降级。
- **无 `deep: true` 侦听**（全仓 0 处）、**无每键 IPC**、**无每键 localStorage 写入**（设置写入 300ms 防抖、阅读位置 800ms 防抖）。
- **自动保存有脏判断前置**（`useDocumentSession.ts:234`），不会无变化落盘。
- **Rust 保存路径零拷贝**：`content: String` 反序列化后按值 move 进 `spawn_blocking`，`content.as_bytes()` 直接写；全后端无 `regex` 依赖、`reqwest::Client` 复用（`OnceLock`）。
- `cell-content-guard` 的 `filterTransaction` 按变更区间、`markdown-paste` / `clipboard-html` 的全量遍历只在粘贴/复制时发生。

## 五、防复发建议（这次最该做的一件事）

这一类 bug 之所以「修过多次还有漏网」，是因为**只能靠人眼**。建议加一条静态锁（与既有 `composition-freeze` 的集合锁同款）：

- 文件：`src/components/Editor/tiptap/__tests__/hot-path-scan.spec.ts`
- 判据：扫 `tiptap/**` 源码，凡出现 `doc.descendants(` / `doc.textBetween(0,` / `doc.textContent` / `doc.toJSON()`，**且所在函数是 `apply` / `appendTransaction` / `decorations` / `handleKeyDown` / `handleTextInput` / `update(`** 的，即红。
- 白名单（需写明理由）：init 构建、forceCheck、粘贴/复制路径、一次性载入。
- 这套做法在本仓已有成功先例（`composition-freeze.spec.ts` 的集合锁：撤修复立刻红）。
- 反向校准：把 `list-fold` 的 `doc.descendants(visit)` 临时改回无条件调用 ⇒ 必须转红。

## 六、建议的推进顺序

1. **P1（删行号死计算）** —— 收益最大（107KB 文档每停笔 100ms 省 1.42ms、282KB 省 5.03ms），风险最低（删的是没人读的字段），但**动了公开类型**（`EditorCursorInfo` / `AppEditorUpdatePayload`），要清 3 处。
2. **P2（Mermaid/公式双渲染）** —— 用户体验直接相关（退出编辑的顿挫），改动 3 行/处。
3. **静态锁** —— 一次性投入，防以后复发。
4. P3/P4 看是否顺手。
