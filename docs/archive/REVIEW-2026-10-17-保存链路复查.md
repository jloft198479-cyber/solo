## 发现 1 · 状态栏保存按钮把 P1-① 的洞留在门外（主因，高）

**位置**：`src/App.vue:429-431`

```
@click="fileStore.currentFile.isDirty && documentSession.saveCurrentDocument(false, true)"
```

**事实链**（全部来自源码，非推测）：

1. 用户打字 → `handleDocChange` → `debouncedSerialize`（**500ms**，`useEditorSync.ts:39`）→ 再交 `requestIdleCallback`（超时兜底 **2000ms**，`useEditorSync.ts:42`）才写回 store。
2. store 的 `isDirty` 只由 `syncEditedContent` 改（`file.ts:73`）。⇒ **停止打字后最长约 2.5 秒内，`isDirty` 仍是 `false`**。
3. 这段时间里状态栏按钮的 `@click` 被 `isDirty &&` **短路**，`saveCurrentDocument` 根本不会被调用 —— 连 `useDocumentSession.ts:234` 那道带实时评估的门都进不去。

**为什么至今没被发现**：P1-①（"刚敲完就按 Ctrl+S 被滞后门吞掉"）在 commit `6a192ed`（2026-10-10）已修，但那次**只改了 `useDocumentSession` 内部**，没动 `App.vue`。`git blame` 显示这行来自 `ac63726`（2026-08-21），早于修复。
- `Ctrl+S` 走 `executeCommand → handleSave`，**无 `isDirty` 门控** ⇒ 快捷键正常。
- 菜单「保存」同理正常。
- **只有状态栏按钮点了没反应。**

**用户可见现象**（三条一起出现）：
- 刚打完字，状态栏仍显示「已保存」（`App.vue:434` 用同一个 `isDirty`）。
- 点它：按钮不响应、不落盘、不报错、不提示。
- `title` 悬停提示也是「已保存」（`saveButtonHint`，`App.vue:44-48`）。
- 等 2 秒后再点，或改按 `Ctrl+S`，就正常了 ⇒ 表现为"时好时坏"。

**测试覆盖**：`grep statusbar-save-btn|saveButtonHint **/*.spec.ts` ⇒ **零命中**。这条路径没有任何测试。

## 发现 2 · 自动保存踩同一道滞后门（中）

**位置**：`src/composables/useDocumentSession.ts:488`

```
if (fileStore.currentFile.isDirty && fileStore.currentFile.path) {
```

自动保存 tick 的前置条件只看 store 的 `isDirty`，**没有走 `evaluateDirtyFromEditor()`**（手动保存那道门有）。

- `git blame`：`71af488`（2026-08-21），同样早于 P1-① 修复。
- 默认关闭（`settings.ts:50` `autoSave: false`），所以只在开启自动保存的用户身上出现。
- 常规节奏（间隔 ≥5s）下 tick 到点时 store 早已追平，**大多数时候没事**。
- 但 `useEditorSync.ts:116-119` 有"超时撞上续打就重新排队"的逻辑 ⇒ **大文档（heavy 档序列化 100–300ms）下连续打字时，空闲回调反复超时重排队，store 长时间不更新 ⇒ `isDirty` 一直 `false` ⇒ 自动保存持续跳过**。表现为"自动保存好像不怎么工作"。

## 已确认**没有**问题的点（排除项）

| 检查项 | 结论 |
|---|---|
| 落盘内容是否可能落后于编辑器 | 否。`persistDocument`（`useDocumentSession.ts:195`）走 `getContent()` 实时取，快路径只在 doc 引用未变时命中 |
| 保存往返期间的编辑被洗成「已保存」 | 否。P1-② 已修（`storeMovedDuringSave` 复查，`:248-259`），有复现锁 |
| 关窗丢稿 | 否。关窗闸口走 `evaluateDirtyFromEditor()`，先冲刷实时内容再判 |
| Ctrl+S / 菜单保存被滞后门吞 | 否。两条路径无 `isDirty` 门控，P1-① 已覆盖 |
| 并发保存（连按 Ctrl+S） | 否。`_savePromise` 互斥 + 冲突重试递归路径已逐行走查，无死锁 |
| 后端写盘原子性 / 权限回落 | 与前端无关。`atomic_write` 有 tmp + `sync_all` + rename；权限不保留是已登记的 #41 |
