# 出站到公众号的格式保真审核

> 审核范围：**只看出站方向**（solo → 外部富文本编辑器），不看入站（粘贴进 solo）。
> 方法：读链路代码 + 用生产 schema 实跑 `serializeDocumentHtml()` 打印真实字节，逐条对照公众号后台的清洗规则。
> 未在真机公众号后台粘贴（无法程序化验证平台侧），平台侧结论取自公开实测资料，标注【平台】。

## 一、平台侧的三条硬规则（判据前提）

| 规则 | 后果 | 来源 |
|---|---|---|
| `class` / `id` 被清除 | 靠类名承载的样式全部作废 | 【平台】【高】三个独立来源一致 |
| `<style>` 块与外部样式表不支持 | 只能靠元素上的 `style=""` 存活 | 【平台】【高】 |
| 常用内联样式（`color` / `background-color` / `font-size` / `text-align` / `border`）保留；`position:fixed`、部分 flex 被过滤 | 内联是唯一可靠的载体 | 【平台】【高】 |
| 正文图片须先在后台素材库上传 | 相对路径 / 本地路径 / `data:` 一律裂图 | 【平台】【高】 |

来源：<http://www.mzlw.cn/news/131553>、<https://tsight.io/articles/17541587>、<https://github.com/wbjf/wechat-typeset-studio>（三者独立，结论一致）。

## 二、solo 出站实况（实测字节）

样本覆盖 15 类语法，`serializeDocumentHtml()` 产出的关键指标：

```
style 属性 6 处   ← 4 处表格 text-align + 2 处 math/mermaid 源码块的 white-space+font-family
class 属性 9 处   ← mk-callout / mk-wikilink / mk-math-inline / mk-math-block /
                     mk-mermaid-block / mk-code-block / language-js / mk-table / mk-image
data-* 属性 15 处 ← 全部只服务 solo 回读，外部一律丢弃
主题色 / 边框 / 底色 / 字号  零处内联
```

**关键判断：一份只有结构和 6 条内联声明的 HTML。** 视觉层全靠 CSS 类，而类会在粘贴瞬间被剥光。
`externalize-html.ts:87-100` 只给 math/mermaid 源码块补了 `white-space`，表格只留 `text-align`——其余样式一条都没内联。这不是遗漏，是这一层的设计边界（它只管「不把私语法漏出去」，不管「长得像不像」）。

## 三、逐项判决（11 项）

### 🔴 必坏（用户一眼看到）

| # | 语法 | 粘进公众号后的实际样子 | 证据 |
|---|---|---|---|
| 1 | **本地图片** | 裂图（红叉/空白）。`src="./assets/a.png"` 原样出站，无任何转换 | 实测 `<img class="mk-image" loading="lazy" src="./assets/a.png" …>`；`extensions/image.ts:301-317` 只处理 width/height |
| 2 | **提示框（callout）的标题**：走 **Ctrl+C** 时 | **整行标题文字消失**——标题只活在 `data-title` 属性里，正文没有它；公众号剥属性即抹掉 | 实测 Ctrl+C 路径：`<div … data-title="危险标题"><p>提示块正文。</p></div>`，正文无标题；`extensions/callout.ts:52` 标题走属性、`:69-71` renderHTML 不含标题文本 |
| 3 | **全部视觉样式** | 提示框变普通段落（无底色/边框/图标）、表格边框色不可控、代码块无底色、语法高亮为零 | 见 §二；代码高亮是 decoration（`code-block.ts:162-228`），**根本不在出站 HTML 里**；编辑器里看到的颜色来自 `editor.css` 的类选择器 |

> 第 3 项的补充：状态栏按钮路径已经把 callout 标题提到正文（`externalize-html.ts:59-70`），所以**按钮复制时标题在**，只有 Ctrl+C 会丢。同一份内容，两个复制法两个结果——见 §四。

## 四、两个结构性问题（比单项失真更重要）

### 问题 A：两条复制通道产出不一致

| 通道 | 触发 | 过归一层？ | 结果 |
|---|---|---|---|
| 状态栏 Copy 按钮 | 点按钮 | ✅ 过（`clipboard-html.ts:24`） | 标题在、表格干净、脚注 `[1]`、无 ZWNJ |
| **编辑器内 Ctrl+C / 右键复制** | 选一段 | ❌ **不过** | 标题丢、`tableWrapper`+`colgroup` 死宽出站、脚注 `[^1]`、frontmatter 出站、ZWNJ 残留 |

原因是 Ctrl+C 的 `text/html` 由 ProseMirror 默认 `DOMSerializer` 直出，`editorProps` 里**只定制了 `clipboardTextSerializer`（text/plain）**，没有 `clipboardSerializer`：
`MarkdownEditor.vue:392-399`。

> `KNOWN-ISSUES #52` 登记过这条通道，但**只登记了 ZWNJ 一个症状**（最轻的那个）。实测同一条通道还带 4 个可见失真（标题丢失、表格死宽、脚注源码、frontmatter 出站）——台账的定性偏轻。

这一条对「贴公众号」影响很大：用户通常**不会**用按钮复制全文，而是选一段 Ctrl+C。他得到的是最差的那一份。

### 问题 B：文档承诺与实际行为不符

`wiki/编辑器功能指南.md:50` 写：

> 状态栏 Copy 按钮：`text/html` 为**跟随当前主题**的富文本（可直接粘到公众号、邮件、Word）

实测出站 HTML 里**没有任何主题色彩**（0 处 color/background/border 内联，6 处 style 全是布局属性）。「跟随当前主题」在 v1.2.18 删除导出系统之后已经不成立。同类问题还有 `docs/solo产品精神.md:42` 把「贴到公众号」列为产品卖点。

## 五、建议（按性价比排序）

| 优先级 | 动作 | 修掉什么 | 代价 |
|---|---|---|---|
| **P0** | 把**清洗组**挂到 `editorProps.clipboardSerializer`：只做 `stripInvisibleChars` + 表格 `colgroup`/宽度剥离。**不改** callout / footnote / frontmatter 这三条改写 | 关掉 #52（ZWNJ）；修掉「选中表格粘 Word/公众号变死宽」；两通道产出一致性提升一半 | 小。钩子已存在（prosemirror-view 调用点已核），改写组里只有「不动语义」的那半可以挂 |
| **P1** | callout 标题跨通道一致：出站时**同时**保留 `data-title` + 注入正文标题，再在 `callout.parseHTML` 里把「attrs 有 title 且正文首段是纯 `<strong>` 等于该 title」的那段剥掉 | 修掉 #2（Ctrl+C 丢标题），且不破坏 solo→solo | 中。动 `parseHTML`，必须跑保真体检 + 重跑 `externalize-html.spec.ts` 的 #3 签名锁 |
| **P2** | 复制时若检测到本地图片路径，给一条一次性提示：「N 张本地图片在公众号需重新上传」 | 让 #1 从「莫名其妙裂图」变成「我知道要手动传」 | 小。纯 UI 提示，不碰序列化 |
| **P3** | 改 `wiki/编辑器功能指南.md:50` 与 `solo产品精神.md:42` 的措辞：删掉「跟随当前主题」，改成「结构化富文本（样式以目标平台默认呈现）」 | 消除假承诺 | 极小 |
| **不做** | 做「公众号主题内联」模式 | #3 | 大。等于重建 v1.2.18 删掉的 `wechat-themes` 层；且与「个人化阅读写作工具、不做长文档处理器」的定位冲突。**建议不做，只把承诺说清楚** |

## 六、一句话结论

**「格式准确」成立——粘过去是一篇结构完整、层级正确、可读的文章；「格式保真」不成立——它不会长得像 solo 里的样子。** 差的不是结构，是样式；而样式丢的原因是「样式全在 CSS 类里，公众号只认内联」，不是序列化写错了。
