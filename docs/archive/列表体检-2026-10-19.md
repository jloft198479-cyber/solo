## P1 · 空首子项 → 段落被读成二级标题（真伤，**已修**）

### 复现（最小）

编辑器里造出这个结构（父项文字 + 第一个子项为空）：

```
- A
  - 
```

存盘 → 重开：**「A」变成 H2**，文件变成 `- ## A`。
任务项同样中招：`- [ ] A\n  - ` 重开后是「`## [ ] A`」（勾选框一起没了）。

### 根因

- CommonMark 里 `A` 后面紧跟一行 `-` 是 **setext 二级标题**（`- A\n  ---` 同族）。
  空列表项序列化出来正好是 `  - `（marker + 空段落），于是被当成了下划线。
- 这是 **serializer 输出有歧义**，不是 parser 错：parser 严格按 CommonMark 解释。
- 关键点：空行可以断开（`- A\n\n  - ` 重开正常），但当前 `renderContent`
  为了紧凑嵌套不插空行（[`serializer.ts:630-644`](../../src/components/Editor/tiptap/markdown/serializer.ts)）。
  实测 `- A\n\n  - ` 再存一次又会收紧回 `- A\n  - ` ⇒ **第二次保存后才爆**，
  典型的「第一次看着没事」静默损坏。

### 修法（已落地）

`renderContent` 里「列表项 → 子列表」的单换行分支加一个条件：
**父项首块是有文字的段落，且子列表是 bulletList、其首项是空 listItem** ⇒ 改用 `blankLine()`。
其余情况保持单换行（不把普通嵌套列表改成 loose）。

- 影响面：只影响「空首子项」这一个形状；普通嵌套列表输出一个字节不变。
- 代价：这一项在外部渲染器里变成 loose（段落带 `<p>`），但换来「重开不改块类型」。
- 必跑：parser/serializer 改动的 5 套契约锁 + 全仓保真体检 + 全量测试。

## P2 · 嵌套首项行首退格：圆点消失（我们自己的守卫，**已修**）

### 复现

```
- A
  - A1
  - A2
```

光标停在 A1 行首，按 Backspace：

| 版本 | 结果 |
|---|---|
| 无守卫（上游 lift） | `- A / - A1 / - A2` —— A1 整体提升一级，**圆点还在** |
| 有守卫（现状） | `- A` + `  A1`（普通段落，**圆点没了**）+ `- A2` |

带孙子的形态（`A1 → A1a`）同样：A1 变段落，A1a/A2 改挂到 A 名下；待办项同款。

### 根因

`list-backspace-guard.ts` 的「首项」分支走 `liftListItem().joinBackward()`
（[`:179`](../../src/components/Editor/tiptap/extensions/list-backspace-guard.ts)）：
lift 之后 A1 成了新列表的首项，`joinBackward` 把**列表与列表**合并，结果是
「A1 的段落并进 A 的项里」，而不是把文字并进 A 那一行。

而该文件的头注释（`:26`）写的是「**嵌套子项｜放行上游 lift**」——**代码没有兑现**：
`isNestedItem()` 只用在 Shift-Tab（`:200`），Backspace 分支一次都没调。

### 修法（已落地）

在「首项」分支之前加一条：`index === 0 && isNestedItem(...)` ⇒ `return false`（放行上游）。
- 只影响嵌套首项；嵌套非首项（A2）仍走「并进上一项」，行为不变。
- 上游 lift 已验证不劈容器（上表第一行）。

## P3 · 父项行中回车：子项跟走后半段（需拍板）

```
- ABC
  - A1
```

光标在 `A|BC` 按 Enter：

```
- A
- BC
  - A1      ← 子项跟到了后半段
```

这是我们刚修的「行尾回车」之外的另一半：上游 `splitListItem` 在段中切整项，
切点之后的一切（含子列表）归新项。行尾那种可以无歧义地判「新建同级」，
**段中**则牵扯一个产品选择：

- **方案甲（保持现状）**：文字后半段 + 子列表一起走。语义＝「光标之后的一切归新项」，
  与纯文本切分一致，但父项身份跟着后半段跑了。
- **方案乙**：子列表留在原项，后半段文字另起一项（放在整棵子树之后）。
  需要新语义，且会出现「后半段文字跳到子项下面」的阅读顺序变化。

建议：**先不动**，登记为已知边界。行中切父项是低频动作，且两种方案都有代价。

## 备注 A · 父项行尾 Delete

- 第一个子项是叶子 ⇒ 被吞成父项里的**第二段**（圆点消失，落盘 `- A\n\n  A1`）；
- 第一个子项自己还有孩子（分支）⇒ 被整项提升为同级（上游 `hoistBranchingNestedList`）。
  同一按键两种结果，不一致，但都不丢文字、不属于高频路径。
- 真要用 Delete 删子项的人很少（中文用户几乎都用退格），建议只登记。

## 备注 B · Shift-Tab 的兄弟改挂

```
- A
  - A1
  - A2
```
Shift-Tab 在 A1：结果 `- A > [- A1]` … A2 变成 A1 的孩子。
这是上游 `liftToOuterList` 的既定语义（把后面的兄弟挂给被提升项，以保住视觉位置）。
实测 A2 的**缩进深度与屏幕位置都没变**，只是「父」从 A 变成 A1；可接受。
