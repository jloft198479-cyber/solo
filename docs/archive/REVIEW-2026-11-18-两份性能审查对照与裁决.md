# 两份性能审查的对照与裁决

## 一、一句话结论

**Qoder 那份是「施工图」，我那份是「总平面图」。** 它找到了我漏掉的、与中文打字直接相关的两处热路径；我的价值在于结构归因和两条它没提的路线。实施应以它的 S 清单为主干。

## 二、关键证据抽样复核（我逐条开原文核过）

| Qoder 条目 | 复核结果 | 证据 |
|---|---|---|
| S1 每次 IME 上屏后全文档 `scanHeadings` | **成立**。compositionend 后 50ms 发 meta 事务 → `forceCheck` → `appendTransaction` 走全量 `scanHeadings`；WeakMap 按 doc 缓存，上屏后 doc 是新的必 miss | `markdown-input.ts:262-270`、`:300-306`、`:512-549`、`:350-352` |
| S2 代码块每键整块重高亮，语言块无规模门 | **成立**。`apply` 对受影响块同步 `highlightBlock`；规模门只拦「无语言 → highlightAuto」 | `code-block.ts:162-180`、`:354-366` |
| S6 大纲关闭仍全量计算；App 收全文 prop | **成立**。`skipOutline` 仅 heavy+关；大纲导航只 `v-if="hasItems"`；`App.vue:381` 确把全文字符串当 prop 传 | `useEditorSync.ts:74`、`OutlinePanel.vue:172`、`App.vue:381` |
| S7 tiptap-core 卷入 Vue、入口 modulepreload | **成立**。当前 dist：`tiptap-core-*.js` 416.8KB，内含 `createApp`，`index.html` 确实 modulepreload | `dist/assets/tiptap-core-*.js`、`dist/index.html` |

四条抽检全中，这份审查的可信度高于一般「AI 审查」。

## 三、双方一致的部分（可直接冻结，不要再反复讨论）

- 「大头已吃完」，不存在单一 bug；问题是多处小动作叠加。
- 不做编辑器虚拟化；不下调 `HEAVY_DOC_CHARS=50万`。
- 透明窗口 / 禁 TSF 只做 A/B 登记，不盲改。
- 先建测量基建，再谈优化。

## 四、各自独有的有效发现

**Qoder 独有（我漏了，且更有价值）**
1. S1 markdown-input 全扫 —— 直接对应「中文长文打字发黏」。
2. S2 代码块同步重染 —— 大代码块里每键 10ms 级。
3. S4 搜索开启时空事务触发全插件 apply 链。
4. S5 NodeView 更新不比对内容（mermaid/math-inline）。
5. S7 分包把 Vue 卷进 tiptap-core，懒加载被架空（实测数据）。
6. S8 表格 `cellToText` 跑两遍；字体字节走 JSON 数字数组过 IPC。

**我独有（它未提）**
1. **条件式 `content-visibility`**：不按文档大小一刀切，只对「离视口 >2 屏且不在组字中」的顶层块启用，组字开始即撤下 —— 在保住 IME 的前提下拿滚动收益。它只把虚拟化列为「不做」，漏掉了这条中间路线。
2. **字体就绪再出首帧**：`@font-face` 异步加载导致开屏整篇重排。
3. **感知层**：焦点模式全篇 opacity 过渡、气泡菜单每帧跟随，属于「慢半拍」的主观来源。
4. 框架层面：**体感由帧一致性决定，而不是平均速度**。

## 五、它的薄弱处（不必照单全收）

- S3 的「序列化 100–300ms」来自 heavy 档注释，10–40 万字真实耗时未测；「缺中间档」的结论成立，数字要打折。
- S6 的「App 每 100–150ms 整壳重渲染」是推断，prop 浪费成立，频率需测量。
- S1 的修复方案（只扫变更段±相邻段）需保留「定期全扫兜底」，否则早期 pending heading 可能漏转 —— 它自己也写了，但这是的主要风险点。
- S10 若干项（主题重排、idle 批大小、滚动写 session）优先级应更低。
- 与我的报告一样：**无 profile 数据，排序靠推理**。

## 六、采纳顺序（合并两版后的建议）

1. 测量基建（两份报告的第 0 步）。
2. S7 分包修正（零风险、收益确定）。
3. S5 内容相等守卫 + S6 大纲关面板停算 / 去掉全文 prop（几行改动）。
4. S1 markdown-input 增量化（主诉最相关，碰敏感区，需完整回归）。
5. S2 代码块编辑期降级 + S3 序列化分片。
6. 我的条件式 `content-visibility` 与字体首帧（需评审）。
7. S4 / S8 / S9 / S10 按测量结果再排。
