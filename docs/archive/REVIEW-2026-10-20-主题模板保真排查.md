# 主题模板保真排查

> 现象：下载 `theme-template.json` → 只改颜色 → 上传 → 排版发生轻微变化（行距变松、标题变大）。
> 用户比喻：墙刷了颜色，墙不该长高。
> 排查日期：2026-10-20

## 一、结论

**是模板定义问题，不是规则歧义 —— 模板夹带了排版参数，且这套参数是错的。**

`solo` 的主题 JSON 除了 `colors`，还有一条 `typography` 通道（`manager.ts` 的
`TYPOGRAPHY_VAR_MAP`，26 个字段会直接写成 `<html>` 的行内 CSS 变量）。

- **9 套内置主题**：`typography` 全部为空（实测 `none`），排版一律走
  `src/components/Editor/tiptap/editor.css` 的 `--mk-*` 默认值。
- **模板 `public/theme-template.json`**：声明了一整段 `typography`，**值不是默认值**。

用户只改 `colors`，`typography` 原样保留 → 导入后排版整体变形。

## 二、证据（模板值 vs 产品默认值）

默认值真理源：`src/components/Editor/tiptap/editor.css:33-61`

| 字段 | 模板值 | 实际默认 | 差 | 视觉后果 |
|---|---|---|---|---|
| `lineHeight` | **1.9** | 1.6 | **+18.75%**（25.6→30.4px/行） | 行距明显变松，整篇变长 |
| `heading1Size` | **1.875em** | 1.6em | +17.2%（25.6→30px） | H1 变大 |
| `heading2Size` | **1.5em** | 1.3em | +15.4%（20.8→24px） | H2 变大 |
| `heading3Size` | 1.25em | 1.2em | +4.2% | H3 略大 |
| `heading4Size` | 1.1em | 1.05em | +4.8% | H4 略大 |
| `letterSpacing` | **0.02em** | 0 | +0.32px/字 | 字距变散 |
| `paragraphSpacing` | 0.75em | 1em | **−25%**（16→12px） | 段距反而变紧 |
| `fontSize` | 16px | 16px | 0 | 无 |
| `heading5/6Size` | 1em / 0.9em | 同 | 0 | 无 |
| `quoteBorderWidth` | 2px | 2px | 0 | 无 |

一篇 50 行的文档，正文额外高 **240px ≈ 多出 9 行**。

**为什么感觉是「轻微」而非「全乱」**：四个变化方向不一致 —— 行距松、标题大、字距散、
段距紧。所以观感是"说不上哪不对，就是不太一样"。

## 三、根因：模板抄了一份漂移的错误值

`src/__tests__/design-contracts.spec.ts:255-258` 的注释是铁证：

```
// ThemeTypography 的 JSDoc 曾漂移 15 处（lineHeight 写 1.9 实 1.6、
// h1 字号写 1.875em 实 1.6em…），而 8 套预设一个都没声明 typography ⇒
// 注释就是唯一文档，写错等于骗人。真理源是 editor.css，这里逐条比对。
```

模板里的 `1.9` 和 `1.875em`，与当年 JSDoc 漂移被抓出来的错误值**逐字相同**。
模板是从"注释写错的那版"抄过去的，2026-06-25 建立至今从未与 `editor.css` 同步。

**为什么能一直错**：现有 23 条相关测试（`design-contracts` 19 + `manager` 4）全绿，
但没有一条读 `public/theme-template.json`。模板是**零覆盖**区域。

## 四、附带发现（同源病灶）

### 1. 模板有 4 个死字段：`radiusSm / radiusMd / radiusLg / radiusXl`

模板第 43-46 行给了 `3px / 6px / 10px / 14px`，但：

- `types.ts` 的 `ThemeColors` **没有**这些字段，`CSS_VAR_MAP` 也没有 →
  `injectColors()` 遍历不到 → **改了毫无反应**。
- `manager.ts:44-46` 注释明写：「圆角不是主题 token，仅定义在 main.css :root 一份」。
- 真实圆角刻度是 `--radius-xs 2px / sm 3px / md 4px / lg 8px / pill 999px`
  （`main.css:182-186`），**名字和数值都对不上**，`xl` 已于批 5 删除。

→ 模板在承诺一个不存在的开关。用户改 `radiusMd: 6px`，界面还是 4px。

### 2. 文档自相矛盾（这才是「规则有歧义」的真实出处）

`wiki/主题与字体.md`：

| 行号 | 原文 | 矛盾点 |
|---|---|---|
| 27 | 每套主题**只换配色**。排版参数是预留通道，当前没有任何主题声明 | ✅ 与代码一致 |
| 47 | solo 的排版参数……**并与主题绑定**。切换主题时觉得行距或字号变化，**是主题自带的排版性格，不是 bug** | ❌ 与第 27 行打架 |

第 47 行恰好会让人**把这次的 bug 当成正常现象**（"就是主题性格嘛"）。
另外第 28 行写"可新建、编辑、导出主题文件"，实际只有**导入**和**下载模板**，
新建/编辑/导出都不存在。

### 3. 真 bug：切换主题时 `accentColor` 残留

`manager.ts:143-154`：

```ts
if (value && style.getPropertyValue?.(cssVar) !== value) {
  style.setProperty(cssVar, value);   // 只写，缺值不清除
}
```

`accentColor` 是可选字段，且**不在** `SHARED_LIGHT_COLORS / SHARED_DARK_COLORS`
兜底表里。9 套预设都声明了它，模板没有。

→ 从任意内置主题切到自定义主题，`--accent-color` 会**留在 `<html>` 行内样式上**，
影响：编辑器光标颜色（`editor.css:640` 等）、大纲面板右边框（`OutlinePanel.vue:304`）、
命令面板光标（`CommandPalette.vue:283`）。

现象：**只换了主题，光标颜色还是上一个主题的。**
（这是"打补丁"式注入的通病；`injectTypography` 已经写对了 —— 无值就
`removeProperty`，两处不对称。）

### 3.5 列表前的小圆点：模板有值，但名字看不出，且不可单独改

**结论：有赋值，是间接的 —— 走 `textSecondary`（次要文字色），没有专属字段。**

`src/components/Editor/tiptap/editor.css:426-429`：

```css
/* 列表 marker 用次要色，让正文内容更突出（iA Writer / Notion 一致做法） */
.tiptap-editor li::marker {
  color: var(--text-secondary);
}
```

`--text-secondary` ← `CSS_VAR_MAP.textSecondary` ← 模板 `"textSecondary": "#475569"`。
全仓只有这一处给 marker 上色（`editor.css:1628` 是聚焦模式的淡化，不是赋色）。

| 问题 | 答案 |
|---|---|
| 模板里有给小圆点赋值吗 | **有**，但字段名叫 `textSecondary` |
| 有专属的列表色字段吗 | **没有**，一处都找不到 |
| 改它会连带改什么 | 满屏次要文字：文件列表里的日期/大小、状态栏、说明文案、主题缩略图的灰线 |
| 值浅吗 | **不浅**。模板 `#475569` on `#ffffff` 对比度 **7.58**（WCAG AA 只需 4.5） |
| 那为什么"不明显" | ① 圆点太小（16px 正文字号下 disc 直径约 5px）；② 模板值 `#475569` 与 9 套预设的 `#4a4f58 / #574a39 / #3f5048 / #4d4d4d` 是**同一档深灰**，肉眼分不出 |

实测对比度（marker 色 vs bgColor，全部 7.5~8.5，均达标）：

| 主题 | bgColor | marker 色 | 对比度 | 正文字对比度 |
|---|---|---|---|---|
| 模板 | `#ffffff` | `#475569` | 7.58 | 17.85 |
| default | `#fcfcfc` | `#4a4f58` | 8.03 | 16.72 |
| scholar | `#f6f1e8` | `#574a39` | 7.64 | 13.93 |
| scholar-dark | `#141a20` | `#9fb0bd` | 7.86 | 13.76 |
| graphite | `#ffffff` | `#4d4d4d` | 8.45 | 17.93 |

**另一处不一致**：无序列表圆点走 `--text-secondary`，而任务列表的勾选框走
`--primary-color`（`editor.css:568-573`）。同样是"列表前的符号"，两条规则。

**副作用（与「墙长高」同源）**：`::marker` 继承字号，所以 `typography.fontSize`
一改，圆点尺寸跟着变 —— 又一条"只改颜色却动了尺寸"的通道。

### 4. 模板 colors 不完整

`ThemeColors` 共 68 个 key（含 `accentColor`），模板只给 60 个，缺 8 个 callout
（`calloutAbstract / calloutInfo / calloutQuestion / calloutFailure / calloutBug /
calloutExample` 及其 `-Bg`）+ `markBg`。缺的走共享兜底，能正常显示，但用户
**看不到也改不到**。

## 五、修复方案（待拍板）

|---|---|---|---|
| 1 | 模板 `typography` 段**整体删除**（方案 A）或 **逐值校正为默认值**（方案 B） | 主修 | 1 个文件 |
| 2 | 删除 `radiusSm/Md/Lg/Xl` 四个死字段 | 必做，无争议 | 同上 |
| 3 | 补齐缺失的 8 个 callout + `markBg` + `accentColor` | 补全 | 同上 |
| 4 | `injectColors` 改为「无值则 `removeProperty`」（对齐 `injectTypography`） | 真 bug | `manager.ts` |
| 5 | 新增 `src/themes/__tests__/theme-template.spec.ts` 做机器锁 | 防复发 | 新增 1 文件 |
| 6 | 改 `wiki/主题与字体.md` 第 47 行矛盾表述 + 第 28 行过度承诺 | 文档 | 1 文件 |

### 圆点要不要单开通道（三选一）

现状：圆点 = 次要文字色，**想改圆点就必然改满屏次要文字**，模板里也看不出这层关系。

**① 什么都不改，只补文档**
在 wiki 里写明 `textSecondary` 同时管列表符号。
- ✅ 零风险、零代码
- ❌ 用户仍然不能单独调圆点

**② 加 `listMarkerColor` 可选字段（推荐）**
- `types.ts`：`listMarkerColor?: string`，进 `CSS_VAR_MAP` → `--list-marker-color`
- `editor.css`：`li::marker { color: var(--list-marker-color, var(--text-secondary)); }`
  （**带 fallback，不声明就完全退回现在的行为，退化安全**）
- 模板里写 `"listMarkerColor": ""`：看得见这个开关存在，留空即不生效
- 前提：必须先修第 4 项（`injectColors` 缺值不清除），否则会和 `accentColor`
  踩同一个残留坑
- ✅ 想单独调的人能调；不想调的人零感知
- ❌ 主题字段从 68 涨到 69；模板又多一项

**③ 圆点改跟主色走**
把 `li::marker` 改 `var(--primary-color)`，与任务勾选框统一。
- ✅ 规则统一、少一个字段
- ❌ 主色通常很艳（朱砂红/兰紫），满屏圆点会很吵；iA Writer / Notion
  都是"符号比正文轻"，这条会破坏既有设计意图。**不建议**

**我的判断**：选 **②**。理由是它把"看不见的隐式绑定"变成"看得见的显式开关"，
正好治你说的"模板规则有歧义"；而 fallback 保证没人用时行为一模一样。

### 方案 A vs B

**A · 纯色卡（推荐）**
模板不带 `typography`。主题语义 = 只换颜色，与 9 套预设**完全一致**。
- ✅ 用户怎么改都不会动排版，墙永远不长高
- ✅ 最省事，不可能再漂移
- ❌ 用户想调行高/字号就没有入口（但 9 套预设本来也没给）

**B · 色卡 + 排版档**
模板保留 `typography`，26 个值**逐个校正为 `editor.css` 默认值**。
- ✅ 通道保留，想调排版的人能调
- ✅ 照抄不改 = 视觉零变化
- ❌ JSON 不能写注释，用户不知道"这段可整段删掉"
- ❌ 下次改 `editor.css` 忘了同步模板 → 复发（靠第 5 项锁兜底）

**我的判断**：选 **A**。理由：9 套预设一个都没用排版通道，说明产品现阶段
不做"主题带排版性格"；`types.ts:117-124` 自己也写明这是「预留通道」。
通道留在代码里不对外暴露即可，不必在用户模板里开个半成品口子。

### 第 5 项机器锁要锁什么

```
① 模板每个 colors key 必须存在于 CSS_VAR_MAP          ← 拦 radius 这类死字段
② 模板 typography 每个值必须等于 editor.css 实测值     ← 拦值漂移（方案 B 才需要）
③ 模板必须能通过 importTheme() 校验且 id 可自动生成     ← 拦"下载下来就导不进"
④ 模板 typography 不得声明 CSS_VAR_MAP 之外的字段       ← 拦拼错字段名
```

## 六、影响面盘点

- 改动文件：`public/theme-template.json`、`src/themes/manager.ts`、
  `wiki/主题与字体.md`、新增 1 个 spec
- 不影响：主题切换链路、9 套预设、`settings.ts` 字号/行高手动设置
  （该设置会在主题注入后覆盖 `fontSize` / `lineHeight`，属预期）
- 已装好的旧自定义主题**不会自动修好** —— 用户存的 JSON 里已经带着错值。
  修复后需请用户重新下载模板 / 手动删掉 `typography` 段。**这是发布说明必须写的一条。**

## 七、复现与验证路径

**复现（免构建）**：当前 9 套预设 `typography` 均为 `none` → 任选一套 →
下载模板 → 一个字不改直接导入 → 立即看到行距变松。

**修复后的验收口径**（写"用户这么操作得到 X"）：
1. 选 `Scholar Light` → 下载模板 → 不改任何内容 → 导入 → 应用
   → **屏幕文本的行距、标题大小与 Scholar Light 完全一致**
2. 只改 `primaryColor` 为红色 → 导入应用
   → **只有颜色变，行距/标题/段距/字距不变**
3. 从 `Scholar Light`（有 accentColor）切到自定义主题
   → **光标颜色跟随新主题**（第 4 项修复的验收）
