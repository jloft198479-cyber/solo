# 输入时轻微闪烁 · 排查报告

> 约定：本轮**只排查、不改代码**（简乐明确：输入法漂移是好不容易解决的，不能冒失）。
> 方法：用生产 `createEditorExtensions()` 起真编辑器，派发真实 keydown / insertText，
> 用 MutationObserver 记录 DOM 变化；另读了渲染链路（装饰、调度、CSS 过渡）与用户设置。
> 临时探针已删，工作区干净。

## 一、结论（先说能确定和不能确定的）

**能确定**：在普通输入路径上，**没有**「每次按键都把这一行 DOM 删了重建」这种事。
连打 5 个字，DOM 只发生文本节点内容变化，`childList` / `attributes` 均为 0——
所以闪烁不是我们自己的装饰层/插件在反复重建节点。

**不能确定**：闪烁发生在**编辑器 DOM 之外**的某一层（输入法上屏、WebView2 合成、浏览器扩展/拼写检查），
这些在单测环境（happy-dom）里没有像素，也就没有"闪"可测，必须真机 A/B 才能定位。

## 二、实测数据（生产扩展，happy-dom）

| 场景 | DOM 变化（5 字） |
|---|---|
| 普通段落连打 | `characterData: 5`，`childList: 0`，`attributes: 0` |
| 焦点模式连打 | 同上（焦点模式是关的，见下） |
| 空行起笔 | `childList: 2`（删占位 `<br>`、加文本节点）+ `characterData: 1` |
| 打 `# 标题` | 定稿瞬间 `<p>` → `<h1>`（整行**一次**替换） |
| 打 `**粗**` | 定稿瞬间文字被包进 `<strong>`（整行**一次**） |

结论：普通文字输入 = 纯文本节点更新；只有「Markdown 语法定稿」才有一次结构替换。

## 三、已排除的层（有证据）

| 层 | 排除依据 |
|---|---|
| 焦点模式淡入淡出 | 用户设置 `focusMode: false`；且开关它打字 DOM 变化都是 0 |
| 字体加载 swap | 字体是 `system-ui`，无自定义字体下载 |
| 大文档掉帧 | 最近文档 0.4–45KB，规模档位 normal；listFold 单次重建在 200 项时约 1ms |
| 主题/字体 crossfade | 只在切主题/字体时触发，打字不触发 |
| 搜索高亮重建 | 只有搜索面板有 query 时才建装饰 |
| IME 重锚护栏 | 只在窗口移动/缩放时触发（`ime-anchor.ts`），打字不触发 |

## 四、剩下的可疑层（按可能性排序）

### 1) 输入法上屏时的原生重绘（最可能，也最不该碰）
中文组字时，预编辑文本由浏览器直接画在 contenteditable 里；上屏瞬间浏览器把它替换成最终汉字，
这是**原生行为**，不是我们的插件。我们的冻结机制保证「结构不在组字期变动」，
但保证不了「浏览器自己替换合成文本时不重绘」。
**特征**：只有中文输入法会出现；英文逐字打不闪。

### 2) WebView2 透明窗口的合成抖动
窗口配置是 `transparent: true` + `decorations: false` + `shadow: true`（`src-tauri/tauri.conf.json`）。
透明窗口在 Windows 上由 DWM 分层合成，文本重绘时偶发轻微抖动/闪，属平台级已知现象。
**特征**：窗口化时明显、最大化时可能消失；与输入法无关。

### 3) 拼写检查（当前设置里已关，先看关掉后还闪不闪）
编辑器创建时按设置写 `spellcheck` 属性（`MarkdownEditor.vue:361`），默认值是 `true`；
我在 20:51 读到设置被改成了 `false`。WebView2 的拼写检查会异步扫描并重绘下划线，
在 contenteditable 里偶发轻微闪动。
**特征**：关掉后消失。

### 4) Markdown 定稿（只在敲语法时）
`# ` / `**` / `~~` 等定稿时整行 DOM 会被替换一次（见上表），`# ` 前缀被删会让文字向左跳一下。
**特征**：只在敲这些符号后出现，纯文字不会。

## 五、顺手发现的其他问题（与闪烁无关）

1. **listFold 每次按键全量重建**：`list-fold.ts` 的 `view.update` 每次 doc 变化都排一次
   rAF 重建，`buildDecorations` 全文档扫描并重建所有折叠箭头装饰。
   实测（happy-dom）：3000 项 **+27ms/键**、8000 项 **+213ms/键**（一帧 16ms）。
   当前文档规模不受影响，但**列表型长文**会明显掉帧。属性能债，可另行处理。
2. **没有 `scrollbar-gutter: stable`**：内容高度刚好在一屏上下时，滚动条出现/消失会让
   整列文字横向跳一次（视觉上像"闪一下"）。低概率，但可解释某些"偶尔闪"。
3. **标题定稿的文字左跳**：`# ` 前缀在定稿时被删掉，文字左移约 1.2em（Typora 同款，属设计）。

## 六、建议的 1 分钟自测（不改代码，用于定位）

按顺序做，哪一步不闪了，就锁定那一层：

1. **关拼写检查**（设置里）→ 打一段中文。还闪 ⇒ 排除拼写检查。
2. **切英文输入**打同样内容。英文不闪、中文闪 ⇒ 指向 IME 上屏。
3. **只打纯文字**（不敲 `#`、`**`、`-`）。纯文字也闪 ⇒ 排除 Markdown 定稿。
4. **窗口最大化 / 换空文档**再打。最大化后不闪 ⇒ 指向透明窗口合成。

## 七、结论与建议

- **先不动代码**：渲染层没有可归因的按键级重建；剩下最可疑的两层（IME、WebView2 透明窗口）
  都属于"一改就可能动到输入法"的高风险区，收益/风险不划算。
- 等自测结果：如果是 1/2 层（IME / 窗口合成），建议**登记为已知现象**，不动；
  如果是 3 层（拼写检查），已有设置开关，零代码成本；
  如果是 Markdown 定稿（4 层），属设计行为，可单独讨论"定稿瞬间是否要补齐视觉过渡"。
- listFold 的全量重建是确定的性能债，与本次闪烁无关，可另开一轮（改法明确：按键时只 map，
  只在结构变化（增删列表项/折叠切换）时重建），但同样要真机验证手感。
