# solo 互链设计评估（v1.2.63）

> **判定口径**：本文结论全部由读源码得出（**代码级判定，未真机实测**），每条附 `文件:行号` 供复核。
> 凡涉及「Obsidian / Typora 行为」的，来自官方帮助文档（Obsidian `Help → Internal links`、`Settings → Files and links`），文末列来源。

## TL;DR

三句话：

1. **同目录内的闭环已经通了** —— 补全、跳转、不存在则创建、改名同步、失效标红、拖入成链，六条链路都在，且各有回归锁。
2. **跨目录是「半做」，比完全没做更危险** —— `[[sub/B]]` 因为路径拼接恰好能用，**能点开**；但补全找不到、标红判不了、改名不同步。用户会以为「能用」，直到改名那天全部断链且界面查不出原因。
3. **Obsidian 语法兼容层缺失** —— `[[笔记#标题]]`、`[[笔记#^块]]`、`![[嵌入]]` 三种写法全部被当成「文件名」处理。后果不只是显示异常：点开会**真的在磁盘上创建 `笔记#标题.md`**。

---

## 一、最新进展（本轮已收口的部分）

`f864e1b`（1.2.63）把互链从「能用但坑多」推到「同目录可信」：

| 修了什么 | 关键点 |
|---|---|
| 互链点开无反应 | 根因不在互链，在**新建窗口**：`additionalBrowserArgs` 与主窗口不一致 → WebView2 环境创建失败、`build()` 仍返回 Ok 的空壳（#77）。修法是沿用主窗口 config，不另立字面量 |
| 改名后入链不同步 | 从「先预览列清单 → 弹框确认」改成**一律自动同步**，并且落盘后**广播**让别的窗口立刻重载 |
| 死链看不见 | 新增 `wikilink-existence.ts`：decoration 标红 + 红色波浪线 + 悬停说明 |

三条设计判断都站得住：

- **状态不进 schema**：文件在不在是「环境状态」，不是文档内容 → 用 decoration 而非节点属性，零持久化代价。
- **性能硬约束**：打字只走 `DecorationSet.map` 平移，全量重扫只在「打开 / 切文档 / 清单刷新」发生。
- **改名不问用户**：弹框会被自动保存打断，答过一次「先不动」就再没第二次机会 → 直接改，改完告知。

## 二、现状设计全貌

### 2.1 数据模型

一个内联 atom 节点，两个属性：

```
wikilink { target: string, alias: string }
  [[B]]        → target="B",  alias=""
  [[B|别名]]    → target="B",  alias="别名"
```

**target 存的是「不带路径的裸名」或「用户手打的相对片段」**（`sub/B`）。没有绝对路径、没有 vault 根、没有 id。

### 2.2 六条链路

| 链路 | 入口 | 范围 | 关键实现 |
|---|---|---|---|
| 补全 | 敲 `[[` | **同目录** `.md`，上限 500，菜单 50 条 | `wikilink-suggest.ts:67-87` + `document.rs:126-152` |
| 解析 | 点击 / 打开 | 当前文档目录 + target + `.md` | `wikilink.ts:21-37`（`:35` 只补 `.md`） |
| 跳转 | 单击 | 另开一窗 | `wikilink.ts:106-112` → `App.vue:86-88` → `new_editor_window` |
| 不存在则创建 | 点击 | 同上 | `MarkdownEditor.vue:210-268`（`:232` 用 target 原文当标题） |
| 改名同步 | 标题栏改名 + 保存 | **同目录**可编辑文档 | `document.rs:343-389`（`:351-354` 只取 parent） |
| 失效标红 | 打开 / 切文档 / 清单刷新 | **同目录** `.md/.markdown/.txt` | `wikilink-existence.ts:45-105` |
| 拖入成链 | 拖 .md 进正文 | **同目录** `.md/.markdown` | `wikilink-drop.ts:53-72` |

### 2.3 三个没写在文档里、但决定了一切的前提

1. **链接是「相对当前文档」存的**，不是相对某个根。所以文档一移动（另存为到别的文件夹），它自己的出链全断。
2. **没有文件监视器**。资源管理器里改名/移动/删除，solo 全程无感知 —— 标红是事后补的「让你看得见」，不是同步。
3. **「一窗一文档」是产品设定**。点互链必开新窗，不顶掉当前文档，也不聚焦已开窗口。

这三条不是 bug，是地基。**后面所有缺陷都是从这三条长出来的**。

## 三、对标：Typora / Obsidian 怎么做

| 维度 | solo（现状） | Obsidian | Typora |
|---|---|---|---|
| 语法 | `[[B]]` / `[[B\|别名]]` | 同上 + `[[B#标题]]` / `[[B#^块]]` / `![[嵌入]]` | 标准 `[文字](路径)` |
| 路径存法 | 裸名 / 手打相对片段 | 三选一：最短唯一路径 / 相对路径 / 库内绝对路径（设置项） | 相对路径 |
| 链接范围 | 同目录 | 整个库（vault） | 同仓库任意相对路径 |
| 补全范围 | 同目录 | 全库模糊搜索（>1 万项降级算法） | 有限 |
| 改名同步 | 同目录自动改 | **全库自动改**（可关，关则提示） | 不自动改（靠用户） |
| 标题锚点 | ❌ 当成文件名 | ✅ `#` 多级 | ✅ `#` |
| 嵌入 | ❌ `!` 当正文 | ✅ `![[note]]` / `![[img\|100]]` | 图片走标准语法 |
| 反向链接 | ❌ | ✅ backlinks + 出链面板 + 图谱 | ❌ |
| 失效提示 | ✅ 标红（仅同目录） | ✅ 未解析链接变色 | ❌ |
| 打开方式 | 只能新开窗 | 当前标签 / 新标签 / 新窗 | 当前窗 |

**关键差距不在「有没有双链」，在「链接的作用域有没有边界」。**
Obsidian 有 vault 这个根，所以补全、改名、标红、移动文件全都知道该扫哪儿。
solo 没有根，只有「当前文件的父目录」—— 于是所有跨目录能力都无处落地。

## 四、缺陷清单

> 标注：`[已登记]` = KNOWN-ISSUES 里已有条目；`[新发现]` = 本次读码新增；`[代码级判定]` = 未真机跑过。

### P0 —— 会造成错误行为或磁盘副作用

#### P0-1 `[[笔记#标题]]` 被误标红 + 点开会创建怪文件名 `[新发现] [代码级判定]`

- **现象**：从 Obsidian 复制一段带标题锚点的内容，进来就是红波浪线；点一下弹「目标文档不存在，是否创建？」，确认后磁盘上真的多出一个 `笔记#标题.md`（frontmatter 里 `title: "笔记#标题"`）。
- **根因**：
  - 存在性判定把 `#标题` 当文件名一部分 —— `isWikilinkTargetMissing` 只排除「带路径分隔符」和「带非 .md 扩展名」，`#` 不在排除项里（`wikilink-existence.ts:67-78`）。
  - 创建流程用 `target` 原文当标题和文件名（`MarkdownEditor.vue:232`），`#` 在 Windows 上是合法文件名字符，一路绿灯。
  - `atomic_write` 会 `create_dir_all`（`document.rs:751-758`），连目录都会替你建。
- **后果**：**违反「别处复制来的内容能正确显示」这条铁律**，而且不是「显示不好看」，是**在用户磁盘上生成垃圾文件**。Obsidian 用户迁移时这是第一道墙。

#### P0-2 跨目录 `[[sub/B]]` 是「半做」——能点开，但三个配套全缺 `[已登记为二期 / 但半做风险未登记]`

| 能力 | 现状 | 证据 |
|---|---|---|
| 点开 | ✅ 能（`dir + sub/B.md` 是合法路径） | `wikilink.ts:21-37` |
| 补全 | ❌ 菜单只列同目录，选不到子目录文件 | `document.rs:139` 只收 `.md` 且不递归 |
| 标红 | ❌ 一律不标（含路径就跳过） | `wikilink-existence.ts:74` |
| 改名同步 | ❌ 只扫 `new_path.parent()` | `document.rs:351-354` |
| 拖入成链 | ❌ 非同目录直接回落 | `wikilink-drop.ts:60-67` |

- **后果**：用户手打一条跨目录链接，**能用**，于是认为互链支持跨目录；等到某天把 `sub/B.md` 改名，链接静默断掉，而标红机制**恰好也不管这类链接** —— 界面连红波浪线都不会给。这是「静默失败」的教科书形态。

#### P0-3 同目录只有 `B.markdown` / `B.txt` 时：不标红，但点开要「创建 `B.md`」`[新发现] [代码级判定]`

- **根因**：两个模块对「B 存在吗」用了两套口径。
  - 标红索引收 `.md / .markdown / .txt` 三种后缀去尾（`wikilink-existence.ts:50`）→ `[[B]]` **不标红**。
  - 解析只补 `.md`（`wikilink.ts:35`）→ 点击时找 `B.md`，**不存在** → 弹创建。
- **后果**：界面说「这链接是好的」，点下去说「这文件不存在，要创建吗」。用户确认后得到 `B.md`（空） + 原 `B.markdown` 并存，**以为打开了自己的笔记，其实开了个空文件**。
- **修法**：两处必须同源 —— 要么解析也试 `.markdown`/`.txt`，要么索引只收 `.md`。**不能各说各话**。

### P1 —— 体验断裂 / 一致性

#### P1-1 一键创建目标文档后，源文档的红标不会消失 `[新发现] [代码级判定]`

`markBrokenWikilinks` 只在两处调用：切文档 watch（`MarkdownEditor.vue:537`）和编辑器懒初始化（`:777`）。创建 `B.md` 之后没有任何刷新动作 → 那条红波浪线原地不动，直到重开文档。用户的第一反应是「创建失败了」。

#### P1-2 单击即跳，而外链要按 Ctrl —— 同一编辑器两套心智 `[新发现]`

- 互链：`handleClickOn` 单击直接跳走（`wikilink.ts:106-112`），返回 true 吃掉默认选中。
- 外链：mousedown+click 自判 10px，且要按住 Ctrl 才变手型并跳转（KNOWN-ISSUES #17）。
- **后果**：用户想改一个链接名，单击 = 开新窗（不可逆、要多关一个窗）。想编辑必须先用方向键定位。而隔壁外链单击是安全的。**同一个编辑器里，两种「点一下」的后果完全不同**。

#### P1-3 互链只能「另开一窗」，没有「在当前窗口打开」 `[新发现]`

`handleWikilinkNavigate` 里没有任何分支，一律 `newEditorWindow`（`App.vue:86-88`）。顺着链接读三篇 = 多三个窗口，且没有「返回来源」。Obsidian 是「当前标签 / 新标签」二选一；solo 只有一个选项。

> 注：`#75` 已拍板「同路径不去重」，理由是命中已开窗口就聚焦会破坏「一窗一文档」。这个口径成立。但**「在当前窗打开」是另一回事**，它不破坏一窗一文档，只是给用户少开窗的选择权。

#### P1-4 跨目录拖入 = 顶掉当前文档 `[已登记范围 / 后果未写明]`

`decideDocumentDrop` 要求同目录（`wikilink-drop.ts:60-67`），不满足就 fallback；fallback 走 `openDocument`（`useAppWindowSession.ts:254-257`）→ **当前文档被换掉**（有脏态确认，不丢数据）。
用户的意图是「拖个链接进来」，得到的是「我正在写的东西被换走了」。

#### P1-5 改名同步大小写敏感 —— `[[b]]` 改 `B.md`→`C.md` 后不更新 `[新发现] [代码级判定]`

`replace_targets_in_line` 用 `String::replace`，逐字匹配（`document.rs:319-321`）。而 Windows 文件系统大小写不敏感、标红索引也做了 `toLowerCase`（`wikilink-existence.ts:48`）。于是：`[[b]]` 判为「存在」（索引命中小写 `b`），改名后却不在改写范围 → 变成死链，且**标红这次会亮**（因为 `b` 已不在索引里）。属于「能看见但不会自动修」，体验上是「明明是你改的名，为什么不帮我改」。

#### P1-6 `![[B]]` 语义错位 —— 被解析成「`!` + 链接」`[新发现] [代码级判定]`

`parseWikilinkText` 只认 `[[...]]`（`markdown/plugins/wikilink.ts:7-26`），前面的 `!` 落成普通文本 → 正文显示 `!B`，点一下跳转。Obsidian 里这是**嵌入**（把 B 的内容整段贴进来），语义完全不同。
不会崩、不会丢内容，但 Obsidian 用户会看到一排莫名奇妙的「!笔记名」。

#### P1-7 另存为到别的文件夹 → 该文档所有出链全断，且无任何提示 `[新发现] [代码级判定]`

链接相对当前文档存。另存为换目录后，所有 `[[B]]` 指向新目录下的 B —— 不存在。而另存为流程不触发任何检查、不提示、不标红（标红要等重开文档后下一次清单刷新，且只在同目录范围内比对）。

### P2 —— 结构性 / 需要产品拍板

| # | 问题 | 说明 |
|---|---|---|
| P2-1 | 开窗失败毫无反馈 | `App.vue:86-88` 的 `await newEditorWindow(path)` 没有 try/catch。#77 修了根因，但**没有补「失败要说一句话」的兜底**。下次再出类似问题，用户看到的仍是「点了没反应」 |
| P2-2 | 没有反向链接 | 「谁引用了我」不可见。改名只能靠扫目录，无法精准定位受影响文件 |
| P2-3 | 标准相对链接不跳转 | 白名单只有 `http/https/mailto`（`link-open.ts:29`）。从 Typora 复制的 `[文字](子目录/B.md)` 点了只弹「仅支持 http/https/mailto」。**这是产品决定，但它和 P0-2 叠加 → 跨目录链接两条路都不通** |
| P2-4 | 乱序命名无「重名歧义」预案 | 现在同目录不会重名，问题被掩盖。一旦开放跨目录递归，`[[README]]` 在全库有 5 个时怎么解析？Obsidian 用「最短唯一路径」，需要提前定口径 |
| P2-5 | 补全无「无更多结果」提示 | 菜单 50 条截断，用户不知道还有更多 | 
| P2-6 | 新插入的互链不标红 | 已知限制（`wikilink-existence.ts:25`）。可接受，但和 P1-1 叠加会让人怀疑标红本身坏了 |

## 五、建议

### 5.1 本轮就做（低成本、高收益、不动地基）

1. **剥离锚点**：解析/标红/创建三处，统一把 target 里第一个 `#` 之后的内容视为锚点、不参与文件名。
   - 收益：Obsidian 复制进来的 `[[笔记#标题]]` 立刻从「红 + 误创建」变成「正常可点」。
   - 成本：三个纯函数各加一行 + 一组回归锁。**不做块引用跳转**，只做「不误判」。
2. **统一存在性口径**（P0-3）：解析和索引要么都收 `.markdown/.txt`，要么都只收 `.md`。推荐**都收**（读文件本来就是白名单三种），解析时按清单实际命中名打开。
3. **创建后刷新标红**（P1-1）：创建成功后直接 `markBrokenWikilinks()`，顺手 `refreshWikilinkCandidates()`。
4. **开窗失败兜底**（P2-1）：`try/catch` + 一句「打开失败：<原因>」。**静默失败最贵**，这条是给 #77 补保险。
5. **`![[...]]` 至少不显示成 `!B`**：最小做法是解析时把 `!` 吃进节点（标记 `embed: true`），渲染成「嵌入占位」样式。不做真嵌入。

### 5.2 跨目录：最小方案（不引入 vault）

**不要引入「库」概念** —— 方案文档已经论证过：那与「不变成 Obsidian」的立项初衷相冲。

要补的是**范围一致性**：

> **补全范围 = 标红范围 = 改名扫描范围**，三者必须调用同一个 Rust 函数。

落地方式：

1. `list_markdown_files` 加一个 `depth` 参数（默认 1 = 现状；跨目录模式 = 3），返回**相对路径**（`sub/B.md`）。
2. 前端候选显示 `sub/B`，插入 target 也用 `sub/B` —— 与已有手打格式天然兼容。
3. 标红不再「含路径就跳过」，改成「按同一份清单比对相对路径」。
4. `sync_wikilinks_on_rename` 的扫描范围跟着改成同一深度。
5. 明确边界：**超出深度的目标不标红、不改名**，但也不假装支持 —— 悬停提示里写清「超出当前文件夹范围」。

关键约束（否则又会造出新的不对称）：**这三处必须是同一次改动的同一批**。历史上 `[[` 补全与拖入就曾因为一边同目录、一边承诺子目录而对不上（方案文档 §「外部审计发现」已记）。

### 5.3 明确不做

| 不做 | 理由 |
|---|---|
| vault / 库 / 工作区概念 | 与「个人化极简阅读写作」定位相冲，方案文档已有结论 |
| 图谱视图 | 同上，且是重资产 |
| 块引用 `#^id` | 需要给每个块生成并持久化 id，动 schema，收益远小于代价 |
| `![[...]]` 真嵌入 | 就是「文档内嵌文档」，需要递归渲染与循环检测，与「不做长文档处理器」冲突 |
| 同路径开窗去重 | #75 已拍板：会破坏「一窗一文档」。真实代价只是多窗口 + 保存冲突弹框，不丢数据 |

### 5.4 一个产品层面的提醒（不附和）

「一窗一文档」+「点链接必开新窗」+「没有当前窗打开」三条叠起来，会让**链式阅读**（A→B→C→D）产生线性增长的窗口数。如果 solo 的核心场景之一是「读自己的笔记」，建议至少给一条出路（`Ctrl+点击 = 在当前窗打开`，或右键菜单「在此窗口打开」）。这不破坏一窗一文档，只是把选择权交回用户。

## 六、怎么一次验完（建议的复核清单）

按优先级排，一次操作验一条，别分开跑：

1. 在 Obsidian 里建 `A.md` 写 `[[B#小节]]`、`[[sub/B]]`、`![[C]]`，整段复制进 solo → 看是否标红 / `!` 怎么显示。
2. 同目录只有 `B.markdown` 时写 `[[B]]` → 看是否标红，点下去弹什么。
3. 点一个不存在的链接 → 创建 → **盯住那条红波浪线**是否当场消失。
4. `sub/B.md` 拖进正文 → 看是插链接还是换文档。
5. 写 `[[b]]`（小写）→ 把 `B.md` 改名成 `C.md` → 看 `[[b]]` 有没有跟着改。
6. 把正在编辑的文档「另存为」到别的文件夹 → 看原有出链是否全断、有无提示。
