# Trae「速度与丝滑体感审查」独立核实（2026-11-18）

> 被审对象：[REVIEW-2026-11-18-速度与丝滑体感审查.md](./REVIEW-2026-11-18-速度与丝滑体感审查.md)（**原稿未动一个字**）。
> 方法：每条论断当待证伪命题，回源码开原文核对（含行号、机制前提、修法可行性）；
> 对照同日另一份独立审查 [REVIEW-2026-11-18-性能与流畅度审查.md](./REVIEW-2026-11-18-性能与流畅度审查.md)（下称「Qoder 报告」）。
> 本轮只读取证，未改任何代码。

## 〇、总判定（大白话）

**部分认同。** Trae 把「平台/架构取舍」这一层讲得比 Qoder 报告好（透明窗合成、字体抖动、
optimizeLegibility 这几条是它的独有贡献，方向都站得住）；但它把中文输入不丝滑**主要归给平台输入法**，
漏掉了 Qoder 报告已拿到代码证据的「每词上屏全文扫描」等每键级热路径——那才是可直接修的部分。
另外它给的两个修法（序列化移 Worker、字体就绪再显示）**风险定级错了**，照单执行会踩坑。

## 一、逐条核实

### 部分成立 · 需精确化

1. **「TSF 禁用是当年修候选窗失锚的取舍」——历史归因不准。**
   `docs/IME-经验卡-失锚翻身记.md:49`：TSF flag 是 09-14 的「转机①」，**有效性未验证**（46 次位移仅 2 次命中，无法 A/B）；
   真正定案转正的修法是 10-12 的 **blur→60ms→focus 重锚护栏**（同卡 :28,:72-77）。
   ⇒ 「为修 IME 付出了禁 TSF 的代价」这个因果不成立：flag 是否仍必要本身就是悬案。
   这不削弱「A/B 测 TSF」的价值，反而加强；但 Trae「默认不建议动」的保守结论可维持（回归成本高）。
2. **「5 万字序列化约 8–12ms」——数字无出处且偏低。**
   存档实测（`REVIEW-2026-09-15-体验与代码评估.md:459,478`）：8k 字 7.5ms、85k 字 28.6ms ⇒ 5 万字内插约 15-20ms。
   Trae 全文声明「没有真机 profiling」，此数却以实测口吻给出，应标「估算」并按存档口径修正。
3. **场景 E 焦点模式装饰成本——默认不发生。**
   `stores/settings.ts:159` isFocusMode 默认 false；`paragraph-focus.ts:139` 仅在开启且非 heavy 时挂装饰。
   论断本身属实（`editor.css:1647-1654` 确有透明度过渡），但**不是全体用户的恒定成本**，
   只影响开了焦点模式的用户；Trae 未注明这个前提。
4. **气泡菜单「追着光标漂」是打字成本——说重了。**
   `MarkdownEditor.vue:635-639`：选区为空（普通打字态）或组字中直接早退，零开销。
   成本只发生在「有非空选区时滚动/拖选」，不是连续打字路径。
5. **optimizeLegibility（`editor.css:88`）「长文滚动额外排版成本」——方向对、量级未证实。**
   Chromium 默认已开 kerning，optimizeLegibility 主要多算 ligature；中文场景 ligature 几乎无作用，
   成本大概率很小。作为一行 CSS 的 A/B 值得做（Trae Step 1.2 合理），但别预期它是主因。
6. **行号漂移两处**：场景 A 引 `MarkdownEditor.vue#L405-L416` 实为 onUpdate 回调块，
   同步 parse 在 :420、基线 serialize 在 :433；场景 E 引 #L624-L630 实为 :627 起。不影响结论，照抄行号会找错。

### 证伪 / 定性错误

1. **「不是某个 bug，而是四层代价叠加，前三层不是继续抠代码能消掉的」——过度概括。**
   Qoder 报告已证实存在**纯代码级、可修、不碰架构**的每键热路径：
   - 每词 IME 上屏一次全文档 scanHeadings（`markdown-input.ts:262-270,300-301,522`，无 heavy 门控）；
   - 每键两次段内光标前全文拷贝 + 约 10 条正则（`markdown-input.ts:406,466`）；
   - 代码块内每键整块重高亮、标注语言块无大小上限（`code-block.ts:176,359-366`）。
   Trae 把中文黏滞主要归给平台 IME 层（场景 C），**恰好漏掉这些可直接消除的代码成本**。
   「四层」框架作为平台视角成立，作为完整归因不成立。
2. **死链一处**：正文第 26 行 `[PERF-…](archive/PERF-AND-THEME-SUGGESTIONS-2026-09-18.md)`——
   本文件已在 docs/archive/ 内，该相对路径指向 docs/archive/archive/…，不存在。
   （文末 See also 的同名链接写法是对的。）

## 二、Trae 的修法验证（结论成立 ≠ 修法可用）

| 修法 | 判定 |
|---|---|
| **Step 2.1 序列化移 Worker** | **方向可行、定级过低。** 已核 serializer 及其 plugins 全无 DOM 依赖（grep 零命中，escapeImageAlt 是纯字符串函数），理论上可进 Worker。但①「主线程只做结构化克隆，停顿感消失」说过头：`doc.toJSON()` + 结构化克隆本身仍是主线程 O(n) 遍历+分配，省的是 tokenize/escape 那段，不是全部；②脏态代际契约（`useEditorSync.ts:92-98,177-187`）假设「序列化在执行时读当前 doc」，Worker 往返引入过期产物，必须加代际标记+丢弃逻辑，关窗/保存闸口仍需实时同步兜底——碰的是敏感区时序，不是「低风险 1–2 天」。9 月 §9.3 已因同类时序风险否决过一次改判，此修法须按中风险评审 |
| **Step 2.3 字体就绪再显示（fonts.ready / font-display:block）** | **证伪其「低风险」定性，不建议采纳。** 现状 swap 是有意设计（首帧不阻塞，`fontLoader.ts:68`、`useEditorAppearance.ts`）；solo 有 5 款远程字体，等字体就绪=把「一次性抖动」换成「首帧白等数秒甚至离线卡死」。正确方向是保持 swap + 提前预载当前字体，不是阻塞首帧 |
| **Step 3.1 条件式 content-visibility（组字开始全局撤下）** | 机制上可行但**切换动作本身就是最敏感时刻的布局事件**：compositionstart 瞬间撤 contain ⇒ 全篇离屏块强制渲染+布局，恰是 IME 光标矩形最易失锚的时点（IME 经验卡全篇在讲这个区域多脆弱）。Trae 已标「需严格组字回归」，维持「实测再议」，不列为下一步 |
| **Step 1 「三个零风险 A/B」** | transparent:false 会改变自绘窗口外观（圆角/阴影依赖透明+shadow），作为**临时测量**可以，作为改法不是零风险；其余两项（optimizeLegibility、焦点模式）确属零风险。另注意焦点模式默认关（见上），A/B 3 对默认配置用户无意义 |
| Step 2.2 / 2.4、Step 0、Step 4 | 可行，与 Qoder 报告一致。图片占位补一句：固定比例骨架在真实比例不符时仍会跳，更稳是首载后把自然尺寸写回（Qoder S8） |

## 三、两份报告的收敛与互补

**双报告同指（优先修，置信度最高）**：先测量（Step 0 = Qoder 第 0 步）、大纲关面板停算、
字数增量/降频、序列化停顿窗独占、图片尺寸预留、搜索装饰预算、透明窗 A/B。

**Trae 独有贡献（Qoder 报告漏/仅疑似）**：optimizeLegibility、字体 swap 开屏抖动、
透明合成作为全局恒定成本的第一嫌疑、「帧一致性而非平均速度」的体感定性。均采纳入候选。

**Trae 漏掉（Qoder 报告已证实）**：S1 每词全文扫描+每键段内拷贝、S2 代码块每键重染、
S5 公式/图表无内容相等守卫、S7 启动 427KB Vue hoist 分包、S8 表格双序列化/粘贴多遍 parse。

## 四、总账

- **可用**：平台/感知层归因（透明合成、字体抖动、optimizeLegibility、帧一致性定性）、
  Step 0 测量清单、大纲/字数门控、A/B 思路。
- **不可用**：「前三层抠代码消不掉」的总结论（漏了每键热路径）、8–12ms 数字、
  TSF 历史因果、「序列化移 Worker 低风险」「字体阻塞首帧低风险」两个定级。
- **推荐落点（唯一）**：以 Qoder 报告的排序为主干执行（先测量 → S7 分包 → S5/S6 快赢 → S1/S2 热路径），
  把 Trae 的三条独有发现并进 Step 1 的零风险 A/B 一起测；**不采纳**字体阻塞首帧，
  Worker 序列化若要做按中风险另行评审。等简乐一句「同意」再动手。
