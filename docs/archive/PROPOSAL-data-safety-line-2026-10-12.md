## 一、问题清单（按「用户会损失什么」排，不按编号）

| # | 问题 | 用户遇到什么 | 严重度 |
|---|---|---|---|
| 1 | 另存为/改名途中打字被抹（台账 #38） | 另存为成功那一刻，编辑器被灌回旧内容——IPC 往返期间敲的字**从屏幕上消失**（不只是脏标被洗）。主路径的同款问题上轮已修，但「刚整理完文件名、正在打字」正是另存为的高频时刻 | 数据丢失级 |

| 3 | 脚注重复标签吞段（#43） | 同一标签写两个定义，**较早定义的正文整段静默消失**，不报错不提醒 | 静默丢内容 |
| 4 | 改回原文脏标不复位（#42） | 打个字再删掉，状态栏仍显示「未保存」、关窗仍弹确认。原审核的「一行修法」已判死——它会真丢稿（Mermaid 后台事务会让「显示已保存、磁盘没写」） | 体验 + 误导 |
| 5 | 自动保存遇外部修改弹窗轰炸（#40） | 外部程序改了同一文件，自动保存每个周期弹一次「是否强制覆盖？」；用户不答就一直挂着，挂着的期间下次保存也不调度 | 烦人 + 卡保存 |
| 6 | 行尾归一不一致（#20 残留） | 打开别人给的 CRLF 文件：自动保存不动行尾，Ctrl+S 把行尾全变成 LF。两处行为打架 | 一致性 |

## 二、总设计：给编辑器立一本「磁盘账本」

现在编辑器心里只有一本账——「我改过没有」（滚动基线，追着编辑器自己跑）。缺的是第二本：**「磁盘上那份到底存了什么」**。

补上第二本账之后，问题 1/3/4 的判据都从「猜」变成「比」：

- `file store` 新增独立字段 `diskContent`，**只在保存成功那一刻**更新为实际写进磁盘的内容；
- 现有滚动基线不动（它服务序列化缓存与自动保存，动它 = 动敏感区第 1 条，引回潮风险）；
- 脏态判据升级：`实时内容 vs diskContent 语义比对`。开销可控——关窗/保存门控本来就要取实时内容（复用 `getContent()` 缓存 + `isSyncedWithStore` 快路径，与上轮 P1-① 修复同款模式）。

「相等分支置 false」这类一行修法之所以判死，就是因为拿滚动基线当磁盘真相；有了 diskContent，判据第一次有了事实来源。

## 三、分期与各项修法

### 第一期（核心，3 项同根，建议本期做）

**1. 磁盘账本 + #42 脏标复位**
- `file.ts`：`currentFile` 加 `diskContent`；`markSaved` 时同步；新增 `evaluateDirty(live)` = `live` 与 `diskContent` 语义比对（复用现有序列化缓存，无新增序列化点）。
- 调用点只换两处：关窗前评估、保存门控——这两处已经走 `evaluateDirtyFromEditor`，改造成本可控。状态栏显示继续用 store `isDirty`（显示滞后无感，不白付序列化）。
- #42 消解：用户改了一笔 ⇒ live ≠ diskContent ⇒ 脏；Mermaid 后台事务不改内容语义 ⇒ 不误清。

**2. #38 另存为/改名不抹编辑**
- 根因已钉到行：`saveCurrentDocumentAs` / `saveRenamedDocument` 成功后走 `fileStore.setFile(快照, …)`，`setFile` 里 `reloadToken += 1` ⇒ 编辑器把旧快照 parse 回 doc，往返期间的编辑被抹。
- 修法：新增 `adoptSavedFile(path, content, mtime)`——更新路径/基线/清脏/重置文件名，**不 bump reloadToken**（磁盘内容就是我们刚写的那份，doc 无需重载，语义上 ≠「外部载入」）。
- 两处调用点从 `setFile` 换成它；`renamePath` 的错误分支保持不动。

**3. 保存前旧版本备份（收 #2）**
- `document.rs` 的 `save_document` 在 rename 前把原文件复制到 `app_local_data_dir/backups/<文件路径编码>/<时间戳>.md`，每文件保留最近 5 份，超龄清。
- 命令面板加「打开备份目录」入口。
- **崩溃恢复本期不做、单列**：它需要「未干净关闭检测 + 恢复 UI + 快照策略」，是大功能；备份区是它的地基，分期合理。

### 第二期（烦人项，建议紧随）

**4. #40 自动保存遇冲突改为暂停**：`manual=false` 时遇 `document_conflict` ⇒ 暂停自动保存调度 + 状态栏常驻提示「自动保存已暂停：文件被外部修改」；模态只留给用户主动保存时。恢复：用户处理完外部修改（或覆盖成功后）自动恢复，暂停态在下次成功保存或手动重试时解除。

**5. #43 脚注重名**：修法明确（动 `plugins/footnote.ts` 的 section 构建，同标签多定义时保留首个、其余定义的内容不丢段落）；保留策略见决策点 3。

**6. #20 残留**：加设置项「保存时归一化行尾（CRLF→LF）」默认开；Ctrl+S 与自动保存行为一致（都归一），M-03 门控（未编辑不写盘）不动，「打开不动不写盘」不回潮。

### 第三期（边界，可缓）

**7. #39 编码回写**：`DocumentOpenResult` 加 `encoding` 字段（读侧已认 UTF-8 BOM / UTF-16 LE/BE），写侧按原编码回写。动 IPC 契约（前端 `services/tauri` 同步加字段）。

**8. #41 权限复制**：Unix 侧 `fs::set_permissions` 一行；Windows 侧要复制 SD/DACL（`GetSecurityInfo`/`SetSecurityInfo`），属新增 Win32 依赖，单独评估。

## 五、验收口径（用户这么操作 → 得到什么）

- 另存为对话框确认后，立刻敲字 → 字在、脏标亮着；关窗弹确认
- 打个字再删净 → 状态栏回「已保存」、关窗不弹确认
- 存错一次 → 备份区能找到上一版；命令面板「打开备份目录」一步到位
- 开着自动保存 + 外部程序改文件 → 不弹窗、状态栏提示暂停；外部改回去 → 自动恢复
- 同一脚注标签两个定义 → 两段都在，较早的定义生效
- 干净 CRLF 文件打开不动 → 仍不写盘（M-03 不回潮）；按一次 Ctrl+S → 按设置归一
- 4MB 文档：刚敲完立刻 Ctrl+S 无可感卡顿（门控只在该评估时评估）

## 六、改动面与风险

**动这些**：`src/stores/file.ts`（diskContent / adoptSavedFile / evaluateDirty）、`src/composables/useDocumentSession.ts`（脏判据、冲突分支、备份调用）、`src/App.vue`（如 handleSave 涉及）、`src-tauri/src/commands/document.rs`（备份、编码回写）、`src/stores/settings.ts`（行尾设置）、命令面板注册 + 新增测试。

**风险与控制**：
- file store 脏态链 = 敏感区第 1 条（脏态/保存冲突）⇒ 全量 `test:full` + 真机手感 checklist（保存卡顿 / 关窗确认 / 4MB 文档 / 另存为流程）；
- 不碰 parser / serializer / schema ⇒ 不动保真五锁的主因，但全量回归照跑；
- 备份写入失败**不能**阻断保存本身（备份是保险不是前提），失败只留痕。

**不做（明确划界）**：崩溃恢复 UI、跨机器备份、脚注重名「合并多个定义」的高级语义——都超出本期。
