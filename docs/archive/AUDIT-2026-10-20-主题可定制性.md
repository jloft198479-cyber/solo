# 主题可定制性审计（范围扩大版）

> 起因：`REVIEW-2026-10-20-主题模板保真排查.md`（模板夹带歪掉的 typography → 墙长高）。
> 本轮把范围扩大到全仓：**还有哪些地方本该能自定义，却被漏掉或绑死？**
> 审计日期：2026-10-20

## 〇、一句话结论

solo 的**语义层 token 做得很完整**（`:root` 里 111 个变量，颜色类全部接进主题映射，无死链），
但**组件层 token 几乎为零** —— 所有「组件专属的视觉身份」都被迫借用语义 token，
于是出现三件事：

- **甲 · 8 个假开关**：模板给了字段，真实界面零消费（改了屏幕没反应）
- **乙 · 14 个该给的没给**：代码里有 token、真正生效，模板里没暴露（用户改不到）
- **丙 · 7 处绑死**：一个 token 管 7 类不同语义，改 A 必伤 B

## 一、扫描口径（先定义再报数）

- **范围**：`src/**/*.css`（4 个纯 CSS 文件）＋ `src/**/*.vue` 内 `<style>`，均排除 `__tests__`
- **颜色属性**：`color` / `background*` / `border*-color` / `accent-color` / `caret-color` /
  `outline-color` / `fill` / `stroke` / `text-decoration-color`
- **token 提取**：`var(--x)`，含 `color-mix(… var(--x) …)` 内的
- **消费点**：一条 CSS 规则里出现一次算一个点
- **脚本**：`.workbuddy/.sandbox-audit/audit-tokens.mjs`（可复跑，只读）
- ⚠️ 局限：脚本只解析纯 `.css`，`.vue` 内样式靠 grep 补，故下方「规则级」数字是**下限**

## 二、甲 · 8 个假开关（模板里给了，改了没用）

| 字段 | 模板值 | `var()` 真实消费点 | 改了会怎样 |
|---|---|---|---|
| `tagBg` | `rgba(59,130,246,0.1)` | **0** | 真实界面无变化；**主题缩略图会变**（`ThemePreview.vue:32`）→ 更容易误判"生效了" |
| `tagColor` | `#3b82f6` | **0** | 同上（缩略图顶栏圆点） |
| `codeBorder` | `#e2e8f0` | **0** | 同上（缩略图代码框边框） |
| `successBg` | `rgba(22,163,74,0.1)` | **0** | 完全无变化（连缩略图都不变） |
| `infoBg` | `rgba(8,145,178,0.1)` | **0** | 完全无变化 |
| `shadowLg` | `0 10px 15px …` | **0** | 完全无变化 |
| `shadowXl` | `0 20px 25px …` | **0** | 完全无变化 |
| `btnGhostBg` | `transparent` | **0** | 完全无变化（幽灵按钮背景是 `transparent` 写死在 `main.css`） |

**参照物（说明这不是"全部状态色都没用"）**：`--warning-bg` 1 点（快捷键冲突提示）、
`--error-bg` 2 点（气泡菜单危险项、主题删除按钮 hover）—— 只有 success / info 两套掉了。

> 补充：这 8 个在代码里是**已登记的预留槽位**（`main.css:113` 注释 + 台账 §三），
> 不是僵尸代码，**不要删变量**。问题在**模板把它们当可调项给了用户**。

**加上上一轮的 4 个 `radiusSm/Md/Lg/Xl`（接口里根本不存在的字段）**，
模板里**共 12 个字段改了不生效**，占模板 68 个 colors 字段的 18%。

## 三、乙 · 14 个该给的没给（真有 token，模板没暴露）

模板 68 个 colors 字段，其中 4 个是接口里不存在的死字段（radius）⇒ **有效字段 64 个**；
`ThemeColors` 78 个 ⇒ **缺 14 个**（64 + 14 = 78，对得上）。

| 缺失字段 | 真实消费点 | 用户为什么想要 |
|---|---|---|
| **`markBg`** | 1（`mark` 高亮底色） | **高亮底色是最常见的定制需求**，现在完全看不到开关 |
| **`accentColor`** | 3（命令面板光标 / 大纲面板右边框 / 链接悬停下划线） | 这是主题的"第二性格色"，9 套预设都声明了，模板却没有 |
| `calloutAbstract` / `-Bg` | 2 | 13 种 callout 只给了 6 种，另外 6 种用户改不到 |
| `calloutInfo` / `-Bg` | 2 | 同上 |
| `calloutQuestion` / `-Bg` | 2 | 同上 |
| `calloutFailure` / `-Bg` | 2 | 同上 |
| `calloutBug` / `-Bg` | 2 | 同上 |
| `calloutExample` / `-Bg` | 2 | 同上 |

**排版侧同理**：`ThemeTypography` 23 个字段，模板只给 11 个。缺的 15 个里
`heading1~6LineHeight` / `heading1~6Margin` / `heading1~2LetterSpacing` / `markBorderRadius`
用户都改不到。

## 四、丙 · 7 处绑死（改一个必伤一串）—— 本轮最重的发现

### 4.1 `sidebarBg` 一个人干 7 类活

| # | 实际用途 | 位置 |
|---|---|---|
| 1 | 右侧大纲面板背景 ✅ **这才是"侧边栏"本意** | `OutlinePanel.vue:196` |
| 2 | 代码块顶部工具条（语言/复制按钮那一条） | `editor.css:663` |
| 3 | 图片加载中的占位底色 | `editor.css:903-905` |
| 4 | 数学公式块背景 | `editor.css:1014` |
| 5 | frontmatter（元信息区）背景 | `editor.css:1337` |
| 6 | 斜杠菜单图标底座 | `editor.css:1547` |
| 7 | 设置弹窗底栏 + 两个设置面板底栏 | `SettingsModal.vue:379`、`SaveSettingsPanel:117`、`ShortcutSettingsPanel:145` |

**用户视角**：觉得"右侧大纲太灰"→ 调 `sidebarBg` → **代码块头部、数学块、frontmatter、
设置窗口底栏、斜杠菜单图标全部跟着变色**。这是全文最典型的"刷一面墙，整栋楼掉漆"。

### 4.2 其余 6 处

| token | 消费点数 | 管着哪些互不相干的语义 | 用户想单独调的典型诉求 |
|---|---|---|---|
| `mutedColor` | **28** | 占位符 / 折叠箭头 / 块删除缩放按钮 / frontmatter / 斜杠菜单描述 / 待办完成态 / 删除线 / 文字变浅 / 语法注释 / 滚动条 hover / 设置页说明 | "折叠箭头太淡了，但我一调全文说明文字都变深" |
| `primaryColor` | 14 | 加载条 / 光标 / 标题旁 `#` 符号 / 待办勾选框 / 链接 / 语法关键字 / 选中文本底 / wikilink / 脚注上标 / 图标 | "我只想让链接红一点，结果光标和语法高亮全红了" |
| `textSecondary` | 8 | 幽灵按钮 / 未保存提示 / 引用块正文 / **列表圆点** / 语法属性名 / 图片说明 | 上一轮已报 |
| `borderColor` | 多处 | **表格边框** / 代码块边 / 输入框边 / 弹窗边 / 滚动条滑块 | "表格线想比 UI 分隔线深一点，做不到" |
| `borderLight` | 多处 | **分割线 `hr`** / 顶栏细线 / 卡片细线 | 同上 |
| `codeBg` | 5 | 行内代码 / 代码块 / 数学输入框 / 图表头部 | 这个复用算合理 |

### 4.3 派生色不可调（`color-mix` 硬算）

| 元素 | 现状 | 问题 |
|---|---|---|
| 选中文本背景 | `primary-color 18%` transparent | 18% 是硬编码；深色主题下可能过淡 |
| 链接下划线 | `primary-color 40%` | 同上 |
| 引用块左边框 | `primary-color` 100% | 只有宽度可调（`quoteBorderWidth`），**颜色不可调**；而 `quoteBg` 有独立 token ⇒ 边框与底色**不对称** |

## 五、建议新增的 token（按优先级，只补"视觉身份独立 + 有定制意愿"的）

| 优先级 | 新增 | 映射 | 现状色源 | 收益 |
|---|---|---|---|---|
| **P0** | `listMarkerColor` | `--mk-list-marker` | `text-secondary` | 圆点独立（上一轮已提） |
| **P0** | `surfaceAltColor`（编辑器次级容器） | `--surface-alt` | `sidebar-bg` | 切断 sidebar-token 的 7 路兼职，**大纲面板从此独立** |
| **P1** | `quoteBorderColor` | `--mk-quote-border-color` | `primary-color` | 与 `quoteBg` 对称 |
| **P1** | `tableBorderColor` | `--mk-table-border` | `border-color` | 表格线独立于 UI 分隔线 |
| **P1** | `selectionBg` | `--mk-selection-bg` | `primary 18%` 硬算 | 深色主题下能单独压/提亮 |
| **P2** | `codeTextColor` | `--mk-code-text` | `text-color` | 代码可比正文深一档 |
| **P2** | `hrColor` | `--mk-hr-color` | `border-light` | 分割线独立 |
| **P3** | `scrollbarThumb` | `--scrollbar-thumb` | `border-color` / `muted-color` | 收益小，先不做 |

**每一条都必须带 fallback**：`var(--mk-xxx, var(--原 token))` —— 不声明就退回今天的行为，
退化安全。这是本仓既有范式（`--mk-mark-radius, 0.25em` 就是先例）。

### 明确「不做」的（避免过度工程）

- **不拆 `mutedColor` 的 28 点**：拆成 6 个（placeholder / fold-toggle / block-action /
  frontmatter / menu-desc / syntax-comment）会让模板从 68 涨到 74 项，
  而 95% 的用户不会去调。**设计系统里"语义复用"是正确做法，不是缺陷**。
  真正需要的是**文档写清它管什么**。
- **不拆 hljs 8 类语法色**：已映射到功能色，拆开会变 8 个专属字段，投入产出比极低。
- **不改 `codeBg` 的 5 点复用**：都是"代码类容器"，语义一致。

## 八、验收口径（写"用户这么操作得到 X"）

1. 下载模板 → 不改任何内容 → 导入应用 → **屏幕文本与当前主题完全一致**（行距/标题/圆点全不变）
2. 只改 `primaryColor` → 只有链接/光标/语法关键字/勾选框变色，**表格线、代码块边框、分割线不变**
3. 改 `sidebarBg` → **只有右侧大纲面板变**；代码块工具条、数学块、设置窗口底栏不变
4. 改 `listMarkerColor` → **只有列表圆点变**，正文次要文字不变
5. 改 `markBg` → 高亮底色变（现在根本改不到）
6. 模板里每一个字段，屏幕上都能找到**恰好一处**对应的变化（无假开关）
