## 二、P2 详情（1 条）

### P2-1 ~~切文档不清 undo 栈~~ —— 已被实验复核推翻（2026-10-25）

初判「跨文档撤销可静默改坏新文档」，**两轮独立实验均推翻**：workbuddy 复核 + 本机用项目同版本 `prosemirror-history@1.5.0` 在 state 级重跑（复刻 `replaceDocumentWithoutHistory` 三行），共 10 个场景——段中插入 / 第一段段首插字 / 段中删除 / 清空整段 / A·B 同构文档 / 加粗切换（AddMarkStep）/ **文档最顶整段插入 / 文档末尾整段追加（边界场景，回执未测）/ 切后先打字再连撤三次**。结果：切文档后撤销**从不改变新文档内容**——旧事件位置全部落进整篇替换的删除区间，重映射后 step 或被丢弃（steps=0），或塌缩成零宽空 ReplaceStep（实测 `{"from":0,"to":0}`，文档逐字节相同，仅光标移动一次）。内容不变 ⇒ 不置脏 ⇒ 不会触发自动保存。原文的「源码坐实」只读到 `addMaps` 分支，漏了 `popEvent` 内部的 remap 投影，误判 step 会原样落位。

**保留备注（低于 P4）**：这份安全性依赖「替换区间覆盖整篇」。若将来把 `replaceDocumentWithoutHistory`（`MarkdownEditor.vue:351`）改成局部替换（如按 diff 只换变动块），落在区间外的旧事件会重新生效，本风险回归；届时同步把 `:344-350` 那条与实现不符的猜测注释改成真实机制说明。详见 [`REVIEW-性能内存响应审计-核实-2026-10-25.md`](./REVIEW-性能内存响应审计-核实-2026-10-25.md)。

### P2-2 快捷键单条改键/删键不触发持久化与菜单刷新

- **位置**：`src/components/Settings/useShortcutSettings.ts:77`（`settings.customShortcuts[item.id] = keyStr`）、`:83`（`delete settings.customShortcuts[item.id]`）——**原地增删 key，引用不变**；对照 `src/stores/settings.ts:361`（watch 源 `() => this.settings.customShortcuts`，无 `deep`）、`useMenuShortcutsSync.ts:15-23`（同款引用 watch）。
- **机理**：watch 源只读容器引用，原地写 key 不改引用 ⇒ 两个 watch 都不触发。`settings.ts:83-84` 注释对 customThemes 有一模一样的认知（「原地 push/splice 引用不变，diff 抓不住」），且 customThemes 已加显式脏标记（`:328`/`:341` `_explicitDirtyFields.add('customThemes')`）——**同一型陷阱，customShortcuts 是漏网的第二个**。
- **后果**：① 单条改键/删键不落盘（`_pendingSettings` 从未置位，`flushPendingSettings` 也救不了）——此后若不再改任何其他设置，**重启即丢**；② 原生菜单键位提示不刷新；③ 面板内 UI 正常、全局快捷键本会话生效（读方按 key 粒度追踪能跟上）——即「当场好用、重启没影」，最难被察觉的那类。
- **触发频率**：每次在设置里改/重置单条快捷键。无性能成本，纯正确性。
- **修法方向**：改走换引用写法 `settings.customShortcuts = { ...settings.customShortcuts, [id]: key }`（reset 用解构删 key），或仿 customThemes 加显式脏标记。`resetAllShortcuts` 已核实不受影响（整体赋值 `{}` 换引用，watch 触发、正常落盘——2026-10-25 复核确认）。

## 六、核查过、确认没问题（防重复劳动）

- **全文正则只在一次性路径**：protectCodeRegions + ZWNJ 两遍只在 `parseMarkdown`（打开/切换/粘贴），handler 按 schema WeakMap 缓存。
