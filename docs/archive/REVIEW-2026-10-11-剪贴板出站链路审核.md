# 剪贴板出站链路审核（2026-10-11 · 只读）

> 审核方式：先读基线文档（敏感区 #13/§11.8、paste-compat-decision、KNOWN-ISSUES §一 #16/#24/#25/#42/#43/#46、§二 #11），再读实际代码，最后**程序化实测**（临时探针跑真实 schema 的序列化器与 markdown-it，跑完即删；现有 `clipboard-serializer.spec.ts` 27 条全绿，佐证下列问题是**测试未覆盖的缺口**，非既有失败）。**未改任何被审代码。**

## 0. 一句话总结论

**双管道整体是健康的，但有三处确凿破口**：① 脚注走 solo→solo 的 HTML 管道会**崩溃 + 丢引用**（最严重）；② 「复制为 Markdown 源码」对**整张表格**丢 GFM 语法；③ 状态栏「复制全文」按钮的 text/html 对 callout/wikilink/数学/mermaid **四种自家语法失真**（10-09 批3 已报，现状仍未修）。其余（frontmatter、图片尺寸、callout/wikilink/数学/mermaid 的 solo→solo 往返、两套转义分离、选区剥开口层）**实测全部正确**。

## 1. 出站四条路径 × 两槽全景（先厘清"双管道"到底有几条）

| 出站动作 | text/plain 由谁产出 | text/html 由谁产出 |
|---|---|---|
| 普通选区 `Ctrl+C` | `serializeClipboardText`（干净文字 / 专有节点回落源码），接线在 `MarkdownEditor.vue:341` | **ProseMirror 默认** `DOMSerializer.fromSchema`（走各节点 `renderHTML`，**不走 NodeView**） |
| 单元格选区 `Ctrl+C`（CellSelection） | `onEditorCopy` 覆盖为 **TSV**（`MarkdownEditor.vue:692-695`） | `onEditorCopy` 覆盖为逐行 `<p>`（丢格内行内格式） |
| `edit.copyAsMarkdown`（Mod+Shift+M） | `serializeClipboardSlice`（源码，轻量转义）`editor-commands.ts:152-160` | **无**（只 `writeText`） |
| 状态栏「复制全文」按钮 | 全量源码 `content`（文件模式严格转义） | `renderMarkdown`（**markdown-it**，与上面 PM 默认是**两套不同的 HTML 生产者**）`StatusbarQuickActions.vue:35-59` |

> ⚠️ **C2 教训的现实映射**：text/html 有**两个互不相同的生产者**——`Ctrl+C` 走 PM `DOMSerializer`（renderHTML），按钮走 `markdown-it`。同一份内容两条路产出**保真度不同**（见 §3 P1-3：callout/wikilink 在 `Ctrl+C` 路径干净、在按钮路径漏原始标记）。修其中一条不等于两条都好。

## 3. 实测确认「正确」的项（避免只报忧）

- **solo→solo HTML 往返**（复刻 PM 剪贴板：`DOMSerializer.serializeFragment` → `PMDOMParser.parse` → `serializeMarkdown`）：**frontmatter、图片 width/height、图片 title、callout(type/title/fold)、wikilink(target/alias)、行内公式(latex)、块公式、mermaid、表格** 全部对称还原（`md2 === 源规范化`）。**唯一破口是脚注**（P1-1/P1-2）。
- **两套转义分离正确**：clipboard 轻量（`` ` * ~ [ ] < > `` + 行首 `# + - . > =`）vs 文件严格，`createChild` 继承 clipboard 模式（`serializer.ts:122-124`）⇒ 引用块内、表格单元格内正文不再多出 `\=` `\$`（`x = 1 与 100$ 报价` 三种容器输出一致，实测 + 现有测试复证）。
- **选区剥开口层正确**（#16 语义）：格内选两字、引用块内选字、列表项内选字都只粘选中文字、不带容器标记（实测 `剪映` / `这是引用` / `苹果`）。
- **链接不回落、专有节点回落、ZWNJ 不出站**：`[百度](url)` 纯文本槽给 `百度`；含公式/互链/callout/脚注/图片/frontmatter 回落 Markdown 源码；`**沉浸式体验，**继续` 纯文本槽无 U+200C（均符合 §11.8，实测）。
- **`Ctrl+C` 的 text/html（PM DOMSerializer）对 callout/wikilink 比按钮路径干净**：renderHTML 出显示文字（`<span class="mk-wikilink">display</span>`、`<div class="mk-callout" data-callout-type>`），**不漏** `[[…]]`/`[!NOTE]`。但**数学/mermaid 仍是原始 source**（`<span data-type="math-inline">E=mc^2</span>`、`<div data-type="mermaid-block">flowchart…`）——因为 DOMSerializer 走 renderHTML 而非 NodeView（KaTeX/mermaid SVG 不进剪贴板）。即：`Ctrl+C` 粘数学/图表到 Word 也是原始 latex/源码（与 P1-4 同类，但**这条是 PM 默认行为，非 solo 独有缺陷**，修复面更大）。
