# 互链改名同步方案（一页纸，过目用）

## 要解决的那一件事
你把一个文档**改了名字**之后，别的文档里指向它的链接还写着旧名——**看着是旧的、点进去还打不开**。
这个方案就治这个：改名那一刻，**顺手把同目录其它文档里写着旧名字的那条链接，一起改成新名字**。一次动作，"显示旧名"和"点开断链"两个毛病一起解决。

## 最关键的一道闸：先列清单，你点头才动
改名不会偷偷批量去改你的文件。存下新名字的那一刻，软件会先弹一句：

> 有 N 篇文档链到它，要不要把里面的链接一起更新？（列出是哪几篇）

你点"更新"才动手，点"取消"就什么都不碰。**理由**：这类跨文件改动没有"一键全部撤销"的后悔药，让你先看清楚、点个头，比事后补救稳得多。

## 动的时候会守的规矩（红线）
- **只动那种用双括号包起来的链接、且名字一字不差的那一处**——绝不拿"笔记"去误改"笔记本"，也不碰正文里出现的普通词，不碰普通链接。
- **链接后面若你另写了显示文字，那部分保持原样不动**，只改真正指向的名字。
- **只改"别的文件"、不动你正在编辑的这篇**；若另有窗口正开着被改到的文件，软件不去猜它有没有未保存改动，而是靠既有的「文件已被外部修改」提示与保存冲突检测兜底——**绝不会静默覆盖你还没存的东西**。
- **每篇都是"整篇写成功才算数"**，中途断电/出错不会出现改了一半的残篇。
- **范围锁死在同一个文件夹、只认 Markdown 文档**，不往外跑、不跟着快捷方式改到别处。
- **只有名字真的改成功了，才去动链接**——不会抢跑改出一堆指向不存在名字的链。

## 出错了怎么退
改之前那一步没跑，就不会有半途状态；改完会明确告诉你**动了哪几篇**。因为是纯文字改动，万一哪篇想退回，对照清单手动改回一处即可，不会被连带影响。

## 怎么算修好了（验收）
- 改个名，同目录里链到它的文档，链接名当场跟着变、点开能打开。
- 若被改到的某篇正开在另一个窗口且有未保存改动——它会收到既有的「文件已被外部修改」提示、保存时走冲突确认，不会被静默覆盖。
- "笔记"改名叫别的，不会误伤"笔记本"；正文里的普通词、普通链接不受影响。
- 改名中途取消——什么都没改。
- 你点"不更新"——链接维持原样，也不报错。

## 这次明确不做（避免跑偏）
- 反向链接面板（"谁链到我"）——那是另一次产品取舍，不在这个方案里顺手带。
- 让链接去跟着正文里的标题变——方向错，不做。
- 跨文件夹、整盘的链接更新——**主动**只圈同目录（并非"链接本来只能在同目录解析"，见下方已知限制）。

## 已知限制（2026-09-12 审查补充，是刻意边界、非 bug）
- **只覆盖同目录、且链接是"裸名"或带 `.md`**（`[[名]]` / `[[名.md]]`，含 `|别名`）。
- 手打 / 从别处粘贴进来的 `[[子目录/名]]`、`[[名.markdown]]`、`[[名.txt]]` 这三类**不改写**——因为解析器 `resolveWikilinkTarget` 其实认得子目录、且"带任意扩展名就原样保留"，而我们刻意只扫同目录、只补 `.md`。将来若要覆盖，需同步放开候选/拖入的递归与扫描范围。
- **只跳过 ``` / ~~~ 围栏代码块**内的示例；缩进式代码块（行首 4 空格）与行内代码（单反引号 ``[[名]]``）里的 `[[旧名]]` **仍会被改**。误伤需同时满足"代码里恰好举例写了旧名"+"旧名正是被改名文档"，概率极低，故接受此限制。

## 实现落点备忘（已落地）
- 触发点挂在 `useDocumentSession.saveRenamedDocument()` 里"改名 + 存内容都成功"**且已释放 isSaving 锁之后**——弹框等用户确认期间不再持有保存锁，不影响"另存为"。
- 将来若做"外部文件自动同步"那个功能，本方案对文件的写入要和它统一口径（自家人改的要认得出，别当成外部改动反弹一次冲突）。
