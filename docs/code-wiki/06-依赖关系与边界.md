# 06 · 依赖关系与边界

> 判断「新代码该放哪」和「这样引用会不会破坏边界」，看这一页。规则的目标只有一个：**依赖方向不能反过来**。

---

## 1. 总体依赖方向

```
                    ┌──────────────────┐
                    │  components/     │  只负责渲染与交互
                    └────────┬─────────┘
                             │ 允许
                    ┌────────▼─────────┐
                    │  composables/    │  业务编排
                    └────────┬─────────┘
                    允许 ↙        ↘ 允许
          ┌─────────────────┐   ┌──────────────────┐
          │  stores/        │   │  services/tauri/ │
          │  Pinia 状态      │   │  IPC 唯一出口     │
          └─────────────────┘   └────────┬─────────┘
                                         │ invoke
                                ┌────────▼─────────┐
                                │  Rust commands   │
                                └────────┬─────────┘
                                         │
                    ┌────────────────────▼────────────────────┐
                    │ state / models / error / events / menu  │
                    └─────────────────────────────────────────┘
```

**箭头只许向下**：下层不得反向 import 上层。

---

## 2. 允许 / 禁止矩阵

| 从 \ 到 | components | composables | stores | services | Rust |
|---|---|---|---|---|---|
| `components/` | ✅ | ✅ | ✅ | ✅（少量） | ❌ |
| `composables/` | ❌ | ✅ | ✅ | ✅ | ❌ |
| `stores/` | ❌ | ❌ | ✅（同层） | ✅ | ❌ |
| `services/tauri/` | ❌ | ❌ | ❌ | ✅ | ❌（只 `invoke`） |
| `commands/registry.ts` | ❌ | ❌ | ❌ | ❌ | ❌（纯数据 + 纯函数） |
| Rust `commands/` | — | — | — | — | ✅ `state/models/error/events` |

补充规则：

- `commands/registry.ts` 必须保持**无副作用**：只导出命令定义与查询函数，不 import Vue、不 import store。
- `services/tauri/` 不 import store/composable/component，避免 IPC 层被 UI 状态污染。
- `MarkdownEditor.vue` 可以直接读两个 store（编辑器是状态密集型组件），这是已知例外，不再扩散。
- `StatusbarQuickActions.vue` 直接持有 `editorRef` 调 `getContent()`，是复制按钮的刻意例外。

## 4. Rust 模块依赖

| 模块 | 可以依赖 | 说明 |
|---|---|---|
| `lib.rs` | 全部 | 唯一装配点 |
| `commands/*` | `state` / `models` / `error` / `events` / 同层纯函数 | 不反向依赖 `lib.rs` |
| `menu.rs` | `events` / `models` | 不依赖 commands |
| `state.rs` | `models` | 不依赖 commands |
| `models.rs` | 仅 serde | 最底层 |
| `error.rs` | 仅 std/tauri/reqwest | 最底层 |
| `events.rs` | tauri | 只发事件 |
| `native_resize.rs` | windows crate | 平台隔离，不碰业务 |

**禁止**：在 `models.rs` 里 import command；在 `error.rs` 里 import state；让 `commands/document.rs` 直接创建窗口。

## 5. 第三方依赖分组

### 5.1 运行时（前端）

| 组 | 包 | 用途 |
|---|---|---|
| 框架 | `vue`、`pinia` | UI 与状态 |
| Tauri API | `@tauri-apps/api` | 窗口/事件/路径 |
| Tauri 插件 | `plugin-dialog`、`plugin-clipboard-manager`、`plugin-opener`、`plugin-store`、`plugin-updater`、`plugin-window-state` | 系统对话框、剪贴板、外链、设置持久化、更新、窗口状态 |
| 编辑器 | `@tiptap/core`、`@tiptap/vue-3`、`@tiptap/pm`、`@tiptap/starter-kit`、各 `extension-*`、`@tiptap/suggestion` | 编辑内核与扩展 |
| Markdown | `markdown-it` + `footnote/mark/sub/sup/task-lists/texmath` | 解析 |
| 数学/图表 | `katex`、`mermaid` | 渲染（懒加载） |
| 代码高亮 | `highlight.js`、`lowlight` | 代码块 |
| 工具 | `lodash-es` | 防抖、深拷贝等 |

### 5.2 构建与测试

`vite`、`@vitejs/plugin-vue`、`vue-tsc`、`typescript`、`tailwindcss` + `@tailwindcss/postcss`、`postcss`、`vitest`、`happy-dom`、`commonmark-spec`、`eslint` + Vue/TS 配置、`prettier`。

### 5.3 overrides

`package.json` 的 `overrides` 固定 `dompurify`、`linkify-it`、`prosemirror-model`、`prosemirror-view`。**不要随意删除**：这些是间接依赖的安全/一致性补丁。

### 5.4 Rust 依赖（分组）

| 组 | crate | 用途 |
|---|---|---|
| 框架 | `tauri`、`tauri-plugin-*` | 应用与插件 |
| 序列化 | `serde`、`serde_json` | DTO |
| 网络 | `reqwest` | 字体/远程图片 |
| 异步/运行时 | `tokio` | 异步命令与后台清理 |
| 平台 | `windows`（Windows） | 原生缩放、WebView2、注册表 |
| 工具 | `once_cell`、`url`、`sha2`/哈希类 | 全局状态、URL 解析、缓存键 |

> 精确版本与启用 feature 以 `src-tauri/Cargo.toml` 为准。

## 6. 构建分包

`vite.config.ts` 的 `manualChunks` 目标：主包尽量小，重依赖按需/独立加载。

| chunk | 内容 |
|---|---|
| `vendor-tiptap` | TipTap / ProseMirror |
| `vendor-markdown` | markdown-it 及插件 |
| `vendor-katex` | KaTeX |
| `vendor-mermaid` | Mermaid（大，独立） |
| `vendor-highlight` | highlight.js |
| `vendor` | 其余稳定第三方 |

Tailwind 4 通过 PostCSS 接入；主题色不写在 Tailwind 配置里，而是 CSS 变量，保证运行时换肤。

## 7. 机器锁与它们保护的东西

| 锁 | 文件 | 防什么 |
|---|---|---|
| 架构漂移 | `src/__tests__/arch-drift.spec.ts` | 命令表/扩展清单与 `ARCHITECTURE.md` 不一致 |
| 事件定向 | `src/__tests__/event-dispatch-target-lock.spec.ts` | 误用全局广播导致多窗口串扰 |
| schema 契约 | `src/__tests__/schema-contract.spec.ts` | schema 与 parser/serializer 的节点/属性不匹配 |
| mark 定界符 | `src/__tests__/mark-delimiter-coverage.spec.ts` | 成对定界符转义漏网导致 roundtrip 变形 |
| 外部样式 | `src/components/Editor/tiptap/__tests__/external-styles.spec.ts` | 导出样式漂移、CSS 变量泄漏 |
| 序列化性能 | `src/components/Editor/tiptap/__tests__/serializer-perf-guard.spec.ts` | 序列化热路径退化 |
| 图标 | `src/__tests__/icon-spec.spec.ts`、`icon-usage.spec.ts` | 图标尺寸/用法不统一 |
| 菜单图标 | `src/__tests__/menu-icons.spec.ts` | 菜单与图标映射错位 |

> 测试文件会增删，具体以 `src/**/__tests__` 与 `bun run test` 输出为准。

## 9. 新代码放哪：决策顺序

1. **是纯渲染/交互吗？** → `components/`。
2. **是跨组件流程吗？** → `composables/`。
3. **需要跨组件共享且长生命周期吗？** → `stores/`。
4. **需要与系统/磁盘/原生交互吗？** → `services/tauri/` + Rust command。
5. **是命令/快捷键元数据吗？** → `commands/registry.ts`（保持无副作用）。
6. **是 Markdown 语法映射吗？** → `tiptap/extensions/` 或 `markdown/plugins/`，并同步机器锁。

反例：把 `invoke` 写进组件、把 Rust 命令名拼在业务代码里、把主题色写死在 `<style>` 里、在 `models.rs` 里创建窗口 —— 都属于边界破坏。
