# 01 · 系统架构

> 架构事实的权威版本是 [ARCHITECTURE.md](../../ARCHITECTURE.md)。本页把它整理成一条可顺序阅读的路线，并补充「为什么这样分层」。

---

## 1. 产品约束如何塑造架构

| 产品约束 | 架构结果 |
|---|---|
| 秒开、零卡顿、安装包小 | Tauri 2 + Rust 原生核心，不套 Electron；编辑器单实例复用，不做「一切换文件就重建」 |
| 一个文件就是一个文件，没有文件树 | 无 workspace / watcher / 侧边栏；文件操作集中在 `commands/document.rs` |
| 所见即所得，语法即时隐藏 | TipTap / ProseMirror schema 驱动，Markdown 只是读写格式，不是编辑态 |
| 粘贴网页内容要保格式 | 自研 parser / serializer + 剪贴板双通道（text/plain + text/html） |
| 中文写作优先 | 字体 7 档、中文 fallback 字体栈、IME 组字保护、`allowedPrefixes: null` 的 suggestion |
| 多窗口一窗一文档 | 窗口 label 路由、定向事件、跨窗口改名/互链广播 |

## 2. 技术栈（版本以源码为准）

| 层 | 技术 | 在项目中的角色 |
|---|---|---|
| 桌面框架 | Tauri 2 | 窗口、菜单、IPC、插件、打包 |

| 前端框架 | Vue 3（Composition API + `<script setup>`） | UI 与业务编排 |

## 3. 三层结构

### 3.1 Vue 前端 (`src/`)

```
main.ts
  └─ App.vue                     协调层：初始化、视图模式、窗口控制、命令接线
       ├─ composables/           业务编排单元（数量以目录实际为准）
       ├─ stores/                file.ts / settings.ts
       ├─ commands/registry.ts   命令、默认快捷键、冲突检测
       └─ components/            Editor / Settings / Layout / 命令面板 / 弹出层
```

**职责边界**：组件负责渲染与交互，composable 负责流程，store 负责跨组件状态，`services/tauri/` 负责 IPC。组件不直接调 `invoke`。

### 3.2 IPC 服务层 (`src/services/tauri/`)

```
client.ts          invokeCommand<T>() —— 全仓唯一 invoke 入口
command-names.ts   TAURI_COMMANDS —— 命令名唯一登记表
document.ts        文档打开/保存/改名/图片
session.ts         最近文件 + 阅读位置
window.ts          窗口标题/全屏/关闭/缩放/启动 ready
dialog.ts          系统对话框
clipboard.ts       读取系统剪贴板 HTML
events.ts          菜单/关闭/焦点/拖拽/跨窗口广播监听
font.ts            字体下载与缓存
asset.ts           asset:// URL 生成
update.ts          更新检查
store.ts           tauri-plugin-store 封装
```

**契约**：上层只拿到领域函数和结构化 DTO；Rust 的 `AppError` 在这里被 `normalizeTauriError()` 转成 `{ code, message }`。

### 3.3 Rust 核心 (`src-tauri/src/`)

```
main.rs            进程入口：独立 WebView2 用户数据目录 → lib::run()
lib.rs             插件注册、setup、菜单、启动开打、窗口创建、命令注册
commands/          document / session / image / font / clipboard / window / desktop
state.rs           5 类 managed state（启动竞态 + 焦点 + 关窗看门狗）
models.rs          DTO（camelCase / kebab-case 序列化）
error.rs           AppError 枚举与结构化 Serialize
events.rs          定向事件常量与 emit 辅助
menu.rs            原生菜单构建与事件挂载
updater.rs         更新代理检测
native_resize.rs   Windows 原生边缘缩放
```

## 5. 启动顺序

### 5.1 Rust 侧

1. `main.rs`：为当前进程准备独立 WebView2 用户数据目录，避免多进程 LevelDB 锁竞争。
2. `lib.rs::run()` 注册插件：opener、dialog、clipboard-manager、cli、store、window-state、updater。
3. `setup()`：
   - `app.manage(...)` 注册 5 类状态；
   - 解析 CLI / OS-open 参数，写入 `StartupOpenRequests`；
   - 构建原生菜单并挂事件；
   - 给窗口挂关闭拦截与焦点事件；
   - macOS 设置窗口背景色。
4. 注册 `generate_handler!` 命令。
5. `run()` 回调处理 macOS/iOS 的 `Opened` URL 事件。

### 5.2 前端侧

`App.vue` 的 `onMounted` 顺序是刻意分阶段的：

```
initThemeOnly()        只读主题与背景色，先避免黑闪
windowSession.setup()  发 startup_ready，窗口显示 + 回放启动开打请求
init() + syncMenuShortcuts() + autoCheckForUpdate()
listenEditorFocus()    窗口获得焦点时检查外部修改
```

窗口创建时默认 `visible(false)`，等前端 `startup_ready` 再 `show()`，避免白屏/黑闪。

## 6. 多窗口模型

- 每个编辑窗口有唯一 label（`main-*`），前端按当前窗口监听事件。
- Rust 的 `menu-event` / `window-close-requested` 用 `emit_to(window.label(), ...)` **定向发送**，不是全局广播。否则会出现「关 B 窗口把 A 也关掉」。
- 菜单动作只作用于当前焦点窗口，焦点 label 存在 `FocusedWindow`。
- 两类跨窗口广播走 JS 侧全局 `emit`：
  - `solo:wikilinks-synced`：别的窗口改名后，本窗口正开的文档内容被改写了 → 需要重载。
  - `solo:file-renamed`：文档只是换路径 → 跟随路径，**绝不重载**，避免抹掉未保存编辑。
- `request_app_quit` 是应用级退出：向所有已加载窗口发关闭请求，各窗口自己确认/保存，全部关闭后进程自然退出。

## 8. 三条横切机制

### 8.1 会话记忆

最近文件（上限 10）与阅读位置（上限 50，按最近读取淘汰）由 Rust 单文件 JSON 管理。滚动位置存**比例**不存像素，窗口尺寸变化后仍成立。数据刻意不进 Pinia：跨窗口、一次性读写、由 Rust 落盘。

### 8.2 大文档分档

按「剔除 base64 图片后的可见字符数」分三档：

| 档 | 门槛 | 行为 |
|---|---|---|
| `normal` | < 50 万 | 全功能 |
| `heavy` | ≥ 50 万 | 停止实时字数全量统计、代码语言自动检测、段落淡化；启用 `content-visibility` |
| `extreme` | ≥ 200 万 | 打开前需确认才进可编辑模式 |

门槛定义在 `src/components/Editor/document-scale.ts`。**下调门槛会让更多文档暴露在已知 IME 候选窗风险下**，改动前先读该文件头注释。

### 8.3 Windows 原生窗口缩放

Windows 上不用前端透明 div，而是 Rust 创建 `WS_CHILD` 覆盖子窗，`WM_NCHITTEST` 直接返回缩放命中码。效果是零 JS、零 IPC、零竞态。`WindowResizeHandles.vue` 只在非 Windows 平台渲染。该模块无法单测，必须真机按 DPI 档位验收。

## 9. 信任边界

- 所有用户输入、外部文件路径、网络下载内容都视为不可信。
- 图片资产路径必须经 `authorize_image_asset` / `validate_image_asset_path` 校验，防路径遍历与符号链接逃逸。
- 字体缓存文件名与路径都做校验，禁止 `../` 逃出缓存目录。
- 前端不拼接 Rust 命令名，`TauriCommandName` 类型把拼写错误挡在编译期。
- 出站 HTML 经过归一层，剥离私有标签/属性，公众号/Word 只拿到通用结构。
