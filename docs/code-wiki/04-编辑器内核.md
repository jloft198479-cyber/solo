# 04 · 编辑器内核

> 编辑器是 solo 最贵的部分：保真、IME、列表语义、剪贴板出站都集中在这里。改动前先读 [sensitive-areas.md](../sensitive-areas.md) 对应条目。

## 1. `MarkdownEditor.vue`

### 1.1 组件契约

```ts
props: {
  initialContent?: string
  outlineOpen?: boolean
}
emits: {
  (e: 'update', data: EditorUpdatePayload): void
  (e: 'image-dblclick', src: string): void
  (e: 'navigate-wikilink', path: string): void
}
```

`defineExpose` 暴露给 App / 状态栏 / 关闭链的能力：

| 导出 | 作用 |
|---|---|
| `scrollToPos(pos)` | 按块节点定位滚动，标题停到视口上方约 1/4 |
| `getContent()` | 当前序列化 Markdown；有 doc 级缓存 |
| `getDoc()` | 当前 ProseMirror doc |
| `isSyncedWithStore()` | store 基线是否已是当前 doc 的序列化产物 |
| `getEditorView()` | 底层 `EditorView`（供搜索/特殊操作） |
| `hasFocus()` | 编辑器是否聚焦 |
| `executeCommand(id)` | 执行编辑器命令 |
| `undo()` / `redo()` | 撤销/重做 |
| `openSearch(showReplace?)` / `closeSearch()` | 打开/关闭查找替换 |
| `handleDocumentDrop(...)` | 拖入文档时尝试建互链，未命中返回 false 由外层回落「打开」 |
| `flushReadingPosition()` | 关窗前强制落盘阅读位置 |

### 1.2 实例复用与懒初始化

- 全组件只创建**一个** TipTap 实例（`shallowRef`），切换文件只 `setContent`，不 destroy 重建。
- 懒初始化：挂载时无焦点不建；获得焦点 / `solo:editor-focus` / `requestAnimationFrame` 兜底后才建，避免后台窗口空耗。
- 切文件时若序列化结果相同则跳过 `setContent`。
- 监听 `[path, reloadToken, pathFollowToken]`：
  - `reloadToken` → 磁盘内容已载入，换 doc；
  - `pathFollowToken` → 同一文档换路径，只更新路径派生物，绝不回灌内容。

### 1.3 内部编排

| 组合 | 作用 |
|---|---|
| `useEditorSync` | 文档变更 → 统计/大纲/序列化/脏态 |
| `useEditorSearch` | 查找替换、搜索高亮 |
| `useEditorAppearance` | 字体、主题、代码高亮注入 |
| `useOutline` | 大纲面板数据 |
| `useImagePreview` | 图片预览视图 |
| `installImeAnchorGuard` | Windows 窗口缩放后重锚编辑焦点 |

## 2. 扩展体系

### 2.1 工厂

```ts
createEditorExtensions(options: EditorExtensionOptions)
```

返回数组是扩展注册的**唯一真相源**，位于 `tiptap/editor-extensions.ts`。`ARCHITECTURE.md §8.3` 的清单与它双向机器比对（`arch-drift.spec.ts`），本页只做分类说明，不复制完整顺序。

`EditorExtensionOptions` 提供 Slash / Emoji / Wikilink 三个菜单控制器；`computeMenuPosition` 是三者共用的定位纯函数。

### 2.2 分类

| 类别 | 代表扩展 | 作用 |
|---|---|---|
| 块级结构 | `Frontmatter`、`SemanticHeading`、`CustomCodeBlock`、`CustomTable*`、`CustomImage`、`Callout`、`MathBlock`、`MermaidBlock`、`Footnote*` | 把 Markdown 扩展语法映射为可编辑节点 |
| 行内 mark | `Code`、`Highlight`、`Strike`、`Superscript`、`Subscript`、`Dim`、`Link` | 保留定界符与互斥关系 |
| 列表语义 | `BulletList`、`OrderedList`、`TaskList`、`ListItem`、`TaskItem`、`ListFold` | 列表容器契约、任务项、折叠 |
| 结构守卫 | `ListEnterGuard`、`ListBackspaceGuard`、`CellContentGuard` | 回车/退格/粘贴不得破坏列表与表格结构 |
| 输入与粘贴 | `MarkdownInput`、`MarkdownPaste` | Markdown 快捷输入与粘贴还原 |
| 交互建议 | `SlashCommands`、`EmojiSuggest`、`WikilinkSuggest`、`WikilinkExistence` | `/`、`:`、`[[` 菜单与死链标记 |
| 搜索与占位 | `SearchHighlight`、`Placeholder` | 搜索命中、空文档提示 |
| 焦点模式 | `ParagraphFocus` | 当前段落高亮、其余淡化 |

**StarterKit 禁用清单**：`codeBlock`、`link`、`heading`、`code`、`bulletList`、`orderedList`、`listItem`、`paragraph`、`blockquote`、`strike`、`underline` 被显式关闭后换成自定义 extend 版本，避免重复注册与不可控默认行为。`underline` 必须关闭：CommonMark/GFM 没有下划线语法。

### 2.3 关键守卫函数

## 3. Markdown 解析

文件：`tiptap/markdown/parser.ts`

### 3.1 主链路

```
Markdown 文本
  → 扩展语法预抽取（frontmatter / callout / $$ 数学块占位）
  → markdown-it（commonmark + table + strikethrough + task-lists + mark + sub + sup + texmath + footnote）
  → getTokenHandlers(schema) + 插件 token handler
  → MarkdownParseState
  → ProseMirror Doc
```

| 导出 | 作用 |
|---|---|
| `parseMarkdown(schema, content)` | 唯一解析入口 |
| `MarkdownParseState` | 维护节点栈、mark 栈、列表状态 |
| `getTokenHandlers(schema)` | 基础 token → PM 节点映射 |
| `decodeLinkDestination(value)` | 还原本地 `file:` 等链接的编码 |
| `installBlockMathGuard(md)` | 块级公式守卫，防止 `$$` 被误拆 |

texmath 传入**空壳 KaTeX 引擎**：解析器只分词不渲染，真正 KaTeX 懒加载，不进入解析热路径。

### 3.2 插件

`markdown/plugins/` 承载扩展语法：

| 插件 | 责任 |
|---|---|
| `frontmatter` | 前置 metadata 抽取与还原 |
| `callout` | `> [!note]` 等块级提示 |
| `math` | 行内/块级数学公式 |
| `mermaid` | Mermaid 代码围栏 |
| `wikilink` | `[[...]]` 互链 |
| `footnote` | 脚注 |
| `fence` | 代码围栏长度与冲突计算 |

`plugins/index.ts` 汇总导出：

```
markdownSyntaxPlugins
getPluginTokenHandlers(schema)
getPluginNodeSerializers()
getPluginFenceHandlers(schema)
getPluginTokenInterceptors(schema)
getPluginPreprocessors(schema)
```

## 4. Markdown 序列化

文件：`tiptap/markdown/serializer.ts`

| 导出 | 作用 |
|---|---|
| `MarkdownSerializerState` | 序列化状态机：节点栈、mark 栈、转义、缩进 |
| `NodeSerializer` | 单节点写出函数类型 |
| `serializeMarkdown(doc)` | 全量保存/复制用；**末尾恰好一个换行** |
| `serializeMarkdownForClipboard(doc)` | 剪贴板专用输出 |
| `serializeClipboardSlice(doc, slice)` | 选区切片 |
| `serializeClipboardText(doc, slice)` | 编辑器内 `Ctrl+C` 的纯文本路径（选区感知、轻量转义） |
| `escapeLinkDestination(src)` | 链接目标转义 |

**核心难点**：按「写出形态」计算成对字符转义，避免 `superscript` / `highlight` / `math` 等 mark 的定界符与字面量重新配对，导致重开格式变化。

### 4.1 代码围栏

`plugins/fence.ts`：

- `maxCharRun(text, ch)`：文本中连续字符最大长度；
- `lineClash(content, fenceChar, fenceLen)`：判断围栏是否与内容冲突；
- `computeFence(content, fenceChar = '`')`：生成长度安全、不与内容冲突的围栏。

## 5. 出站 HTML 与剪贴板

### 5.1 两条通道

| 通道 | 入口 | 档位 | 行为 |
|---|---|---|---|
| 状态栏「复制」 | `serializeDocumentHtml(doc)` | `document` | 删全部 frontmatter；拆 `div.tableWrapper` |
| 编辑器内 `Ctrl+C` | `createSelectionClipboardSerializer()` | `selection` | 只删第一块 frontmatter；永不拆 `tableWrapper` |

两条通道都进入 `externalize-html.ts::externalizeHtml(root, target)` 归一：

- 剥离 solo 私有标签/属性，保留通用结构；
- 统一图片 `src`：`data-src` 优先、排除 `data:`/`blob:` 占位、相对/绝对择优、`//` 归一为 `https:`；
- callout 标题同时写 `data-title` 与正文首段（`data-solo-injected-title`），回读只删带标记的那段。

### 5.2 内联样式

`external-styles.ts::inlineReadingStyles(root)` 把阅读形态逐条内联：

- 字号/行高/间距运行时读 `--mk-*`，与屏幕同源；
- 颜色固定为中性灰，避免把深色主题带进白底文章；
- **禁止输出 `var(--...)`**：微信会丢弃 CSS 变量；
- 字重必须与 `editor.css` 一致，有测试锁。

编辑器不在时（图片预览模式）回落到 `utils/markdown-to-html.ts::renderMarkdown`，这是兜底，不是正统出口。

## 7. 主题系统

`themes/manager.ts`：

```ts
applyTheme(theme)             // 外观 class + 颜色变量 + 排版变量
triggerContentCrossfade()     // 编辑区淡入
getPresetTheme(id)
getAllPresetThemes()
getTheme(id, customThemes)
importTheme(json, appearance)
generateThemeId()
```

`applyTheme` 做三件事：

1. 切 `<html>.dark`，同步原生窗口主题/背景色；
2. 按 `CSS_VAR_MAP`（`themes/types.ts`）把 `ThemeColors` 写入 `--bg-color` / `--text-color` 等；
3. 先 `removeProperty` 再注入 `--mk-*` 排版变量（行高、字号、标题梯度、段距、字距、引用边框）。

主题分三层：

- 范式层：`CSS_VAR_MAP` + 共享默认色 + `editor.css :root`；
- 实例层：`themes/presets/` 下的预设 JSON，只写性格差异字段；
- 消费层：所有组件只引用 `var(--x)`。

新增主题只需填 `typography`，不必改渲染代码。

## 8. 字体系统

| 文件 | 内容 |
|---|---|
| `constants/fonts.ts` | `FONT_OPTIONS`：系统默认 + 微软雅黑 UI + 5 款远程字体；有 `fileName` = 下载型，无 = 系统字体 |
| `utils/fontStack.ts` | `buildFontStack(primary)`：生成带中文 fallback 的完整字体栈，编辑器与导出共享 |
| `services/fontLoader.ts` | `ensureFontLoaded` / `isFontAvailable` / `isFontFailed` / `onProgress` / `PROGRESS_DONE` |
| `useFontStatus.ts` | 字体下载进度与失败状态的 Vue 封装 |

加载策略：

1. 首选 `@font-face` + `asset://` URL，浏览器内核直读磁盘，不走 CORS；
2. 失败回退 `read_font_bytes` 经 IPC 取字节 → `new FontFace(...)` 同源加载；
3. 系统字体跳过；已缓存复用；加载中去重。

## 10. 改编辑器前的检查清单

1. 改 parser / serializer / schema：先跑 roundtrip + fixtures + fuzz + schema-contract + mark-delimiter-coverage。
2. 改 NodeView：事件监听必须挂 `AbortController`，`destroy()` 里 `abort()`，异步回写检查 `signal.aborted`。
3. 改扩展注册：同步 `ARCHITECTURE.md §8.3` 机器锁清单。
4. 改剪贴板：同时验证 `text/plain` 与 `text/html`，以及「编辑器不在」的回落路径。
5. 改排版：只消费 `--mk-*`，不硬编码尺寸/颜色。
