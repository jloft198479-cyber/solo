# 03 · 前端外壳

> 这一页讲「编辑器之外的 Vue 应用」：谁负责启动、谁持有状态、命令怎么分发、IPC 怎么封装。编辑器内核见 [04-编辑器内核.md](./04-编辑器内核.md)。

---

## 1. `main.ts`

极简入口，只做三件事：

```ts
const app = createApp(App);
app.use(createPinia());
app.mount('#app');
```

没有全局路由、没有全局事件总线；所有流程都在 `App.vue` 与 composables 里显式接线。

---

## 2. `App.vue`：协调层 + 少量界面编排

### 2.1 职责

| 类别 | 内容 |
|---|---|
| 协调 | 初始化 settings store、window session、菜单快捷键同步；把 composable 能力组合进命令分发器 |
| 模板 | `CustomTitlebar` + 主区域（editor / image 视图切换）+ 状态栏 + 设置弹窗 + 图片全屏层 |
| 全局拖放 | 文件 drop → `documentSession.openDocumentWithPrompt(path)` |
| 启动编排 | `initThemeOnly` → `windowSession.setup()` → `init()` + `syncMenuShortcuts()` + `autoCheckForUpdate()` |
| 焦点模式提示 | 进入 3.5s、退出 2s 的提示状态机，定时器成对清理 |
| 窗口关闭 | 标题栏 X 先原生关闭；失败回退前端关闭链；再失败 `destroyCurrentWindow()` |
| 外部修改 | 状态栏告警点击 → `openDocumentWithPrompt(path)`（内部含脏态确认） |
| Shell 集成 | watch `shellIntegration` → `registerShellNew` / `unregisterShellNew` |

视图模式：`activeViewMode = 'editor' | 'image'`，另有独立的 `isFullscreenPreview`。

### 2.2 启动顺序（`onMounted`）

```
initThemeOnly()          只读主题与背景色，避免黑闪
windowSession.setup()    发 startup_ready，显示窗口并回放启动开打
settingsStore.init() + syncMenuShortcuts() + autoCheckForUpdate()
listenEditorFocus()      窗口获得焦点 → 检查外部修改
```

顺序刻意分两阶段：先让窗口可见，再加载完整设置，避免用户盯着白屏等配置。

## 3. Composables

> 目录下每个文件导出一个 `useXxx()`。它们负责流程编排，不直接持有跨组件状态（状态在 Pinia）也不直接 `invoke`（IPC 在 services）。

| Composable | 导出 | 职责 | 关键点 |
|---|---|---|---|
| `useDocumentSession` | `useDocumentSession(options)` | 文档生命周期：打开、保存、另存为、自动保存、外部修改、改名跟随 | `_savePromise` 互斥；自动保存递归调度；保存前用编辑器实时内容评估脏态 |
| `useCommandDispatcher` | `useCommandDispatcher(options)` | 命令分发：`scope=editor` 转发编辑器，`scope=app` 走应用动作 | 菜单、快捷键、命令面板的单一入口 |
| `useAppDomEvents` | `useAppDomEvents(options)` | 全局 keydown → 查快捷键 → 分发 | 输入框/IME 场景需让路 |
| `useAppEditorState` | `useAppEditorState()` | 编辑器状态桥接：字数、大纲、光标、选区 | 定义 `AppEditorExpose` / `AppEditorUpdatePayload` |
| `useAppWindowSession` | `confirmUnsavedChanges()` / `useAppWindowSession(options)` | 窗口会话：启动开打、关闭确认、标题、全屏、拖放 | `handleCloseRequest` → `runCloseChain` |
| `useMenuEvents` | `useMenuEvents(onCommand)` | 监听 `menu-event` → 分发 | 只处理本窗口事件 |
| `useMenuShortcutsSync` | `useMenuShortcutsSync(options)` | 自定义快捷键变更 → 同步原生菜单 | 只更新 accelerator，不重建 |
| `useImagePreview` | `useImagePreview()` | 图片预览视图模式状态机 | 与 `activeViewMode` 配合 |
| `useFloatingListMenu` | `useFloatingListMenu<T>(options)` | SlashMenu / EmojiMenu 共享的浮动菜单逻辑 | 键盘导航、定位、关闭 |
| `useOutline` | `useOutline()` | 大纲提取与导航 | 与 `OutlinePanel.vue` 配合 |
| `useEditorSync` | `useEditorSync(options)` | 编辑器 ↔ store 同步、统计防抖 | 脏态 A1 核心；多档防抖 |
| `useClickOutside` | `useClickOutside(...)` | 点击外部检测 | 通用 |
| `useFontStatus` | `useFontStatus()` | 字体下载/可用/失败状态 | 三键按 family 索引；带竞态防护 |

### 3.1 `useDocumentSession` 关键函数

| 函数 | 作用 |
|---|---|
| `loadDocumentFromPath(path, silent)` | 调 Rust 打开 → 文档分档 → 写入 store → 触发编辑器换文档 |
| `applyLoadedDocument(document)` | 把打开结果落到 `fileStore` |
| `openDocumentWithPrompt(path, silent)` | 未保存确认 + 外部修改警告后的统一打开入口 |
| `handleOpenDocument()` | 系统对话框选文件并打开 |
| `evaluateDirtyFromEditor()` | 取编辑器实时序列化结果评估脏态，绕开 500ms 防抖 |
| `saveCurrentDocument(force?, manual?)` | 保存；带互斥锁、自动保存计数、冲突处理 |
| `saveCurrentDocumentAs()` | 另存为 |
| `saveRenamedDocument()` | 标题改名 → 另存为 → 改名 → 同步互链 |
| `syncInboundWikilinks(oldPath, newPath)` | 改名后同步指向本文档的互链并广播 |
| `checkExternalModification()` | 窗口获得焦点时比对 mtime，提示外部修改 |
| `handleWikilinksSynced(payload)` | 别的窗口改写了本窗口正开的文件 → 处理重载 |
| `handleFileRenamed(payload)` | 别的窗口改名 → 跟随路径，不重载 |
| `stopAutoSave()` | 关闭前停止递归自动保存 |

### 3.2 `useEditorSync` 防抖分层

| 延迟 | 内容 | 为什么 |
|---|---|---|
| 100ms | 光标行号 | 状态栏需要跟手 |
| 150ms | 字数统计 | 接近实时，但不逐键重算 |
| 500ms | 大纲 | 结构变化不频繁，可慢 |
| 500ms | `serializeMarkdown()` → `fileStore.syncEditedContent()` | 序列化贵，等停顿再跑 |

`onUpdate` 是单一出口。heavy 档且大纲面板关闭时跳过全文大纲提取；空闲序列化撞上继续输入时推迟回防抖，不在输入中途硬跑大序列化。

## 4. Pinia Store

### 4.1 `stores/file.ts`：文档状态（短生命周期）

```
currentFile: {
  path, content, isDirty, lastModifiedTime, displayName, originalBaseName
}
isLoading: boolean
reloadToken: number       // 仅 setFile() 递增：磁盘内容已载入，编辑器必须换文档
pathFollowToken: number   // 仅 renamePath() 递增：同一文档换路径，只更新派生物
```

| Action | 语义 |
|---|---|
| `setLoading(loading)` | 状态栏加载条 |
| `setContent(content)` | 只同步基线，**不标脏** |
| `syncEditedContent(content)` | 脏标记唯一真相源：去掉尾部换行后语义比对；不同才更新并标脏 |
| `setFile(content, path, mtime)` | 载入新文档，重置脏态，递增 `reloadToken` |
| `setDisplayName(name)` | 修改标题并标脏 |
| `renamePath(newPath)` | 只换路径，保留内存编辑，递增 `pathFollowToken` |
| `syncLastModifiedTime(mtime)` | 跨窗口改名跟随时对齐磁盘时间基线 |
| `markSaved(mtime?, content?)` | 清脏；传 content 时同步基线为实际落盘内容 |

**关键区分**：`reloadToken` 触发「换文档」，`pathFollowToken` 触发「只换路径」。混用会导致未保存编辑被旧基线洗掉。

### 4.2 `stores/settings.ts`：全局设置（长生命周期）

15 个字段：

`activeThemeId`、`customThemes`、`fontSize`、`fontFamily`、`autoSave`、`autoSaveInterval`、`spellCheck`、`titlebarAutoHide`、`lineHeight`、`customShortcuts`、`alwaysOnTop`、`imageStoragePath`、`shellIntegration`、`enableAutoUpdateCheck`、`configVersion`。

| 机制 | 说明 |
|---|---|
| 持久化 | `tauri-plugin-store`（`settings.json`），变更后 300ms 防抖写盘 |
| 关窗兜底 | `flushPendingSettings()` 强制落盘，防抖窗口内关窗不丢最后一次改动 |
| 迁移 | `configVersion` 当前 12；版本不符 → 规范化后一次性回写 |
| 规范化 | 合并默认值、`autoSaveInterval ≥ 5s`、刷版本号 |
| 主题回退 | 主题 id 失效时按当前外观回退到 `scholar-dark` / `default-light` |
| 两阶段启动 | `initThemeOnly`（只读主题，避免黑闪）→ `initFull` / `init`（全量设置 + watcher） |
| 多窗口合并 | 写前 `reloadStoredSettings()`，只写本窗改过的 dirty 字段，避免旧值洗掉他窗改动 |
| 焦点模式 | `<html>` 上 toggle `focus-mode` |
| 窗口置顶 | `toggleAlwaysOnTop()` 调窗口 API |

## 5. 命令系统

### 5.1 `commands/registry.ts`

命令是声明式数据，不是散落在各处的回调：

```ts
interface CommandDefinition {
  id: string;
  title: string;
  description: string;
  icon?: string;
  scope: 'app' | 'editor';
  group: CommandGroup;
  defaultShortcut?: string;
  menuSection?: MenuSection;
  palette?: boolean;
  fixedShortcut?: boolean;
}
```

| 导出 | 作用 |
|---|---|
| `COMMANDS` | 全部命令定义 |
| `COMMAND_LOOKUP` / `getCommand(id)` | 按 id 查命令 |
| `getShortcut(id, custom)` | 取生效快捷键（自定义优先） |
| `getShortcutCommands(custom)` | 取有快捷键的命令 |
| `getShortcutGroups(custom)` | 设置页按组展示 |
| `findCommandByShortcut(event, custom)` | 全局 keydown 反查命令 |
| `eventToKeyString(event)` | 键盘事件 → 规范化键串 |
| `formatShortcutDisplay(shortcut)` | 面向用户的快捷键文案（Mac/Win 符号） |
| `shortcutHint(...)` | 提示文案 |
| `toTauriAccelerator(shortcut)` | 转 Tauri 菜单 accelerator |
| `getMenuShortcuts(custom)` | 菜单快捷键映射 |

消费方：`CommandPalette.vue`、设置页快捷键编辑器、`useAppDomEvents`、`useMenuShortcutsSync`、`CustomTitlebar.vue`。改字段前先确认这几处。

### 5.2 分发

```
shortcut / menu / palette
        │
        ▼
executeCommand(id, source)
        ├─ scope = 'editor' → editorRef.executeCommand(id)
        └─ scope = 'app'    → 应用动作（打开/保存/设置/退出/视图）
```

`edit.find` / `edit.replace` 虽是 app scope，但会转发给编辑器。

## 6. IPC 服务层

### 6.1 统一入口

```ts
invokeCommand<T>(command: TauriCommandName, args?): Promise<T>
```

- 内部包 `@tauri-apps/api/core` 的 `invoke`；
- `catch` 后 `normalizeTauriError()` 统一成 `{ code, message }`；
- 命令名受 `TauriCommandName` 类型约束，拼错编译期就报。

### 6.2 领域封装

| 文件 | 关键导出 |

| `session.ts` | `recordDocumentSession` / `readDocumentSession` / `DocumentSessionState` / `ReadingPosition` |
| `window.ts` | `setCurrentWindowTitle` / `isCurrentWindowFullscreen` / `setCurrentWindowFullscreen` / `destroyCurrentWindow` / `closeCurrentWindow` / `minimizeCurrentWindow` / `toggleCurrentWindowMaximized` / `startCurrentWindowResize` / `startupReady` / `refreshNativeMenuShortcuts` / `revealStartupOpenLog` / `setCurrentWindowTheme` / `setCurrentWindowBackgroundColor` / `registerShellNew` / `unregisterShellNew` / `setCurrentWindowAlwaysOnTop` / `newEditorWindow` / `requestAppQuit` / `reportWindowClose` |

### 6.3 错误展示

`normalizeTauriError` 只做结构化，不改文案。`withErrorHint` 在展示层给 Windows 错误码补「该怎么做」，例如 `os error 32` → 提示文件被占用。**不要把它挪进 `normalizeTauriError`**：启动路径靠匹配原始 `os error 2` 做静默跳过。
