# 05 · 关键数据流

> 排查「为什么没保存 / 没刷新 / 关不掉 / 内容被洗掉」时，先在这页找到链路，再看对应函数。

---

## 1. 启动并显示窗口

```
main.rs 准备独立 WebView2 数据目录
  → lib.rs::run() 注册插件
  → setup(): manage 状态、解析启动参数、建菜单、挂窗口事件
  → 创建窗口 visible(false)
  → 前端挂载
      → initThemeOnly()（避免黑闪）
      → windowSession.setup()
          → startupReady()
              → Rust 显示窗口
              → 回放 PendingWindowPaths / StartupOpenRequests
      → initFull() + syncMenuShortcuts() + autoCheckForUpdate()
```

**关键点**：窗口先隐藏后显示；启动开打请求有缓冲，不依赖前端加载时机。失败过程写 `startup-open.log`。

## 2. 打开文档

```
用户：Ctrl+O / 拖入文件 / 最近文件 / 启动参数
  → useDocumentSession.openDocumentWithPrompt(path)
      ├─ 有未保存改动 → confirmUnsavedChanges()
      ├─ 有外部修改警告 → 先处理
      ├─ loadDocumentFromPath(path)
      │     ├─ services/document.openDocument(path)
      │     │     └─ Rust：扩展名校验 → 读 UTF-8/UTF-16 → 返回 {path, content, lastModifiedMs}
      │     ├─ countVisibleChars → resolveDocumentTier
      │     ├─ extreme → 确认弹窗，取消则中止
      │     ├─ fileStore.setFile(content, path, mtime)   // reloadToken++
      │     └─ MarkdownEditor 监听 reloadToken → parseMarkdown → setContent
      └─ recordDocumentSession(path) + 恢复阅读位置
```

**易错点**：

- `setFile` 是「换文档」，会递增 `reloadToken`；仅换路径必须用 `renamePath`（递增 `pathFollowToken`）。
- 打开失败不能把旧文档清空：错误在 `fileStore` 之外处理，保留当前编辑。
- 极端大文档进可编辑前必须确认；取消应回到空态或旧文档，不能半载入。

## 3. 编辑 → 脏态

```
TipTap onUpdate
  → useEditorSync 防抖 500ms
      → serializeMarkdown(doc)
      → fileStore.syncEditedContent(content)
          → 去掉尾部换行后与基线语义比对
          → 不同才更新 content 并置 isDirty = true
```

其它延迟层：

| 延迟 | 内容 |
|---|---|
| 100ms | 光标行号 |
| 150ms | 字数 |
| 500ms | 大纲 |
| 500ms | 序列化 + 脏态 |

**脏态唯一真相源**是 `syncEditedContent`，不是编辑器事件本身。保存前若防抖未跑，`evaluateDirtyFromEditor()` 会立即序列化一次补评估。

## 4. 保存

```
手动 Ctrl+S / 自动保存 / 关窗保存
  → saveCurrentDocument(force?, manual?)
      → if (_savePromise) 复用/排队（互斥，避免并发写）
      → evaluateDirtyFromEditor() 取实时内容
      → services/document.saveDocument({ path, content, lastModifiedMs })
          → Rust：
              ├─ 扩展名校验
              ├─ mtime 冲突检测（磁盘比基线新 → Conflict）
              ├─ 写同目录临时文件
              └─ rename 原子替换
      → fileStore.markSaved(newMtime, savedContent)
      → recordDocumentSession(path)
      → autoSaveStatus = saved
```

**冲突**：返回 `document_conflict`，前端提示「文件已被外部修改」，让用户选择覆盖/另存/放弃，不静默覆盖。

**自动保存**：`autoSave` 开启后递归调度，间隔取 `autoSaveInterval`（最小 5s）；`stopAutoSave()` 在关闭链最前面调用，避免保存与关窗互相踩。

---

## 5. 另存为

```
saveCurrentDocumentAs()
  → 系统保存对话框选目标
  → Rust 写文件
  → fileStore.setFile(content, newPath, mtime)   // 切到新路径并重置脏态
  → 记录会话
```

保存失败（目标被占用/无权限）时保持原路径与原内容，不切换。

## 6. 标题改名 → 同步互链

```
用户改标题（displayName）→ saveRenamedDocument()
  ├─ services/document.renameFile(oldPath, newName)        // 先原子移动文件
  ├─ persistDocument(newPath, force=true)                  // 再把内容写入新路径
  ├─ fileStore.setFile(savedContent, newPath, mtime)       // 换文档基线
  ├─ emitFileRenamed({ oldPath, newPath })                 // 他窗跟随路径
  └─ syncInboundWikilinks(oldPath, newPath)
        ├─ Rust：扫同层 + 向上 2 层，改写 [[旧名]] → [[新名]]
        └─ emitWikilinksSynced({ paths })                  // 他窗正开被改文件则提示/重载
```

**顺序很重要**：先 rename 再写内容。若 rename 成功但写内容失败，store 必须 `renamePath(newPath)` 跟上新路径并保留脏态，否则下次保存会再次 rename 旧路径而永久卡死。互链同步放在保存锁释放之后执行，避免弹框期间持有锁导致「另存为」无响应。

**为什么区分两个事件**：改名的文件本身只是换路径，内容没变，重载会抹掉未保存编辑；被改写互链的文件内容变了，必须让正开着它的窗口知道。

## 7. 关闭窗口

```
用户点 X / Alt+F4
  → Rust CloseRequested
  → CloseGuard.evaluate(label, 3s)
      ├─ Prompt  : prevent_close + emit window-close-requested
      ├─ Waiting : prevent_close（吞重复）
      └─ Force   : 放行（前端疑似卡死）
  → 前端 handleCloseRequest()
      ├─ reportWindowClose('ack')   // 必须先发，fire-and-forget
      ├─ stopAutoSave()
      ├─ flushPendingSettings()     // 300ms 防抖窗口内的设置
      ├─ flushReadingPosition()     // 当前滚动比例
      ├─ 脏态确认（保存 / 不保存 / 取消）
      ├─ 需要则 saveCurrentDocument()
      ├─ 保存窗口状态
      └─ destroyCurrentWindow()
```

失败/取消：

- 用户取消 → 前端发 `reportWindowClose('abort')` → `CloseGuard` 复位，窗口继续可用；
- 关闭链抛异常 → 同样 `abort`，避免「窗口再也关不掉」；
- 3 秒无应答 → `Force` 放行，是逃生舱，不是正常路径。

标题栏 X 的优先级：原生 `closeCurrentWindow()` → 失败回退前端关闭链 → 再失败 `destroyCurrentWindow()`。

## 8. 退出应用

```
request_app_quit
  → 向所有 LoadedWindows 定向发 window-close-requested
  → 每个窗口各自走第 7 节关闭链
  → 全部关闭 → 进程自然退出
```

不是强杀：任一窗口取消，应用就留下。避免多窗口未保存内容丢失。

---

## 9. 外部修改

```
窗口获得焦点（solo:editor-focus）
  → useDocumentSession.checkExternalModification()
      → getFileMtime(path) 与 lastModifiedTime 比对
      ├─ 相同 → 清除告警
      └─ 不同 → statusbar 外部修改告警
            → 用户点击 → openDocumentWithPrompt(path)
                → 脏态确认 → 重新打开
```

不在焦点时轮询：本地优先应用不应在后台持续碰磁盘。

## 10. 多窗口协作

| 场景 | 行为 |
|---|---|
| 同一文件在两个窗口打开 | 各自独立基线；保存冲突由 mtime 检测兜底 |
| A 窗口改名 | A 广播 `file-renamed`；B 若开着旧路径 → `renamePath`，不重载 |
| A 窗口改名导致 B 正开的文件互链被改写 | A 广播 `wikilinks-synced`；B 提示/重载被改文件 |
| 菜单/快捷键 | 只作用于焦点窗口（定向事件 + `FocusedWindow`） |
| 退出 | 逐窗口确认，全部关闭才退出 |

## 11. 图片

### 11.1 插入本地图片

```
拖入 / 粘贴文件 / 选择图片
  → Rust import_document_image
      ├─ 校验扩展名与来源
      ├─ 复制到文档同目录 assets/（或设置目录）
      ├─ 同名自动加 -1/-2 后缀
      └─ 返回 relativePath / absolutePath
  → authorize_image_asset（加入 asset 协议作用域）
  → 编辑器插入 CustomImage 节点
```

### 11.2 粘贴剪贴板图片

```
paste 事件带 image/*
  → canvas/blob → data URL
  → Rust save_clipboard_image
      ├─ parse_data_url（MIME + base64）
      ├─ 解码并校验大小
      └─ 写入 assets/
```

### 11.3 远程图片

```
Markdown 含 http(s) 图片
  → fetch_remote_image
      ├─ 下载（≤ 10MB）
      ├─ 类型校验
      ├─ 按 URL 哈希写入 remote-image-cache/
      └─ 返回缓存路径
  → resolve_image_display / asset 协议显示
```

缓存 200MB 上限，按 mtime 淘汰；启动时后台清理，近期写入 10 分钟宽限。离线或失败时保留原始 URL，不阻塞编辑。

## 12. 字体与主题

### 12.1 字体

```
选择字体
  → settingsStore 更新 fontFamily
  → buildFontStack → 写入 --font-family
  → 下载型字体：
      ├─ ensureFontLoaded
      ├─ getCachedFontPath
      ├─ 未缓存 → fetchFontData（Rust 下载 + 写缓存）
      ├─ @font-face + asset:// URL
      └─ 失败 → read_font_bytes → new FontFace 兜底
```

### 12.2 主题

```
选择主题
  → settingsStore 更新 activeThemeId
  → applyTheme(theme)
      ├─ 切 <html>.dark
      ├─ 同步原生窗口主题/背景色
      ├─ 写入颜色变量
      └─ 注入 --mk-* 排版变量
  → triggerContentCrossfade()
```

主题文件是纯数据 JSON，不执行代码；加载前做结构校验与 id 规范化。

## 13. 剪贴板出站

```
状态栏「复制」 / 编辑器 Ctrl+C
  → 双槽写入：
      text/plain : Markdown 源码（裁剪掉零宽字符）
      text/html  : externalizeHtml + inlineReadingStyles
  → 微信/公众号/Word 优先取 text/html，代码编辑器取 text/plain
```

编辑器不在（图片预览模式）时，用 `renderMarkdown` 兜底生成 HTML，保证复制按钮不哑火。

## 14. 会话记忆

```
打开/保存/滚动
  → record_document_session(path, ratio?)
      ├─ 最近文件：去重置顶，上限 10
      ├─ 阅读位置：path → ratio，上限 50，按最近读取淘汰
      ├─ 内存中改完整结构
      └─ spawn_blocking 原子写回
启动
  → read_document_session → 最近文件列表 + 恢复阅读位置
```

滚动存比例不存像素，窗口尺寸变化后仍成立。损坏的 session 文件视为空状态重建，不弹错。
