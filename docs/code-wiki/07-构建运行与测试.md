# 07 · 构建运行与测试

> 构建细节的唯一真理源是 [BUILD_GUIDE.md](../../BUILD_GUIDE.md)；验收等级的真理源是 [agent-playbook.md §C](../agent-playbook.md)。本页是「按场景该跑什么」的索引。

## 1. 环境准备（Windows）

| 工具 | 作用 | 说明 |
|---|---|---|
| Rust stable（MSVC toolchain） | 编译原生核心 | 版本要求见 `BUILD_GUIDE.md` |
| MSVC Build Tools 2022 | C++ 链接器 / Windows SDK | 勾选「使用 C++ 的桌面开发」 |
| WebView2 | Tauri 渲染容器 | Windows 10+ 通常内置 |
| Bun | 包管理与脚本 | 仓库锁定版本见 `package.json.packageManager` |

工具链可能装在非默认盘。**以 `BUILD_GUIDE.md §2–§3` 的实际路径与环境变量为准**，不要照抄别处的路径。

常见环境坑：

- `CARGO_HOME` / `RUSTUP_HOME` 必须全大写；
- PowerShell 调 `.bat` 可能给 `RUSTUP_HOME` 末尾加空格；
- 缺 MSVC 时 `cargo check` 也要跑，CI 是最终闸门。

```bash
bun install
```

## 2. 命令表

| 场景 | 命令 | 说明 |
|---|---|---|
| 只调前端 | `bun run dev` | Vite 开发服务器，浏览器里没有原生能力 |
| 完整桌面开发 | `bun run dev:tauri` | 推荐；Tauri + Vite |
| 带 DevTools | `bun run dev:tauri:inspect` | 设 `SOLO_OPEN_DEVTOOLS=1` |
| 前端类型检查 | `bunx vue-tsc --noEmit` | 本地唯一必跑项 |
| 前端构建 + 打包安装包 | `bun run build` / `bun run build:tauri` | **默认交给 CI**；仅排障且经同意时本地跑 |
| 全量测试 | `bun run test` | `vitest run` |
| 只跑改动相关 | `bun run test:changed` | 信号聚焦；**不查文档死链** |
| 全量 + 保真体检 | `bun run test:full` | 跨平台安全 |
| Lint | `bun run lint` | ESLint，已自动拦 `invoke(`、`String.replaceAll` |
| 自动修复 | `bun run lint:fix` | |
| 格式化 | `bun run format` | Prettier |

## 3. 按改动半径选验证

| 改动半径 | 必跑 |
|---|---|
| 样式 / 文案 / 单组件内部 | `bun run test:changed` |
| 前端任意改动 | `vue-tsc --noEmit` |
| 任意 Rust | `cargo check` |
| parser / serializer / schema | `vue-tsc` + `bun run test` 全量 + `bun run test:full` 保真体检 |
| 时序 / UI / IME / 异步 | 上述 + 真机手感（人工或 CDP 探针） |
| 发版 / 大规模重构 / 跨模块 | `bun run test:full`（构建与打包交给 CI） |
| 新增 / 改名 / 删除 Rust 命令 | `command-names.ts` → `commands/mod.rs` → `lib.rs` → `ARCHITECTURE.md §4.2` 四处同步 |
| 纯文档搬家 / 改名 / 删文件 | `bun run vitest run src/__tests__/docs-lint.spec.ts`（查死链） |

> `vite build` 不在日常门禁里；日常 `vue-tsc` + 相关测试足够。`test:changed` 的价值是「红的就是你的锅」，不是省时间。

## 4. 测试网

| 类型 | 代表 | 保护什么 |
|---|---|---|
| 行为锁（A 级） | `roundtrip`、`fixtures` | 打开→保存后格式/内容是否保真 |
| 契约锁（B 级） | `schema-contract`、`mark-delimiter-coverage`、`arch-drift` | 结构/名单是否齐全 |
| 棘轮锁（C 级） | `fidelity-scan` | 只许变好不许变坏 |
| 功能单测 | 图片粘贴、表格、列表、快捷键、设置迁移、会话、改名跟随 | 具体行为 |
| 文档锁 | `docs-lint.spec.ts` | 相对链接是否死链 |

**能当交活依据的只有 A 级行为锁**；B/C 级只是警报器。验收结论写「用户这么操作，得到 X」，不写「N 条锁转绿」。

新增锁的准入：

1. 能一句话说清它防的是哪个**已发生的事故**；
2. 做过**反向校准**（撤掉修复，锁必须转红）；
3. 能归到 A/B/C 某一级。

## 5. 调试入口

| 问题 | 入口 |
|---|---|
| 前端白屏 / 控制台错误 | `bun run dev:tauri:inspect` 开 DevTools |
| 启动参数没打开文件 | `reveal_startup_open_log` 返回的 `startup-open.log` |
| 窗口不显示 | 检查前端是否发了 `startup_ready`；Rust 显窗看门狗 |
| 保存失败 | 看 `AppError.code`：`document_conflict` / `io_error` / `validation_error` |
| 关窗卡住 | `CloseGuard` 3 秒 `Force`；检查前端是否先发 `ack` |
| 多窗口串扰 | 检查是否误用 `emit` 全局广播而非 `emit_to` |
| 字体不生效 | 先看 `getCachedFontPath`，再看 `@font-face` 失败后的 `read_font_bytes` 兜底 |
| Rust 编译失败 | `cargo check --manifest-path src-tauri/Cargo.toml` |
| 已知缺陷 | [KNOWN-ISSUES.md](../KNOWN-ISSUES.md) |
| 踩坑方法论 | [LESSONS.md](../LESSONS.md) |

## 6. 目录级自检

提交前快速过一遍：

- [ ] `git status` 干净起步，改动范围可解释；
- [ ] 没有直接 `invoke(` / `String.replaceAll`；
- [ ] 没有硬编码颜色/尺寸/超时/路径；
- [ ] 新 Rust 命令四处同步；
- [ ] 新扩展同步 `ARCHITECTURE.md §8.3`；
- [ ] NodeView 监听器有 `AbortController` 且在 `destroy()` 里 `abort()`；
- [ ] 新增文件没有制造第二份真理源；
- [ ] 纯文档改动跑了死链检查。

## 7. 发版前

1. 版本号三处同步：`package.json` / `src-tauri/Cargo.toml` / `src-tauri/tauri.conf.json`；
2. 查 `String.replaceAll`；
3. `bun run test:full`；
4. 确认 **CI 构建与打包通过**（不在本地跑 `bun run build` / `build:tauri`）；
6. tag 与版本号一致；
7. 完整流程见 [RELEASE_PROCESS.md](../RELEASE_PROCESS.md)。

---

## 8. 不要做

- 不要擅自装软件/依赖；工具链位置以 `BUILD_GUIDE.md` 为准。
- 不要为了「跑通」跳过 `cargo check` 或类型检查。
- 不要把 `bun run test` 绿了当功能验收；行为要用真实操作验证。
- 不要在 Windows 上只用前端缩放把手验证原生缩放；必须真机按 DPI 档位验收。
