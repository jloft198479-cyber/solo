## 2. 必修 A：验收 #1 的计数断言必红

验收 #1 要求 `<li>`/`<pre>`/`<hr>`/`<sup>` 等「计数与归一前逐项相等」，但改法本身会改结构：

| 元素 | 归一层动作 | 计数变化 |
|---|---|---|
| `sup` | 规则 5 把 `sup[data-footnote-ref]` 替换为文本 `[N]` | **−1** |
| `li` | 规则 5 把 `div[data-footnote-def]` 转 `<li>` | **+定义数** |
| `hr` | 规则 5 脚注 section 前插 `<hr>` | **+1** |
| `pre` | 规则 6 把 math-block / mermaid-block 转 `<pre>` | **+2** |

括号注「（ZWNJ/属性清洗不改结构）」说明本意是限定范围，但清单把**会改结构的元素**混进去了。⇒ 应改写为：「`<h1>/<strong>/<em>/<code>/<mark>/<s>/<sub>/<a>/<table>/<th>/<td>/<ul>/<ol>/<blockquote>/<input>` 计数与归一前相等（仅属性清洗与拆壳，不改结构）」，并把 `li/hr/pre/sup` 的**期望值**单列断言。

## 3. 必修 B：ZWNJ 只剥 TextNode ⇒ 属性通道漏网（实测）

规则 2 明写「遍历 `TextNode`…整串 `split/join` 会连属性一起碰，不做」。实测证明**属性确实带 ZWNJ**：

| 用例 | DOMSerializer 输出 | 通道 |
|---|---|---|
| `![**甲，**乙](a.png)` | `<img … alt="**甲，**乙">` | **属性**（ZWNJ 在 `alt` 内） |
| `[x](https://a "**甲，**乙")` | `<a … title="**甲，**乙">` | **属性**（ZWNJ 在 `title` 内） |
| `**甲，**乙`（段落） | `<strong>甲，</strong>` | 文本 |

而规则 8 的白名单**保留** `alt` / `title` / `href` / `id` / `class` ⇒ 这些属性里的 ZWNJ 直接出站，**P1-5 修不干净**。

> 这不是新知识：`tiptap/zwnj.ts` 的文件头已明写「ZWNJ 也会固化进节点 attrs，而 attrs 的序列化**不经过** `escapeInline`，必须在各写出点显式剥（台账 §二 #32 / 敏感区 #23④）」；台账 §二 #32 就是为此立的。归一层作为**新的出站写出点**，必须同样对待。

**修法**：规则 2 扩为「遍历 TextNode **+ 遍历元素属性值**（对每个属性值调 `stripZwnj`，空串则删属性）」。顺带把规则 2 的理由改准——「不做整串 split/join」的理由应是「避免误伤标签语法」，而不是「避免碰属性」（属性恰恰必须碰）。

## 4. 决策 E：白名单清洗会破坏「按钮复制 → 粘回 solo」的保真（未声明的取舍）

规则 8 删掉一切非白名单属性，包含 solo 自己的语义载体：

| 被删属性 | 粘回 solo 的后果 |
|---|---|
| `data-type="taskItem"` | Tiptap TaskItem 的 `parseHTML` 认不出来 ⇒ **任务列表降级为普通列表**（勾选框仍在，因为 `<input>` 保留，但不再是可交互任务项） |
| `data-callout-type` | callout 规则 `div[data-callout-type]` 落空 ⇒ **callout 降级为普通 div/段落** |
| `data-wikilink` | 互链降级为纯文本 |

现状（markdown-it 通道）粘回 solo 同样降级，所以**不算回归**；但方案**没有声明这个取舍**，实施者会以为「换生产者后 HTML 更强了」而忽略它的代价。而且这里有一个**真实的两难**：

- 对外消费者对未知属性通常是**宽容的**（Word/公众号/Notion 忽略 `data-*`）⇒ 保留私有属性对外基本无害；
- 但对 solo 自己，它们是**语义本体**。

⇒ 建议把「**按钮复制 → 粘回 solo，期望保真还是可降级？**」作为**决策点交简乐拍板**：若要保真，规则 8 应改为「只删已知有害属性」而非白名单全删（此时 P1-5 的「私有属性外泄」定性也要跟着改：外泄本身无害，只有 ZWNJ 是有害的）。

## 5. 表述 C / D 与论证 F

- **C（③ 的 try 位置）**：原句「取数保持在 `try` 内**之外**的现状结构不动，但要把 `getDoc()` 也放进 `try`」自相矛盾，且 `getDoc()`（`editor.value?.state.doc ?? null`）**不会抛**——真正会抛的是 `getContent()`（它内部调 `serializeMarkdown`，正是 F4 指的原爆点）。改法应是「把 `getContent()` 移进 `try`（或外包一层 try）」，否则 F4 等于没修。
- **D（第 3 条 fallback）**：NodeView 的判据是 `title \|\| normalizeCalloutType(calloutType)`（`callout.ts:22/121`），方案写成 `title \|\| type`。抽 `calloutDisplayTitle()` 时必须把 `normalizeCalloutType` 一起带上——否则正是方案要避免的漂移。
- **F（不接管 Ctrl+C 的理由）**：`data-pm-slice` 复刻确实是风险，但**更根本的理由**是：Ctrl+C 的 HTML 同时也是 **solo→solo 的语义载体**，归一化（删 `data-*`、`<pre>` 化）会**直接打断内部粘贴保真**——这是方案自己的规则 3/5/6/8 的必然结果。建议按此改写，否则后人会以为「只要能复刻 `data-pm-slice` 就能接管」，从而做出破坏性改动。
  - 附带：`handleDOMEvents.copy` 拿不到 PM 已写好的 clipboardData，但**同元素上后注册的 `copy` 监听器可以**（`onEditorCopy` 对 CellSelection 就是这么干的）。所以「此路封死」的表述不准确；准确说法是「能修，但要走后处理监听，且会与 CellSelection 分支、PM 默认行为交织，收益不匹配」。

2. **回落路径的失真未声明**：`App.vue` 切到图片预览模式时编辑器卸载 ⇒ `getDoc()` 为 null ⇒ 走 `renderMarkdown` ⇒ **产出的 HTML 仍带 P1-4a~e 全部失真**。方案在 §现状/改法 ③ 提到了回落存在，但「不改什么」没把它登记为**已知降级**，应补一句。
3. 叙述与编号错位：改法里 ④ 是单测、⑤ 是文档，但开头写「先 ①②③…再 ④⑤（表格/脚注这些成块项）」——表格/脚注其实是规则 7/5，不在这两个编号下。
