# 编辑体验 · 行业对标基线

> **立此文档的目的**：2026-10-10 用户立为长期方针 ——「此后处理的所有问题，都要与行业最佳实践对比比较，以向行业最佳看齐为目标」。
> 所以**先查这张表、再定优先级**；新增编辑体验类条目时，在 `KNOWN-ISSUES.md` 里必须写清「对标谁、差在哪」。
>
> 对标对象：**Typora**（形态最贴近，主基准）、**Obsidian**（同为本地 Markdown，副基准）、iA Writer / Craft / Bear / Notion（局部参考）。
> 前身：`REVIEW-2026-10-09-第三方全面审查-批1-宏观与对标.md` §5（带日期快照，本文件为**常驻版**，随新证据更新）。

## 一、先分清「我们对标哪一种」

行业里叫「Markdown 编辑器」的其实是三种形态，混着比会得出一堆假差距：

| 形态 | 代表 | 语法可见性 | 文件干净度 | 契合 solo？ |
|---|---|---|---|---|
| 源码 / 分栏预览 | VS Code、StackEdit、Dillinger | 全程可见 | 最干净 | ❌ 不是我们 |
| 内联预览 Live Preview | Obsidian | 隐藏，**光标进入的那行语法重新显形** | 干净 | ⚠️ 近似 |
| 所见即所得 WYSIWYG | **Typora**、MarkText、Notion | 全程隐藏 | 干净 | ✅ **就是 solo** |

**⇒ solo 与 Typora 同型，一切对标以 Typora 为准**。凡「Typora 也没有」的，不列为本项目的差距（例如拖拽手柄、部分导出能力）。

## 二、逐项基准：行业怎么做 vs solo 现状

| 维度 | 行业基准（Typora 为主） | Obsidian | solo 现状 | 差距 |
|---|---|---|---|---|
| **标题快捷键** | **`Ctrl+1..6` 定级、`Ctrl+0` 回段落、`Ctrl+= / Ctrl+-` 升降级**（官方 Shortcut Keys 页） | 命令面板 / 可自定义 | ❌ 设置页**显示了同一组键**，编辑区内按下去**没反应**（`KNOWN-ISSUES §二 #28`） | 🔴 **大** |
| **标题折叠** | 有大纲面板；正文折叠无 | ✅ **默认开启**（Fold heading + Fold indent），悬停出箭头，可「全折叠/全展开」，可绑热键 | ⚠️ **只有列表能折**（`list-fold.ts`），标题不能 | 🟠 中 |
| 列表 Enter / Tab 语义 | Enter 续项、再 Enter 退出、Tab / Shift+Tab 缩进 | Smart indent lists（同款） | ✅ 已有 | 🟢 无 |
| **列表内放复杂内容** | 支持（项内可放标题/引用/代码） | ⚠️ **长期被吐槽**（缩进渲染不稳、粘多段进列表出错、项内引用/代码块缩进错乱；官方论坛 1.5.3 / 1.11.5 多版本复现帖） | ⚠️ 列表项内标题**上方必有一条空行**（`§二 #30`，schema 硬约束） | 🟠 中（**行业共同难点**） |
| 拖拽重排 | 无 | 官方无，靠社区插件补（Block Drag&Drop / Dragger：Notion 式手柄 + 落点线） | ⚠️ 拖拽**功能是活的**，但没有手柄、没有落点线（`§二 #17`） | 🟠 中（行业也靠外挂） |
| 聚焦模式 | ✅ 块级 + **打字机模式**（当前行垂直居中） | ❌ | ⚠️ 段落级，且**列表整块同亮同暗**（`§二 #24`，方案已定未执行）；**无打字机模式** | 🟠 中 |
| 阅读位置记忆 | ✅ 重开回上次位置 | 官方无，插件补（Last Position / Remember File State） | ❌ 无 | 🟠 中 |
| 最近文件 | ✅ File → Recent Files | ✅ `Ctrl+O` 快开 | ❌ 无（命令面板无该分组） | 🟠 中 |
| 崩溃恢复 | ✅「热保存」+ 恢复现场 | 插件 | ❌ 无 | 🟡 低-中 |
| 复制出去的纯文本 | 干净文字 | 源码 | ✅ 已按 Typora 范式改造（`§一 #24`） | 🟢 **无** |
| 中文 IME | 无专项 | 长期有 IME 抱怨 | ✅ 组字期冻结 + 三层守卫（**局部反超**） | 🟢 **反超** |

| **中文标点边界的强调** | 遵循 GFM 分词、**改写解析规则而非文件内容**（用户所见即文件）【待核实 Typora 对 CJK 边界是否有专门放宽】 | 同 GFM | ✅ 能力达标（中文标点边界也能加粗），但走的是「解析前插 ZWNJ、序列化剥离」路线 ⇒ 引入**横切不变量**：所有出站 / 统计 / 交互路径都得记得剥离（敏感区 #23；目前字数统计与纯文本剪贴板**未闭环**） | 🟡 低（能力达标，机制有债） |

> 注：Obsidian 的列表渲染问题有官方论坛实证，说明「列表里放复杂内容」是**行业共同难点**，solo 的 `#30` 属普遍难题、不是独有缺陷 —— 别按「我们比别人差」定级。

## 三、结论

**solo 在「WYSIWYG + 本地 Markdown + 中文」这条线上，主体能力已达一线水平。**
反超项：复制范式（纯文本干净）、中文 IME 守卫、**列表大纲区（折叠 + 同层换位 + 导轨，Typora 没有）**、12 色 Callout、WikiLink 全家桶、多进程多窗口、装机 14.8MB。

**真正落后的一律集中在两类**（不是散点、是两类）：

1. **承诺未兑现的键位层** —— 设置/提示里写着组合键，编辑区内按下去没反应（`§二 #28` 一族）。这是「失信」而非「缺失」，性质最重。
2. **行业标配、solo 完全缺席的「阅读 / 会话层」** —— 标题折叠、阅读位置记忆、最近文件、崩溃恢复备份、跳转历史（`§二 #17/#19`）。

其余为**行业共同难点**（列表内复杂内容、拖拽手柄）或**已定案未执行**（聚焦下探 `#24`），不应排在最前。

## 四、待拍板（2026-10-10 建议）

| 顺位 | 动作 | 一句话理由 | 成本 | 风险 |
|---|---|---|---|---|
| **1** | **键位一致性（`#28`）**：让注册表默认键与编辑器实际绑定对齐 + 加一致性回归锁 | 设置页写着 `Ctrl+1..6`、按下去没反应；Typora 全靠这组键 —— 这是「承诺了没兑现」，且修它不碰 parser / serializer / schema | S | 零保真风险 |
| 2 | 阅读位置记忆 + 最近文件（`#19` / 批1 §5 #1#2） | 行业标配，用户每次开软件都感知；已躺 4 轮 | M | 低 |
| 3 | 标题折叠（复用既有 `list-fold.ts`） | Obsidian 默认开启的标配，长文档阅读/写作核心杠杆 | M | 中（新 decoration 须走 `composition-freeze`） |
| 4 | 空段落落盘两头（`#29`） | 文件级静默失真，属 solo 最高价值（保真）；仅动 serializer | S-M | 中（碰序列化） |
