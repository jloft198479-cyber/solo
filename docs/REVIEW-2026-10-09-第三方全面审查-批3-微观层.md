## 3. 【本批最重要的功能发现】复制通道对自家四种一等语法失真的

> 【P1】「复制为 HTML」把 callout / 互链 / mermaid / frontmatter **降级成字面文本**，而这四种正是 solo 的一等公民
> **证据链（我亲自比对两条管线的装配清单，不是转述）**：
> - 生产解析器 `parser.ts:96`：`new MarkdownIt('commonmark', {html:false, linkify:false}).enable(['table','strikethrough'])` + `task-lists`/`mark`/`sub`/`sup`/`texmath`/`footnote` **6 个官方插件** + 自建插件组（`plugins/index.ts`）+ 自定义 inline ruler `mk_dim`（`:112-135`）。
> - 复制用的预览管线 `utils/markdown-to-html.ts:51`：`new MarkdownIt({html:false, linkify:false}).enable(['table','strikethrough'])` + **同样那 6 个官方插件**（`:34-58` 我逐行看过）——**但没有任何自建插件、也没有 `mk_dim` ruler**。
> - 差异澄清（**我否掉了一个过头的说法**）：`dim` **不是漏的**，它是**有意剥掉**的——文件头注释 `:1-14` 写明「私有标签剥壳保内层文字」，且 `PRIVATE_TAG_RE`（`:15`）只处理 `mk-dim` 这一条。真正**缺席且未声明**的是另外四条：
>   - **callout** `> [!NOTE] 标题` → 无 callout 插件 ⇒ 渲染成引用块，里面**留着字面 `[!NOTE]`**；
>   - **WikiLink** `[[甲]]` → 无插件 ⇒ **原样带方括号出去**；
>   - **Mermaid** ` ```mermaid ` → 无 renderer ⇒ 变成**纯代码块文本**（图没了）；
>   - **Frontmatter** `---\ntitle: xxx\n---` → 无抽取 ⇒ 按 commonmark 渲染成**文档开头两条横线 + 明文 yaml**。
> - 消费者只有一条：`StatusbarQuickActions.vue:7/34`（状态栏「复制 Markdown」按钮的 `text/html` 槽）。
> - 测试侧：`utils/__tests__/markdown-to-html.spec.ts` 共 5 条用例（`:11/17/21/27/35`），**全部只测 `mk-dim` 剥壳 + 通用格式不误伤**；上述四条**零用例**。
> **影响**：这一条打在**产品自己点名当卖点的能力**上——`docs/solo产品精神.md:42` 写「在 Solo 中，我们就用『复制为 HTML』等轻量方式扩展了『把内容带出去』的能力（如贴到公众号/文档平台），我认为这非常重要」。而现在这条通道对 callout（12 色）、互链、图表、frontmatter 是**失真**的：用户精心排好的一篇带 callout 和图的笔记，一键复制贴进公众号/Notion，得到的是 `[!NOTE]` 字面量、`[[某文件]]` 和一段 mermaid 源码，文档开头还多两条横杠。**而且没有任何一处文档或测试声明过这个降级**——`FEATURE-MATRIX` §7 只说「状态栏复制按钮：`text/html` = 渲染富文本」。
> **建议**（不改代码，只给方向）：① **最低成本**是把这件事写成事实——在 `FEATURE-MATRIX` §7 与 wiki 明确「复制为 HTML 目前不支持 callout/互链/图表/frontmatter，会按字面输出」，别让用户体验到才发现；② 真修则是让预览管线复用 `plugins/index.ts` 的装配清单（09-14 审计原话就是「可共享插件装配清单」，现在它已从「结构重复」恶化成「行为差异」）。

> 【P2·平行事实】`sanitizeForExternal` 只认 `mk-dim` 一条，与「私有语法清单」没有任何绑定
> **证据**：`utils/markdown-to-html.ts:15` 的 `PRIVATE_TAG_RE` 是**手写的单条正则**。而项目私有语法至少有 7 种（dim / callout / wikilink / frontmatter / 脚注 / 数学 / 图片 `|WxH`）。新增第 8 种时，**没有任何机制提醒这里要加一条**——`AGENTS.md` 禁令 5b（mark 必须有 markdown 载体）管的是序列化器，管不到这条预览管线。
> **建议**：把「哪些是 solo 私有语法」做成一份**清单常量**，让 `parser.ts` 插件装配、`markdown-to-html.ts`、`FEATURE-MATRIX` §4 三处都从它派生（或至少加一条测试断言「私有语法清单 ⟷ 预览管线处理清单」）。

## 4. 「本地能跑 ≠ 别人能编译」——§一 #32 那一次病，同一批代码里长出两个新藏身处

> 【P2】7 个 `@tiptap/*` 子包被直接 `import`，但 `package.json` 一个都没声明（幽灵依赖）
> **证据**（我把 `package.json:8-44` 的 dependencies 全文打印核对过）：**未声明但被生产代码直接 import 的有**：
> - `@tiptap/core` —— `extensions/callout.ts:7`、`footnote.ts:1`、`frontmatter.ts:1`、`list-fold.ts:1`、`paragraph-focus.ts:1`、`search-highlight.ts:1`、`code-block.ts:12`、`markdown/__tests__/test-utils.ts:3` 等 **≥13 处**；
> - `@tiptap/extension-bold` / `-italic` / `-strike` / `-code` —— `extensions/markdown-input.ts:29/33/34/35`（拿的是 `inputRegex`，即**为了和内置输入规则保持同步而直连内部导出**）；
> - `@tiptap/extension-heading` —— `extensions/semantic-heading.ts:15`；
> - `@tiptap/extension-bullet-list` / `-ordered-list` —— `editor-extensions.ts:3/4`。
> 声明了的只有 `-code-block/-highlight/-image/-link/-placeholder/-table*/-task-*/pm/starter-kit/suggestion/vue-3`。上面这些能装到 `node_modules` 里（我查了 `@tiptap/core = 3.31.3` 确实在），**靠的是 `@tiptap/starter-kit` 的传递依赖 + bun 的扁平提升**。
> **影响**：`§一 #32` 的教训原文是「本地『能跑』≠ clean 态能编译」。这里是**同型的前端版**：一旦①换包管理器或改用 isolated/pnpm 布局，或②`starter-kit` 在某个小版本调整它的成员依赖集（**这个项目的 §一 #31 就是「StarterKit 默认成员没显式关掉」造成的**——它对 starter-kit 的内部组成已经有过一次意外），`import '@tiptap/core'` 立刻 `Cannot find module`。失败模式是 **build 期响亮报错**（不是静默数据损坏），所以定 P2 而非 P1；但它同样是「CI 全绿、换环境才炸」。
> **建议**：把这 7 个包**显式写进 `dependencies`**。⚠️ 这属于**装/改依赖**，按 `AGENTS.md` §0 与禁令 15 必须先获你同意，我没有动，只登记。

> 【P2·潜伏】macOS 专属代码臂引用了一个没被 re-export 的符号 ⇒ 哪天首次 mac 构建必编译失败
> **证据**（四处我自己读原文）：① `commands/window.rs:173` 定义 `#[cfg(target_os = "macos")] pub fn apply_macos_window_background(...)`，`:188` 有非 mac 孪生体 ⇒ **函数在所有平台都定义了**；② `commands/mod.rs:16-18` 的 `pub use window::{attach_window_events, report_window_events, request_app_quit, set_window_background_color}` **不含它**（我把 mod.rs 全文打过）；③ `lib.rs:102` 用**限定路径** `window::apply_macos_window_background(...)` → 能编译（`use commands::*` 把 `window` 模块本身带进来了）；④ **`lib.rs:339-340` 用裸名** `apply_macos_window_background(&main_window, "#ffffff")?` → 只能靠 glob 拿到符号，而 glob 里没有它 ⇒ **E0425**。两处都在 `#[cfg(target_os = "macos")]` 臂内。
> **为什么永远不会被发现**：开发机 win32 ⇒ `cargo check` 不编译该臂；`.github/workflows/test.yml:11` 是 `runs-on: windows-latest` 单机；`.github/workflows/release.yml:14-17` 的 matrix **只有一条 `windows-latest`**。**没有任何一条路径编译过 mac 臂。**
> **影响**：`FEATURE-MATRIX` §8 把 macOS 适配记成「⚠️ 代码在位但无 Mac 环境实测」——**实际比这更弱：mac 上根本编不过**。好消息是产品只发 Windows，所以这是潜伏债；坏消息是它与 `§一 #32` 是同一种病的第二次发作，而那次事故之后项目**只补了「新增 Rust 命令必须三处同步」这一条纪律，没补「cfg 臂也要被编译到」这一条**。
> **建议**（方向，不动手）：`mod.rs` 补一行 re-export；更根本的是给 CI 加一个 `cargo check --target aarch64-apple-darwin`（只需 `--target` + std 层，不必完整打包），一条 job 就够——**cfg 臂的守门成本是「让它被编译到」，不是「让它被测试到」**。

> 【P3】一处「注册表 / 能力 / 依赖」三方齐全、只缺调用者的死重量
> **证据**：`package.json:23` 声明 `@tauri-apps/plugin-clipboard-manager`；`Cargo.toml:22` 有 `tauri-plugin-clipboard-manager`；`lib.rs:260` 注册了 `.plugin(tauri_plugin_clipboard_manager::init())`；`capabilities/main-window.json:34` 与 `secondary-window.json:34` 各给了 `clipboard-manager:allow-write-html`。**但前端全仓 `src/` 对它的 import 是 0 处**（我 grep 过连下划线形态，只命中 Rust 注册点与 `clipboard.rs:10` 的一句注释）。真实读剪贴板走的是 Rust `arboard`（`commands/clipboard.rs`）。
> **影响**：一个装进二进制、开了权限、却无人调用的插件。与产品精神「安装包小、内存占用小」直接相抵（现在安装包 14.8MB / 内存实测 42MB，是达标的好数据，**多一个没人用的插件就是白交的税**）；权限侧也多开了一道 `allow-write-html`。
> **建议**：确认无未来用途后，四处一起摘（npm 依赖 / Cargo 依赖 / `lib.rs:260` 注册 / 两条 capability）。删依赖属高危动作，**先问你**。

> **实测输出**：折叠集合 `{1}` → `∅` ⇒ **「甲」移动后不再是折叠态**，视觉上就是它自己展开了。
> **⚠️ 我差点误杀这条**：第一版探针我把光标落在 `foldedPos + 4`，实际落进了**嵌套子列表**，`moveListItem` 取「最内层列表项」⇒ 动的是子项、`mapResult(1).deleted` 得 `false`，看起来「没事」。改成 `+2`（落在「甲」自己的段落）才现形。**结论：这不是推理，是实测；但也说明这条很容易被子项级测试掩盖。**
> **影响**：谁会遇到——把「折叠 + Alt 换位」当日常用法的长大纲写作者（正是这批新功能的目标用户）。后果——折叠视图被打乱，用户得重新点一遍；**不丢内容、不丢格式**（纯视图态），所以是 P2 不是 P1。**为什么现在没人报**：`list-fold.spec.ts` 23 例 + `list-move.spec.ts` 15 例，**交叉零例**；两个功能出自同一批提交（`0e534ba` 系列与 `5c4001f`），互不感知。
> **建议**（方向，不动手）：换位事务应让折叠集合跟随——最小改动是 `mapFolded` 遇到「本事务是整项搬移」时改用**节点身份**而非位置（`list-move` 已有 `itemNode` 引用），或让 `list-move` 在 dispatch 后把折叠集合按 old→new pos 显式重映射。**同时补一条交叉用例**（折叠父项 → 换位 → 断折叠仍在），这条用例本身就能当防复发的锁。
