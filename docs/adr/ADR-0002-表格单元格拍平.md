# ADR-0002 表格单元格一律拍平为行内文本

- Status: Accepted
- Date: 2026-10-11（决策一 + 决策二 B1，简乐拍板）

## Context

GFM 表格单元格**只能表达行内文本**，但 solo 的 schema 收得下块级结构（heading / bulletList / codeBlock / callout / mathBlock 等），且斜杠菜单与命令面板实测**全部能造出来**。结果：块级语法被写进单行容器，落盘后每存一次变一次（不收敛），属于「能渲染 ≠ 能存住」。

另有一层：`serializer.ts::atBlockStart()` 把单元格首格误判成块起点，导致打开第三方手写表格再保存就被加反斜杠（格首 `-` `>` `1.` `#` 全中招）。

## Decision

1. `cellToText` 一律走 `renderFlattenedInline()` 拍平为行内文本，直接子块之间以 `<br>` 分隔；`callout.title` 这类存在 attrs 里的文字显式补写
2. `atBlockStart()` 在 `inTableCell` 下**恒为 false** —— 单元格是行内语境，格首不是块起点

块级语法一个都不进单元格。

## Consequences

- 正面：8 种块型一次收敛；打开第三方表格保存不再被静默改写
- 负面（部分修复，未收口）：
  - 格内块结构降级为文本 + 字面 `<br>`，重开后屏幕上显示 `<br>` 字样（§二 #63，分隔符取舍未拍板）
  - **拍平只到格的直接子块一层**：容器内部兄弟块仍首尾黏连（`买奶`+`写码` → `买奶写码`），字符没少但**词边界没了**
  - `checked`（勾没勾）、`start`（编号从几）这类存在 attrs 里的用户输入整体消失
- 未做：收紧 schema 禁止造出来（B2）。入口四个命令实测全开，但前置条件已变成「格内点了斜杠菜单没反应时，怎么让用户知道」，不是技术问题
