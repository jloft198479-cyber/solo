## 1. 一句话总账

**这个代码库的「底线」依然是健康的（保真四网真的在抓 bug，旧结论 6 项验收 5 项成立）；但它现在最大的问题不是烂代码，而是「新长出来的能力没有入口、没有文档、没有登记」——以及一处可能让「替换」快捷键彻底失效的菜单撞键。**

## 3. 定位一致性 + 减法正确性

**判据 = `docs/solo产品精神.md`**（极简/极速/优雅 + 灵活/高效/可拓展；明言「不希望它承担太多功能」「利用碎片化时间快速表达想法」「不需要像知识库那样有侧边栏」）。

| 检查 | 结论 |
|---|---|
| 有没有功能越界进「协作/知识库/长文档处理器」 | **没有硬越界**。互链全家桶是知识库特征，但它是「单文件之间的手拉手」，没有库、没有索引、没有侧栏——**在准绳内**，且已拍板。 |
| **正在发生的方向漂移**（值得你亲自看一眼） | 列表区正在被「幕布化」：折叠（`list-fold.ts`）、同层上下移（`list-move.ts`）、树状导轨（`editor.css:435-438`）、折叠态跨文档记忆。这四件合起来 = **幕布的核心卖点**，而 Typora 恰恰**没有**列表折叠（09-14 §6.2 #11 记的是「Typora 同样没有折叠，对齐不做」）。**我不判断这是不是坏事**——但它意味着对标基准正在从 Typora 往幕布滑。如果这是你要的，就该把 §5 的主基准写清「写作器以 Typora 为准、大纲区以幕布为准」；如果不是，就该收。**这条要你说，我不替你定。** |
| 已删功能的替代路径够不够用（减法正确性） | **导出系统**：替代 = 状态栏按钮（整篇：`text/plain`=Markdown 源码 + `text/html`=渲染富文本，`StatusbarQuickActions.vue:35-40`）+ 命令面板 `edit.copyAsMarkdown`（选区源码）。贴公众号/文档平台这条路**够用**。**真正的落差只剩「打印/PDF」**（见 §4 决策单 #4），且它卡在一个**跨了 4 轮审查仍未实测**的问题上：按一次 `Ctrl+P` 就知道了，但至今没人按过（`KNOWN-ISSUES §二 #16`，登记于 09-14）。**文件树/工作区**：替代 = 双击 `.md` + 拖入 + 右键新建（文件关联）+ 命令面板——**符合「随手开一篇」的定位，够用**。**源码模式**：`copyAsMarkdown` 只能把源码**搬到别处看**，不能**就地看**。这是真落差，但属已拍板不做（§5 红线 2，不翻案）。 |

## 4. 入口可发现性：四源一致性实测（本批硬料集中区）

> 四源 = **原生菜单 / 命令面板 / 快捷键 / 标题栏-状态栏-右键-Slash**。真理源是 `src/commands/registry.ts`（43 条命令，我逐条读过）。

> ### 【P1】「替换」的 Ctrl+H 与一个**点了没反应的死菜单项**撞键，Windows 上可能整个失效
> **证据**：
> - `src-tauri/src/menu.rs:61` —— 「隐藏 solo」硬编码 `Some("CmdOrCtrl+H")`；`menu.rs:173` 把 `app.hide / app.hideOthers / app.showAll` 的事件**直接吞掉、从不 emit**（这三个是 macOS 概念，Windows 上是死项）。
> - `src/commands/registry.ts:387` —— `edit.replace` 的 `defaultShortcut: 'Mod-h'`，Windows 即 **Ctrl+H**。
> - `menu.rs:219-235` `update_shortcuts_in_items` 只对「map 里存在的 id」**设置**加速键，**从不清除** ⇒ 死项的 Ctrl+H 永远留在系统加速键表里。
> - 本项目自己的排查文档 **已承认这是一层**：`docs/debugging.md:99-101`「IME → **原生菜单加速器(Tauri)** → WebView2 → JS keydown；快捷键『没反应』先怀疑前两层」。
> **我没能拿到的那一环**：真机实测。`src-tauri/target/release/solo.exe`（2026-09-24 编译，`menu.rs` 自 2026-08-21 起一字未改，所以在这件事上等同于当前代码）在我的托管 shell 里**起了进程但窗口枚举不到**（`tauri.conf.json` 里 `visible:false`，要等前端 `startup_ready` 才显示），所以下不了「确实失效」的定论。**这条必须由你或 owner 花 10 秒实测**：打开 solo → 在正文按 **Ctrl+H** → 看「查找替换」面板弹不弹。
> **影响**：若弹 = 本条作废（降级为「不整洁」）；**若不弹 = 功能性缺陷 P1**，用户按设置页写的 Ctrl+H 完全无反应，且这是「替换」——想找替无的用户最不想碰到这个。
> **建议**（无论实测结果如何都成立）：把这三个 macOS 专属菜单项用 `#[cfg(target_os = "macos")]` 圈起来，Windows/Linux 根本不建；顺带删掉它们的硬编码加速键。一处改动，同时解决撞键 + 死菜单项 + macOS 概念泄漏。

> 【P2】原生菜单的默认加速键与 registry 不一致，靠启动后同步「救回来」，首屏窗口期是错的
> **证据**：`menu.rs:32` 查找写死 `CmdOrCtrl+G`（registry 是 `Mod-f`，`registry.ts:377`）、`:33` 替换 `CmdOrCtrl+Shift+G`（registry `Mod-h`）、`:36` 全屏 `CmdOrCtrl+Shift+F`（registry Windows `F11`，`registry.ts:421`）。`lib.rs:330` 建菜单时传**空表** ⇒ 首屏就是这三个错值；`App.vue:261` 才 `await Promise.all([settingsStore.init(), syncMenuShortcuts()])` 覆盖成 registry 值。**依赖 IPC 成功**，IPC 失败或同步前用户就点开菜单 → 看到旧键位。
> **影响**：文档漂移表里的「查找不是 Ctrl+G 而是 Ctrl+F」（FEATURE-MATRIX 附录 B-2）**其实没清根**——wiki 改了，Rust 菜单里的 `CmdOrCtrl+G` 一字未动，只是被启动后的同步盖住了。这正是方案 §4.1 要抓的「四源不一致」。
> **建议**：`menu.rs` 里那三个 `Some("...")` 默认值改成与 registry 同源（或直接 `None`，让同步来填），别留两套事实。

> 【P2】快捷键注册表与原生菜单之间**没有任何一致性测试**
> **证据**：`src/commands/__tests__/registry.spec.ts`（8 例）只测 TS 侧派生函数，无一条把 `menu.rs` 的写死 id / 写死加速键与 `COMMANDS` 对齐。`useMenuShortcutsSync.spec.ts` 只有 2 例，测的是「变更时调用了 IPC」，不测值对不对。
> **影响**：上面两条 P1/P2 都属于「改一处漏一处」，而这类漂移正是这个项目历史上反复犯的（AGENTS.md 禁令里已有先例条目）。**没有护栏，就会再漂第三次。**
> **建议**：把「menu.rs 用到的 command id 必须存在于 registry」做成一条测试（menu.rs 可用 `include_str!` 读源码 + 正则抽 id，成本很低）。

> 【P2】列表折叠（幕布式大纲的招牌能力）**有实现、零键盘入口、功能表与用户文档均未登记**
> **勘误（批 3 复核时改）**：本条原写「零现行文档」，**过头了**——`docs/CHANGELOG.md` 的 `[1.2.58]` 段（`:25-29`）**确实登记了**折叠能力与跨文档记忆。准确的缺口是：**功能状态真理源 FEATURE-MATRIX 没登记**（`:253` 反把「折叠」记为未实现）+ **wiki 用户文档零提及** + ARCHITECTURE 零提及。发布说明有、给用户看的文档没有，仍然等于用户不知道。
> **证据**：`list-fold.ts:161-174` 折叠**只能靠点那个箭头**；箭头本身 `editor.css:456` 默认 `opacity:0`，**悬停那一行才浮现**（折叠态常显 `:466-469`）。registry 里**没有任何 fold 命令**（`:263-290` 只有 moveUp/Down），所以：**无快捷键、无右键菜单项、无 Slash 项、不进命令面板、没有「全部折叠/全部展开」**。文档侧：`docs/FEATURE-MATRIX.md:253` 至今把「折叠」记为**未实现**；`docs/INDEX.md:72-73` 只挂了两个 `status: proposal`；`wiki/` 用户文档**零提及**。
> **影响**：这是最近三个版本做出的一整块新能力，**普通用户很可能一辈子都不会发现它**。对一个「极简」产品，鼠标 hover 才出现的箭头是唯一入口可以是刻意的，但**「没有全部折叠/展开」不可能是刻意的**——折叠三层大纲后想一键展开，只能一项一项点。
> **建议**：① 补 `list.foldAll` / `list.unfoldAll`（或一条 toggle）进 registry，命令面板 + 大纲区右键菜单给入口；② FEATURE-MATRIX 补一行登记现状；③ wiki 用户文档补一段。①是功能，②③是账。

> 【P2】三处 tooltip 硬编码键位，用户自定义之后会当面撒谎
> **证据**：`src/App.vue:405` `'点击保存 (Ctrl+S)'`、`App.vue:419` `title="设置 (Ctrl+,)"`、`src/components/Editor/OutlinePanel.vue:157` `title="收起大纲 (Ctrl+/)"`。这三条命令（`file.save` / `settings.open` / `view.toggleOutline`）**都没有 `fixedShortcut`**（`registry.ts:71-89/447-455/426-433`），**用户可以在设置页改**。同一项目里已有正确写法：`CustomTitlebar.vue:117-122` 的大纲 tooltip 是从 registry 派生的（注释还专门写了「不再手抄键位」）。
> **影响**：改了键位的人看到按钮上还写着 Ctrl+S —— 这是 2026-09-14「大纲/命令面板收编进注册表」（`4cade7a`）那一刀的**同类漏网**。
> **建议**：三处照 `CustomTitlebar.vue` 的写法改成派生，机械改动。

> 【P2】`Escape` 和 `Mod+Backspace` 两组键位游离在注册表外
> **证据**：`useAppDomEvents.ts:75-92` 全局 Esc 四态级联（全屏预览 → 图片视图 → 焦点引导 → 退焦点模式）直接写在 handler 里；`math-block.ts:203`、`mermaid-block.ts:474` 的 `Mod+Backspace`（整体删块）也不在 registry。registry 里**没有** `app.escape` / `editor.deleteBlock` 之类条目。
> **影响**：① 违反 AGENTS.md「快捷键一律登记 registry.ts（键位真理源）」；② 设置页的「可自定义快捷键」列**看不见它们**，用户既不知道有这些键、也改不了；③ `wiki/快捷键速查.md` 声称列「全部默认快捷键」，实际必然缺。
> **建议**：`Mod+Backspace` 该进 registry（它是**功能键**，不是导航键）。`Escape` 可以论证「不该可改」，但那就要像 `fixedShortcut` 那样**显式声明**（入口键固定 = 标 `fixedShortcut: true` 仍参与冲突检测），而不是干脆不登记。

> 【P2】「插入链接」「清除格式」只能靠鼠标浮动菜单，没有命令 / 快捷键 / 面板入口
> **证据**：`src/components/Editor/tiptap/editor-commands.ts:9-51` 浮动菜单的动作串里有 `link` / `unlink` / `clearFormat`，而 `registry.ts` 中**不存在** `editor.link`、`editor.clearFormat`（全文 43 条我逐条看过，只有 bold/italic/strike/highlight/dim/code）。浮动菜单只在**有选区时**出现。
> **影响**：插链接是写作高频刚需。现在的路径是「先选中文字 → 等浮动条出现 → 点链接图标 → 在输入框里贴 URL」。**没有键盘路径**，也没有「清除格式」的任何其他入口。Typora / Obsidian 都给 `Ctrl+K` 插链接——顺带一提，solo 的 `Ctrl+K` 被命令面板占用了（`registry.ts:435-445`，且标了 `fixedShortcut`），这不算错，但意味着**必须给链接另配一键**。
> **建议**：`editor.link` / `editor.clearFormat` 登记进 registry + 进命令面板。成本很低（dispatcher 已有 `scope: editor` 转发通道）。

> 【P2】状态栏「复制 Markdown」与命令面板「复制为 Markdown」**同名不同事**，且失败时静默
> **证据**：`StatusbarQuickActions.vue:30-48` 按钮复制的是**整篇**（`editorRef.getContent()` 全文）源码 + 渲染 HTML 双槽，`title="复制 Markdown"`（`:72`）；`registry.ts:392-404` 命令面板那条描述写的是「把**选区**以 Markdown 源码写入剪贴板」。另外按钮的 `catch {}`（`:45-47`）在剪贴板 API 不可用时**一声不吭**，按钮也不变样。
> **影响**：用户以为「点了就是复制我选的东西」，实际拿到整篇；复制失败时提示「已复制」不会出现，但也没有任何错误告知——**用户会带着旧剪贴板内容去粘贴**。这一条不是代码错，是**语义没对齐**（FEATURE-MATRIX 附录 B-4 早就记了「口径不一」，至今没定谁说了算）。
> **建议**：两个入口二选一命名（比如状态栏叫「复制全文」）；`catch` 分支至少把按钮标成失败态 1.5s。

> 【P3】新命令 Alt+↑ 在界面上显示成「Alt+ARROWUP」
> **证据**：`registry.ts:549-563` `formatKeyForDisplay` 对最后一段做 `.toUpperCase()`，`'Alt-ArrowUp'` → `'Alt+ARROWUP'`。消费方是 `CommandPalette.vue:75-78` 和 `ShortcutSettingsPanel.vue:82`，**两处都是用户会直接看的**。
> **影响**：命令面板里两条新命令的键位显示丑陋且不规范（应为 `Alt+↑`）。
> **建议**：给方向键加显示映射（ArrowUp→↑ / ArrowDown→↓ / ArrowLeft→← / ArrowRight→→），且只对标点/字母做 upper。

> 【P3】附录 A 用「grep 零命中」当判据的那几条，判据本身已经过期
> **证据**：`FEATURE-MATRIX.md:251` 断「阅读位置记忆：`scrollPosition` / `restoreScroll` 零命中」。我在 HEAD 实测 `restoreScroll` **命中 2 处**（`ime-anchor.ts:143` 定义、`:202` 调用）——是 IME 重锚时的滚动还原，**与阅读位置记忆无关，结论仍然成立**，但表里写的证据已经假了。
> **影响**：这类「以零命中为判据」的条目会随代码生长自动失真，下一个读表的人要么误判「已被实现」，要么花时间重测。
> **建议**：判据改成「命中了也不算，看有没有**用户可见的**持久化读写点」，或直接写「`grep` 结果见 `docs/xxx` 复核记录（日期）」。

### 4.1 正面清单（不只说问题）

- **命令面板这一源是真的干净**：`CommandPalette.vue:23` 完全由 registry 驱动，43 条命令**全部至少被面板列举一次**，「定义了但完全不可达」的命令 = **0 条**。这在同规模项目里少见。
- **`list.moveItemUp/Down` 的 scope 选择是有脑子的**：`registry.ts:266-276` 解释了为什么必须 `app`（PM 没有整项移动内置命令，标 editor 会彻底按不动），也解释了为什么刻意不给 `menuSection`（加速键别名表没有方向键，给了会注册失败）。`useCommandDispatcher.ts:86-93` 还专门加了「编辑器必须真持有焦点」的门，注释写明是为了防「在大纲里按 Alt+↑ 看不见地挪动正文」——**这个判断是对的，我之前怀疑它是不是缺陷，读完代码确认是设计**。
- **`fixedShortcut` 的设计口径正确**：入口键固定但**仍参与冲突检测**（`registry.ts:504-520`），防住了「用户把别的命令设成 Ctrl+K 把入口悄悄抢走」。
- **定时器纪律整体到位**：`StatusbarQuickActions.vue:50-52`、`CustomTitlebar.vue:162-164`、`ime-anchor.ts:237-238`、`list-fold.ts:311-314` 都在 unmount/destroy 里清。（`markdown-input.ts:262` 那个 50ms 未登记句柄，但回调内有 `view.isDestroyed` + `isFrozen` 双重守卫，**不构成风险，不算问题**。）
