## 2. 🔴 A：待办列表 toggle ⇒ 产出 `- [ ] - 乙` 畸形

**实测**：`- [ ] 甲\n  - 乙\n- 丙` → 命令面板「任务列表」第二次按 ⇒
`- [ ] 甲␤␤- [ ] - 乙␤- 丙`

**严重度**：高。这**正是本次要根除的畸形，原样复现**，且用户天天按这个键。

**根因**（已回源码定位）：`list-demote.ts:78` 判「同类型」用的是
`child.type === parentList.type`（**列表节点的 type**）。
但解析后待办列表的真实结构是（实测 dump）：

```
bulletList                      ← 父容器是 bulletList，不是 taskList
  taskItem    paragraph "甲"
  listItem    paragraph "丙"   ← 同容器里 taskItem / listItem 混编
```

子列表也是 `bulletList` ⇒ 判成「同类型」⇒ 展开成 `listItem` 并入父列表
⇒ PM 拿 `listItem` 补齐推演成 `taskItem` ⇒ `- [ ] - 乙`。

**修法**：判据下沉一层 —— 比「**子列表里项的类型**」与「**父列表里项的类型**」，
一致才并入；不一致按异类整块提升。

```ts
// 现在（错）：比列表节点
if (child.type === parentList.type)
// 应比：子列表首项类型 vs 父列表实际项类型
```

⚠️ 待拍板：若父容器混编（`bulletList` 里同时有 `taskItem` 与 `listItem`），
`listItem` 到底能不能并进去？建议**一律走异类整块提升**（更保守、可逆），
而不是猜 PM 的补齐推演。

## 3. 🔴 B：段落带 2 空格缩进残留 ⇒「退出列表」是假的

**实测**：

| 输入 | 目标 | 输出 |
|---|---|---|
| `- A\n  - B\n    - C\n- E` | B | `- A␤␤␣␣B␣- C␤- E` |
| `- B\n  - D\n  - C\n  - E\n- A` | C | `- B␤␣- D␤␤␣␣C␣- E␤- A` |

**严重度**：高。**直接违反契约公理 1「缩进是唯一的坐标」**。

**根因**：`replaceItemWithItsBlocks`（`list-demote.ts:184`）用 `replaceWith` 在
**父列表原位**放段落块。而 schema `ListItem content: 'block+'` **允许段落留在列表项内**
⇒ 末尾 `setBlockType` 把它「变成段落」了，**但它还在 `listItem` 里面，缩进没归零**。

实测 DOM 佐证（`deep` 场景 AFTER）：

```
bulletList
  listItem
    paragraph "A"
    paragraph "B"      ← B 是段落，但仍被 listItem 包着 ⇒ 落盘带 2 空格
    bulletList > listItem "C"
```

⇒ **它退出的是「项」，没退出「列表」。** 契约 §2 动词表那句「这一行退出列表」在非顶层项上不成立。

**修法方向**（待拍板，我倾向 A）：

- **A（推荐）**：让块**真正脱离** `listItem` —— 即在**父列表之外**找落点，
  而不是父列表原位替换。代价：非顶层项要跨层提升，需处理「祖先链上还有兄弟」的情况，
  复杂度明显上升。
- **B（保守）**：非顶层项**不接管**，交回原命令，并把契约 §2 那句话改成
  「顶层项退出列表；非顶层项仅去 mark」（诚实降级，但功能弱）。
- **C（最低成本）**：接受残留，但**在契约 §6 明确写出来**，
  并把 §2 动词表改成「这一行不再属于列表项」而非「退出列表」。

⚠️ 无论选哪个，都必须**先跑一遍探针确认 A/B 各自的次生问题**（尤其 A：
祖先链上有兄弟时，子列表上提会不会改变别人的层级 —— 那就又违反公理 3 了）。
