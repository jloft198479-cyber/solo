## 1. 问题与背景

### 1.1 两个具体症状

| # | 症状 | 定位 | 危害 |
|---|---|---|---|
| 1 | 输入 `:\`（如 `G:\skills-pi\volc-web-search`）弹出「没有匹配的表情」 | `:` 是 Emoji 菜单触发符；URL 上下文守卫词表只有 `http/https/ftp/file/mailto/tel`，**漏 Windows 盘符**；叠加 emoji 的 `allowedPrefixes: null` → `:` 后整条路径成为搜索词 | 低（`useFloatingListMenu` 对空列表 `return false`，回车不误插，仅遮挡视线） |
| 2 | 复制出去夹带转义噪音（`a\*b`、`\#井号`、`\[重点\]`）；路径反斜杠翻倍（`G:\a` → `G:\\a`） | 算法侧：`escapeInline` 的 `text.replace(/\\/g, '\\\\')` 无条件全转义；架构侧：`clipboardTextSerializer` 无条件把 `text/plain` 覆盖成 Markdown 源码 | 高（内容变形、粘到任何纯文本目标都脏） |

### 1.2 架构侧根因（git 证据）

`git log -S` 追溯 `text/plain` 的产出策略，**四次提交全是「加转义」，零次「减」**：

| 提交 | 日期 | 动作 |
|---|---|---|
| `ec3a69f` | 06-27 | 初次加剪贴板复制（7 行） |
| `ffa2d2a` | 06-28 | 加上「反斜杠全转义」那一行（commit message **未提**，混在列表序列化提交里） |
| `bb57029` | 07-21 | 正式引入 `clipboardTextSerializer` 覆盖 `text/plain`，理由写明「出站 callout / 公式 / mermaid / 互链 / 脚注**标记全丢**」 |
| `6a28edd` | 09-06 | 剪贴板出站转义**补** `_~[]<>`（转义集再扩一次） |

**这是一条单向棘轮**：每次都朝「别丢内容」使劲，没人回头问「是不是转多了」。根因四条：

1. **底层是自建的**——`package.json` 无 `prosemirror-markdown`（自建序列化器以支持扩展），失去上游「最佳实践默认值」兜底。
2. **优先级倒置**——先撞「内容**丢失**」（严重），后撞「内容**脏**」（轻微），补丁全朝前者。
3. **单向棘轮**（上表）。
4. **测试视角缺一角**——roundtrip 只覆盖 solo→solo 幂等，**无一条覆盖 solo→外部纯文本**，噪音在测试里不可见。

### 1.3 业界对标（调研结论）

| 参照 | 做法 | 来源 |
|---|---|---|
| Typora | 复制**同时**塞 HTML + RTF + 纯文本；**默认纯文本 = 渲染后的文字**（`A **boy**` → `A boy`）；Markdown 源码只在 `Ctrl+Shift+C` 或显式设置项时进纯文本槽 | [Typora 官方文档](https://support.typoraio.cn/Copy-and-Paste/) |
| prosemirror-markdown | 行内固定只转 7 个（`` ` * \ ~ [ ] _ ``），行首才额外转 3 组；`escapeExtraCharacters` 交给调用方按需补；code 声明 `escape:false` | [源码](https://raw.githubusercontent.com/ProseMirror/prosemirror-markdown/master/src/to_markdown.ts) |
| tiptap-markdown | `transformPastedText` / `transformCopiedText` **默认均为 false**（默认不做剪贴板 md 转换） | [行为扩展分析](https://deepwiki.com/aguingand/tiptap-markdown/3.3-behavior-extensions) |

**结论：solo 的做法与所有优秀编辑器相反** —— 把「为 Markdown 目标做的优化」强加给了所有目标。

## 2. 决策过程

| 方案 | 内容 | 结论 |
|---|---|---|
| A | 照 Typora 范式重做：纯文本槽放渲染后文字 + 专有语法回落 + 显式源码入口（+可选设置项） | ✅ **采用**（去掉设置项） |
| B | 把转义集砍到业界最小集（对齐 prosemirror-markdown 的 7+3） | ❌ **实测否证后放弃** |
| C | 纯文本槽彻底不转义 | ❌ 未采纳（粘回 Markdown 环境丢语义） |

**B 被否证的证据（关键，避免评审重复走这条路）**：用仓库 79 份真实 `.md` 回放，按「集合」整体去掉转义后重解析比对：

- 去掉 `] ( ) = < { }` 整组 → 命中 43 份，**14 份语义漂移**；
- 三个**真实且正当**的漂移机制：① 用户会写「长得像 Markdown 的示例文本」（`docs/archive/catpaw-…/step1-…md` 里的字面量 `!\[\]\(data:image/svg+xml;…\)` 去转义后**变真图片**）；② 表格单元格里的 `|`；③ **代码块里作者手写的 `\|`**（非序列化器产物，动它就是改内容）。
- **决定性约束**：solo 语法是 CommonMark 的**超集**（数学 `$`、上下标 `^`/`~`、互链 `[[`、callout、frontmatter），实测这些**在所有上下文都必须转义** ⇒ **照抄参考实现的 7 字符集 = 反向破坏自己的扩展**。

**因此把改动面收缩到剪贴板这一层，完全不碰序列化器。**

## 5. 回滚方案

```bash
# ① 只回滚范式改造，保留算法侧修复（推荐，粒度最小）
git revert --no-edit 6f1119a

# ② 回到改造前基线（同时丢掉算法侧修复）
git reset --hard 79cb44c
#   或保留历史地反向提交：
git revert --no-edit 6f1119a 5951b44

# ③ 只回滚文档
git checkout 6f1119a -- <文件>
```

- 三个提交互相独立，`git revert` 任一都不会牵动另外的代码路径。
- **无数据迁移**：无配置项、无版本号、无 schema 变更；唯一「行为变化」是磁盘上已存成 `\\` 的老文件重开保存会被归一化成 `\`（Markdown 语义等价，已写入 CHANGELOG）。
- 回滚后需重跑：`vitest run` + `vue-tsc --noEmit` + `vite build`（三项均无外部依赖）。

## 6. 已知取舍 / 残余风险 / 未做事项

### 6.1 需要评审重点判断的取舍

| # | 事项 | 现状与理由 | 若评审有异议，改法成本 |
|---|---|---|---|
| R1 | **含 frontmatter / callout / 图片的选区整体回落源码** | 这三者都是「纯文本无法表达其语义」的节点（frontmatter 的 `---` 界定、callout 的 `[!NOTE]` 类型、图片的路径）。代价：**整篇复制带 frontmatter 的笔记时，纯文本槽给的是 Markdown 源码**（HTML 槽不受影响，粘到微信/Word 仍走 HTML） | 把节点名从「回落集」移入白名单即可（1 行/个），但会牺牲对外部 Markdown 编辑器的保真 |

#### 6.1.1 评审反馈：链接（mark）不触发回落 —— 已确认，**不构成缺口**（2026-09-13 裁定）

**反馈**：默认复制含超链接的文字时，纯文本槽只剩显示文字、网址丢失（`[百度](url)` → `百度`），质疑与「图片等专有节点触发回落」的原则不一致，建议① 把链接纳入回落判据 / ② 文字后补网址 / ③ 仅写文档。

**裁定：机制属实，但只覆盖了链路的一半；不改代码逻辑。**

| 判定 | 依据 |
|---|---|
| 机制确认 | `hasProprietaryNode()`（`serializer.ts:789`）只遍历**节点**、不遍历 marks，而 `link` 是 mark（`@tiptap/extension-link`）⇒ 不触发回落 |
| **只影响纯文本目标** | `text/html` 槽由 Tiptap `Link.renderHTML` 输出 `<a href>`（`node_modules/@tiptap/extension-link/dist/index.js:364/376`）⇒ 粘到 Word / 微信 / 公众号 / Gmail 等富文本目标，网址完整且可点击 |
| 与业界一致 | `text/plain` 的定义即「字符、无标记」；浏览器选中带链接的文字粘到代码编辑器同样是**超链接消失、只剩文字** |
| 与图片**不属同类** | 图片去标记后只剩 alt（常为文件名或空，无意义），纯文本里**无合格替身**；链接去标记即人写的显示文字，**有合格替身** |

**处理**：补 2 条回归测试锁住当前行为（`clipboard-serializer.spec.ts`：默认复制链接给显示文字 / 链接触发回落与否只取决于选区有无专有节点），并在 `ARCHITECTURE.md §11.8` 写明该分界与「要网址的两个出口」。

```ts
import { describe, it } from 'vitest';
import fs from 'node:fs';
import path from 'node:path';
import { Slice } from '@tiptap/pm/model';
import { parseMarkdown } from '../src/components/Editor/tiptap/markdown/parser';
import * as serializer from '../src/components/Editor/tiptap/markdown/serializer';
import { createTestSchema } from '../src/components/Editor/tiptap/markdown/__tests__/test-utils';

const FIXTURES = 'src/components/Editor/tiptap/markdown/__tests__/fixtures';
const OUT = process.env.PROBE_OUT ?? '.sandbox-copy-probe/snapshot.json';

/** 新函数在「改动前」的代码里不存在——兼容两侧，便于 stash 前后各跑一次 */
const clipboardText = (serializer as Record<string, unknown>)['serializeClipboardText'] as
  | ((doc: unknown, slice: Slice) => string)
  | undefined;

function fixtureFiles(): string[] {
  return fs.readdirSync(FIXTURES).filter((f) => f.endsWith('.md')).sort();
}

describe('剪贴板范式改造 —— 取证探针', () => {
  it('A. 落盘序列化快照（整篇 fixture，证明文件保存路径零漂移）', () => {
    const schema = createTestSchema();
    const files = fixtureFiles();
    const snapshot: Record<string, string> = {};
    for (const f of files) {
      const md = fs.readFileSync(path.join(FIXTURES, f), 'utf8');
      snapshot[f] = serializer.serializeMarkdown(parseMarkdown(schema, md));
    }
    fs.writeFileSync(OUT, JSON.stringify(snapshot, null, 2), 'utf8');
    console.log(`[A] 已导出 ${files.length} 个 fixture 的整篇落盘序列化结果 → ${OUT}`);
  });

  it('B. 剪贴板 text/plain 前后对照（旧=Markdown 源码 / 新=干净文字）', () => {
    const schema = createTestSchema();
    const print = (name: string, md: string) => {
      const doc = parseMarkdown(schema, md);
      const slice = new Slice(doc.content, 0, 0);
      const oldOut = serializer.serializeClipboardSlice(doc, slice).replace(/\n$/, '');
      const newOut = clipboardText ? clipboardText(doc, slice) : '（改动前：函数不存在）';
      console.log(`[B] ${name}\n    旧: ${JSON.stringify(oldOut)}\n    新: ${JSON.stringify(newOut)}`);
    };

    console.log('── 合成用例 ──');
    print('标题', '## 标题');
    print('加粗斜体', '**粗** 与 *斜*');
    print('列表', '- 苹果\n- 香蕉');
    print('引用', '> 引用一句');
    print('分隔线', '第一段\n\n---\n\n第二段');
    print('表格', '| A | B |\n| --- | --- |\n| 1 | 2 |');
    print('行内公式', '行内 $E=mc^2$ 在此');
    print('互链', '参考 [[我的页面]]');
    print('callout', '> [!NOTE]\n> 提示');
    print('mermaid', '```mermaid\nflowchart TD\n```');
    print('图片', '![图](a.png)');
    print('frontmatter', '---\ntitle: x\n---\n\n正文');
    print('脚注', '文本[^1]\n\n[^1]: 脚注');

    console.log('── 真实 fixture 全量 ──');
    for (const f of fixtureFiles()) {
      const md = fs.readFileSync(path.join(FIXTURES, f), 'utf8');
      const doc = parseMarkdown(schema, md);
      const slice = new Slice(doc.content, 0, 0);
      const oldOut = serializer.serializeClipboardSlice(doc, slice);
      const newOut = clipboardText ? clipboardText(doc, slice) : '（改动前）';
      console.log(`[B] ${f.padEnd(20)} 旧长 ${oldOut.length} → 新长 ${newOut.length}`);
    }
  });

  it('C. 回落归因：命中哪些「非纯文本安全」节点', () => {
    // 与 serializer.ts 的 PLAIN_TEXT_SAFE_NODES 保持一致（沙盒副本，仅用于归因）
    const SAFE = new Set([

      'bulletList', 'orderedList', 'listItem', 'taskList', 'taskItem',
      'codeBlock', 'horizontalRule', 'table', 'tableRow', 'tableHeader', 'tableCell',
    ]);
    const schema = createTestSchema();
    for (const f of fixtureFiles()) {
      const md = fs.readFileSync(path.join(FIXTURES, f), 'utf8');
      const doc = parseMarkdown(schema, md);
      const hits = new Set<string>();
      doc.descendants((node) => {
        if (!SAFE.has(node.type.name)) hits.add(node.type.name);
      });
      console.log(`[C] ${f.padEnd(20)} ${hits.size ? `触发回落 ← ${[...hits].join(', ')}` : '全文本型 → 干净纯文本'}`);
    }
  });
});
```
