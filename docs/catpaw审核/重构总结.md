## 一、背景

基于 catpaw 出具的 8 份诊断报告（`docs/catpaw审核/step1~step8`），梳理出 31 项问题，分 6 阶段排期执行。执行计划见 `docs/catpaw审核/8.21solo修复和优化执行计划.md`。

问题来源覆盖 8 个维度：

1. 启动与首屏性能（窗口显示时序、编辑器创建时机、首屏依赖）
2. 编辑器输入响应（延迟、卡顿、IME 处理）
3. 大文档渲染（滚动、虚拟化、增量更新）
4. 编辑器整体架构（扩展机制、ProseMirror 管线）
5. 搜索、替换与文本操作
6. 渲染管线与 ProseMirror 增量更新
7. 保存与文件 IO
8. 多窗口与进程架构

### Phase 4：编辑期性能优化（`788775d`~`adf8571`，5 commits）

> 核心目标：让"每次按键的 JS 计算量"不再随文档增大而增大。

| 编号  | 问题                                         | 修复                                      | 效果                                         |
| ----- | -------------------------------------------- | ----------------------------------------- | -------------------------------------------- |
| P4-01 | 代码块全文档 findChildren + 命中门控重渲全部 | 增量高亮——只处理 changed range 内的代码块 | 大文档代码块编辑从全文档遍历降为 O(变化区间) |
| P4-02 | scanHeadings 全树 descendants 每次按键扫两遍 | WeakMap 缓存 + 增量扫描                   | doc 引用不变时 O(1) 命中缓存                 |
| P4-03 | focus mode 装饰每次按键重建全部段落          | 增量聚焦——只处理 changed range 内的块     | 顶层块遍历开销极小                           |
| P4-04 | Suggestion 匹配每次按键全文档扫描            | 守卫——仅光标位置变化时触发                | 打字时 Suggestion 不触发匹配                 |
| P4-05 | serialize 防抖到点立即同步执行，阻塞主线程   | 改 requestIdle 空闲调度                   | 序列化不在按键间隙阻塞主线程                 |

**影响**：小文档无感变化，大文档（20000+ 字）连续打字从"能感觉到卡"到"基本感觉不到卡"。5 个"每次按键都全文档遍历"的热路径全部改为只处理变更区间或 O(1) 操作。

**未解决**：大文档下 PM diff 和浏览器 reflow 仍随节点数线性恶化——需 Phase 6 虚拟化（未做）。

### lowlight 懒加载（`6a9308b`）

> 消除编辑器 chunk 模块求值与窗口显示的竞争。

`createLowlight()` 从模块顶层移到 `getLowlight()` 懒加载函数，通过 `createIncrementalLowlightPlugin` 默认参数惰性求值，延迟到编辑器创建（RAF 后）才触发。17 种 highlight.js 语言的静态 import 保留（纯数据，开销 <5ms），重活 `createLowlight()` 调用本身延迟到首次使用。
