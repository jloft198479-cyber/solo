## 3. 问题 A：强调里包行内代码 ⇒ 加粗**静默丢失**（台账 §一 #35）

### 现象
`**加粗 `代码`**——后文` 打开再保存后输出 `\*\*加粗 `代码`\*\*——后文` —— 加粗消失、凭空多出两个字面星号。**不报错、不提示、不看渲染察觉不到。**

### 根因（反证链，非推断）
1. **先证明分词无罪**：`markdown-it`（裸 commonmark 与 solo 插件集**都**）对该输入产出 `strong_open … strong_close` ⇒ 问题不在分词。
2. **再定位到预处理**：`parser.ts` §1.5 的 ZWNJ 预处理跑在解析**之前**，而行内代码区此时已被 `protectCodeRegions` 换成 `\u0000N\u0000` 占位符。
3. **最后给出语义判据**：占位前该位置本是**反引号**（属 `\p{S}`），而 NUL 既不是 `\p{P}\p{S}` 也不是空白 ⇒ 被「开启方向」正则 `(?<=[^\s\p{P}\p{S}])(\*{1,2})(?=[\p{P}\p{S}])` 当成「普通字」，于是 ZWNJ 被插到**闭合 `**` 之后**，强调配对崩掉。

### 修法
把 `\u0000` 与 `\p{P}\p{S}` **同等对待**：① 两条 flanking 正则的 **4 个字符类**全部纳入 `\u0000`；② 重复两次的内联守卫提为模块常量 `ASCII_SYNTAX_PUNCT` 并同样纳入 `\u0000`。

> **② 不可省（关键）**：只改 ① 会让 `` `a`**b `` 从"不插 ZWNJ"变"插"，**修一个洞引入一个新偏差** —— 已实测验证。

**为什么这是"对位修复"而不是代码堆砌**：它恢复的是**不变量**「占位符等价于代码区边界字符」，不是给某个用例加 `if`。

### 回归锁（`roundtrip.spec.ts` Phase A2，+4 条）
闭合符后接破折号 / 句号 / 逗号 ⇒ 不丢；后接空白 ⇒ 照常加粗；**后紧跟字母 ⇒ 仍不加粗**（CommonMark 语义，防"修过头"）。

### 验证
- `markdown` 目录 **1069 → 全绿**
- 全仓 106 份 md 体检：内联格式受影响 **42 → 19** 份；「`**` 包行内代码」形态 **33 份 / 56 处 → 1 份 / 1 处**（残余那 1 处已查明**属另一类**，见 §6）

## 4. 问题 B：ZWNJ 是「横切不变量」但未闭环（台账 §二 #32）

### 现象（两处，均在修复前实测复现）
| # | 漏点 | 实测 |
|---|---|---|
| 1 | **字数统计虚高** | `getEditorWordCount` 只剥 `\s+`，而 **ZWNJ 不是空白** ⇒ 「他说：「**重点**」」可见 **7** 字 → 状态栏 **9** 字 |
| 2 | **纯文本剪贴板带隐形字符** | `serializeClipboardText` 走 `textBetween`，未剥 ZWNJ ⇒ 复制正文粘到微信 / Word 带上 U+200C |

### ⭐ 按「覆盖完整性枚举」全仓排查 —— 又查出两处（比首轮复查更多）
对 `textContent` / `textBetween` 的**全部消费方**逐一判定（而非只修已知两处）：

| 消费方 | 判定 | 处置 |
|---|---|---|
| `getEditorWordCount` | **真漏** | 剥 |
| `extractEditorOutline` 的 `text` | **真漏（首轮复查遗漏）** | 剥 |
| `serializeClipboardText` | **真漏** | 剥 |
| `math` 解析入口（`math_inline` attr / `math_block` / fence 形式） | **真漏，且最严重** | 剥 |
| `serializer` 既有三处（escapeInline / 行内码 / 围栏块） | 已剥 | 保持 |
| `markdown-paste` 的 `textBetween`（比对用户是否编辑过） | 两侧同源 ⇒ 不构成漏 | 不动 |
| `code-block` / `mermaid-block` / `math-block` 的 `node.textContent`（渲染用） | 内容受围栏保护 | 不动 |
| `markdown-input` 的前缀正则 | ZWNJ **永不落在文本块首**（两条规则都要求有前驱字符）⇒ 安全 | 不动 |

### ⭐ math 落盘污染（本次最严重的一处，实测）
`$$…$$` / `$…$` **不在** `protectCodeRegions` 覆盖内 ⇒ ZWNJ 被插进数学源；`mathBlock` 落进 `textContent`、`mathInline` 甚至落进 **`attrs.latex`**，**并被原样写进文件**：

| 输入 | doc 内 ZWNJ | 落盘输出 |
|---|---|---|
| `$$a**——b$$` | 1 | **含 ZWNJ** 🔴 |
| `$a**——b$` | 0（在 attr 里） | **含 ZWNJ** 🔴 |
| ```mermaid 围栏 / 围栏代码块 / 缩进式代码块``` | 0 | 0 ✅ |

**修法**：在 **math 解析入口**剥一次（入口是数学内容的**唯一来源** ⇒ 内存 / 渲染 / 落盘 / 剪贴板全部自动干净，也顺带清洗存量脏文件）；**故序列化侧不重复剥**。

### 修法（结构式）
`stripZwnj` 从 `serializer.ts` 私有提为**跨模块契约**：新建 [`zwnj.ts`](../src/components/Editor/tiptap/zwnj.ts)（`ZWNJ` 常量 + `stripZwnj` 为**唯一来源**），parser / serializer / editor-metadata / math 全部改用它，散落的 `'\u200C'` 字面量与私有实现一并删除。

### ⭐ 刻意「不做」的两件事（附实测理由，防幽灵代码）
| 没做 | 理由 |
|---|---|
| mermaid / frontmatter 序列化器**不加**剥离 | 实测其内容**不可能**含 ZWNJ（围栏被保护 / frontmatter 在 ZWNJ 前已剥离）—— 加了就是死代码 |
| **不**把 `$$…$$` 纳入 `protectCodeRegions` | 需复刻 `markdown-it-texmath` 的分隔符判定 = **手抄库函数**（项目禁令 12）。入口清洗已消除"写坏用户文件"这一最严重后果，不为残余内存态冒漂移风险 |

### 回归锁（+6）
`roundtrip.spec.ts` math 2 条（落盘无 ZWNJ）+ `clipboard-serializer.spec.ts` 1 条 + 新建 `editor-metadata.spec.ts` 3 条（字数 7 / 4、对照 13、大纲剥净）。

## 6. 问题 D：实体解码 —— **原判有误，改判为非缺陷**（台账 §二 #31 / §三）

**精确触发条件（2026-10-10 实测钉死）**：**闭合 `**` 的前一个字符是标点**，**且**后面紧跟一个「以标点字符开头的 HTML 实体」。
最小例 `**a）**&#x548C;b`：源文渲染出 `<strong>`（因 `&` 是标点，"右向可闭合"成立）；保存后 `**a）**和b` ⇒ **不再加粗**。
**两组对照证明"只由解码引起"**：`**a）** b`（后接**空格**）保存前后都加粗 ✅；`**甲**&#x548C;**乙**`（闭合符前是**字母**）保存前后都加粗 ✅。

**关键结论**：Solo 输出的 markdown 与原文**逐字相同**（唯一差异是实体 → 真字符）⇒ **内容没被改坏**；变的只是渲染，而**解码后的渲染才是 CommonMark 标准结果**（源文加粗本是"靠 `&` 恰好是标点"的意外）。⇒ **非保真缺陷**。
**处置**：§二 #31 标 `[已改判 · 非缺陷]`；§三 立「HTML 实体解码」取舍（若要"实体原样回写"须在 doc 携带原始写法载体 ⇒ 动 schema 与保真三道防线，需先有真实用户诉求）。**已结案。**

4. **§6 的改判是否过宽**：「解码后的渲染更符合 CommonMark」能否作为"非缺陷"的充分理由？是否应反过来**保护源文的意外加粗**？
5. **§7 三条纪律是否落到"可执行"**：体检工具**只报告不断言**，会不会重演"红灯文件不入库"式的失效？
6. **§8 三处订正是否有第四处没被我发现**：请特别核对台账 / 材料里所有**计数与行号类断言**（这是我最易失手的地方）。
7. **覆盖性**：本会话**是否遗漏**了"读正文文本"的其他消费方（我枚举了 8 类，见 §4 表）？

## 12. 结论

- **代码层**：2 个真实缺陷已修（加粗静默丢失、ZWNJ 横切未闭环，含 math 落盘污染），均有回归锁与实测验证。
- **判定层**：2 项从"缺陷"改判为"设计取舍"（表格重排、实体解码），理由与代价均已写入台账。
- **制度层**：新增 1 个可复用工具 + 3 条纪律 + 1 条敏感区 + 2 条方法论。
- **诚实面**：3 处自我订正已公开留痕（§8），6 项未验证 / 未做已披露（§9），18 份未定性文档明确标注为**独立一轮工作**。
