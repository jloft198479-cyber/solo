# 方案：列表内 Shift+Tab 语义收编

> **✅ 状态：已执行（2026-10-11，方案 B）。** 简乐拍板「先按 B 执行，其他暂不行动，中间如果发现问题先记录」。
>
> **落地内容**：`src/components/Editor/tiptap/extensions/list-backspace-guard.ts::handleListShiftTab` —— 门槛由 `resolveGuardContext`（要求 offset 0 + 空选区）换成 `itemDepthAt`（只看在不在项内），**顶层项一律 `return true` 吞掉**；嵌套项 / 不在项内照旧放行上游；组字期 `isFrozen` 门控保留。头注释同步改写（消除「只锁不许劈」的无条件措辞）。
>
> **验证读数**：① 反向校准（实跑）＝撤掉新门槛 ⇒ 新增 **5 条转红**（offset>0 四格 + 公理 3），恢复后 `list-backspace` **21 条全绿**；⚠️ 其中「组字门控」那条两种实现下都绿（PM 的 keydown 在合成态本就忽略按键，`prosemirror-view:3189/3192/3548`）⇒ 标注为**意图哨兵**、不当承重锁。② 真机（Chromium + CDP 可信按键 + 原生选区）：中间项字中间按 ⇒ **原样不动**；连按两次 ⇒ 仍不动；嵌套子项字中间按 ⇒ **仍收一级**；Ctrl+0 ⇒ 仍正常转段落。③ 全量 `bun run test`：0 红。
>
> **未收编（拍板「暂不行动」）**：D2 有选区两格（单项内有选区＝照旧劈、跨项选区＝整表解散），已用「现状登记」用例锁住；`#55` 里那条**结构性判据冲突**（契约 `:48` vs 台账 #26）仍待拍板。
>
> **⚠️ 本文已于 2026-10-11 按独立复审重写**：首版的 **A 案**（把 Shift-Tab 接到 `demoteListItemToBlock`）经实测**证伪**，保留在 §3 只为「挡住下一个执行者重提它」。
> 证据来源：[`REVIEW-2026-10-11-编辑器交互内核线审核.md`](./REVIEW-2026-10-11-编辑器交互内核线审核.md) §1.1（四形态矩阵）；复审原件 [`REVIEW-2026-10-11-编辑器交互内核线审核-复审.md`](./REVIEW-2026-10-11-编辑器交互内核线审核-复审.md)。
> 规则来源：[`PROPOSAL-list-semantics.md`](./PROPOSAL-list-semantics.md)（列表语义契约 §1 公理 / §2 动词表）。

## 0. 一句话

**守卫只拦住了「光标恰在项首块第 0 位」那一刻；其余位置的 Shift+Tab 会按四种形态破坏结构（中间项劈成两段 + 中间夹 doc 层孤立段落；首/末项把该项甩成 doc 层段落），有选区时更重（单项内照旧劈、跨项整表解散），且原样落盘。本方案把守卫的接管范围一次性放宽到「项内任意位置」，并让键位语义保持 no-op。**

## 1. 问题（四形态 + 有选区两格）

**链条**：

| 环节 | 位置 | 事实 |
|---|---|---|
| 接管门槛 | `extensions/list-backspace-guard.ts:65-85` | `resolveGuardContext` 要求 `selection.empty` + `$from.parentOffset === 0` + `$from.parent === item.firstChild` ⇒ 只要光标不在第 0 位（或有选区），返回 `null` |
| 守卫放弃 | 同文件 `:149-159` `handleListShiftTab` | 判定不成立即 `return false`（放行下游） |
| 落到上游 | `@tiptap/extension-list/dist/index.js:492`（listItem）/ `:1253`（taskItem） | `'Shift-Tab': () => liftListItem(...)` |
| 上游实现 | **`prosemirror-schema-list/dist/index.js:206` `liftListItem` → `:217` 顶层分支 → `:238-260` `liftOutOfList`** | `:239-243` 先把范围内各项并成一个 big item；两侧不留 join ⇒ 劈开 |

**实测矩阵**（`- 甲⏎- 乙⏎- 丙`；本方独立复跑，与复审逐格一致）：

| # | 光标 / 选区 | 落盘 | 破坏形态 |
|---|---|---|---|
| 1 | 中间项 offset=0 | `- 甲\n- 乙\n- 丙\n` | 无（守卫吞掉） |
| 2 | **中间项 offset=1** | `- 甲\n\n乙\n\n- 丙\n` | **劈成两段 + 中间夹孤立段落** |
| 3 | **首项 offset=1** | `甲\n\n- 乙\n- 丙\n` | 首项甩成 doc 层段落 |
| 4 | **末项 offset=1** | `- 甲\n- 乙\n\n丙\n` | **留 doc 层孤立段落** |
| 5 | 单项 offset=1 | `甲\n` | 退出列表 |
| 6 | 嵌套子项 offset=1 | `- 甲\n- 甲1\n- 乙\n` | 无（安全，符合契约） |
| 7 | **有选区·落在单项内** | `- 甲\n\n乙\n\n- 丙\n` | **照旧劈开** |
| 8 | **有选区·跨两项** | `甲\n\n乙\n\n丙\n` | **整张列表被解散** |

**连带影响**：容器被切碎后，`list-move.ts:41` 的「同层换位」只认同一父容器 ⇒ 跨段落的两项再也无法用 `Alt+↑/↓` 互换 —— 正是台账 `§二 #26` 当初的用户报障症状。

**锁为何没抓到**：`extensions/__tests__/list-backspace.spec.ts:169-173` 只有一条 Shift-Tab 用例，且 `pressAt`（同文件 `:108-113`）把光标钉在文本起点（＝ offset 0）——**恰是守卫仍生效的那一格**。12 条全绿（现役）＝假绿灯。

## 2. 本方案承诺的硬不变量（只承诺这一条）

> **无选区时，光标在任意列表项内按 Shift+Tab，都不得把列表劈成两段、不得留下 doc 层孤立段落。**

**不承诺**（请按这行核对，别按「Shift+Tab 全面修复」期待）：

- 有选区（非空）时的行为 —— 见 §7 第 7/8 格与决策点 **D2**（默认**保持现状**：放行上游 ⇒ 单项内照旧劈、跨项整表解散）。
- `Mod-Backspace` / 纯 `Backspace` —— 已由现役守卫覆盖（`list-backspace.spec.ts` 12 条全绿），本方案不动。
- 引用块同名问题 —— 台账 `§二 #26` 已明确另案，本方案不纳入。

## 3. ❌ A 案（**已证伪，勿用**）——把 Shift-Tab 接到「转普通段落」落点

首版曾推荐它（「行首/项内行为归一」）。**实测证伪**：直调 `demoteListItemToBlock` 五格，产物与现状 offset>0 四格**逐字相同**：

| 格 | A 案落盘 | 现状 Shift-Tab 落盘 | 是否相同 |
|---|---|---|---|
| 中间项 offset=0 | `- 甲\n\n乙\n\n- 丙\n` | `- 甲\n- 乙\n- 丙\n`（不变） | ✗ **A 案反而新增劈开** |
| 中间项 offset=1 | `- 甲\n\n乙\n\n- 丙\n` | `- 甲\n\n乙\n\n- 丙\n` | ✅ **逐字相同** |
| 首项 offset=1 | `甲\n\n- 乙\n- 丙\n` | `甲\n\n- 乙\n- 丙\n` | ✅ 逐字相同 |
| 末项 offset=1 | `- 甲\n- 乙\n\n丙\n` | `- 甲\n- 乙\n\n丙\n` | ✅ 逐字相同 |
| 单项 offset=1 | `甲\n` | `甲\n` | ✅ 逐字相同 |

**为什么**：契约 `PROPOSAL-list-semantics.md:48` 白纸黑字把「转普通段落」的顶层项结果写成「原地退出列表，**前后兄弟拆成两张列表**」——拆成两张是**该动词契约批准的正确产物**。把 Shift+Tab 接到它身上，等于**把劈开换个来源并转正**，而且还顺手放开了守卫目前唯一挡住的那一格（中间项 offset=0）。

⇒ **A 案对 P1 零疗效，且自相矛盾**（同一份方案里 §2 把该形状列为禁止的不变量、§8 却把它当 A 案的合格产物验收）。**保留本节的唯一目的是挡住重提。**

## 4. ✅ 推荐案 B：只放宽守卫接管范围，语义保持 no-op

**做法**：顶层项内 Shift+Tab **一律吞掉、不改文档**；嵌套项照旧放行上游反缩进。

**为什么是「唯一满足硬不变量」的选项**：

1. **它是唯一能堵住第 2/3/4 格的选项**——不放开结构，就不产生「劈成两段 / 甩出段落」。
2. **契约自洽**：§2 动词表把 `Tab / Shift+Tab` 定义为「**缩进 ±1**，连带子树 —— 唯一的微调动词」；顶层项已是最外层，**−1 越界 ⇒ no-op 是这个动词字面上唯一合法的解**。「退出列表」是**另一个动词**的职责（转普通段落 / toggle 第二次），且已有三个入口（Ctrl+0 / 命令面板「普通段落」/ 斜杠「正文」）。
3. **改动面最小**：不新增任何语义，只把「劈不劈」这条分歧从上游收回来。

**改法骨架**（`extensions/list-backspace-guard.ts` 的 `handleListShiftTab`；门槛从 `resolveGuardContext` 换成 `itemDepthAt`，不再要求 offset 0）：

```ts
function handleListShiftTab(editor: Editor): boolean {
  const { selection } = editor.state;
  if (!selection.empty) return false;               // 有选区：保持现状（D2）
  const { $from } = selection;
  const itemDepth = itemDepthAt($from);             // 复用现有 helper，不要 offset 0 门槛
  if (itemDepth < 0) return false;                  // 不在列表项内 → 放行
  if (isFrozen(editor.view)) return true;           // 组字期吞掉（现状保留）
  if (isNestedItem($from, itemDepth)) return false; // 嵌套项 → 上游反缩进（现状保留）
  return true;                                      // 【全部】顶层项一律吞掉、不改文档
}
```

**代价（必须认，且要拍板）**：一处**行为回退** —— 今天「首项 / 单项 offset>0」两格按下去能退出列表，改后变无反应。

- 现状那两格的产物是 `paragraph(甲) + bulletList(乙,丙)` / `paragraph(甲)`，**与 A 案同形**；而 A 案对中间项无效 ⇒ 「用 A 换回这两格」的代价是**把中间项的破坏形态转正 + 放开守卫唯一生效的一格**，不值。
- 要退出列表，契约 `:48` 的三个入口本来就在。

**外部依据（本轮查证，结论不充分，如实标注）**：Notion 官方快捷键文档把 Shift+Tab 定义为「取消嵌套 / 减少缩进」【中】，Obsidian Outliner 类插件文档同样只定义「向左缩进」【中】——**都没有定义「已是顶层」时的行为**。⇒ 本决策点**没有可直接照搬的业界标准答案**，只能由本仓契约推导。

## 5. 方案 C（不推荐）：保持现状，改文档与锁承认它

把守卫头注释 `list-backspace-guard.ts:30-31` 的「Shift-Tab 只锁「不许劈」…顶层项吞掉不做事」改成带位置限定，并把 §1 的 5 格现状写成「会破坏」的现在时。

**为什么不推荐**：与契约 §1 公理 3「操作不外溢」冲突（劈开使未选中的兄弟项改变容器归属），且实测读数显示有选区时能**整表解散**——把可复现的破坏写进契约当既成事实，只在前两案都被否时作兜底。

## 8. 回归锁与反向校准（执行时必须一起交）

**新增用例**（`extensions/__tests__/list-backspace.spec.ts`，沿用该文件既有 `pressAt` / `treeSig` / `topLevelTypes` 基建；**注意 `pressAt` 把光标钉在文本起点，必须另写一个“把光标放到 offset=1”的助手**，否则新用例会重蹈「假绿灯」）：

1. 【禁止破坏】顶层**中间项** offset=1 Shift+Tab ⇒ `bulletList(甲, 乙, 丙)` 原样（`topLevelTypes === ['bulletList']`）
2. 【禁止破坏】顶层**首项** offset=1 ⇒ 原样（B 案；首版矩阵漏了这格）
3. 【禁止破坏】顶层**末项** offset=1 ⇒ 原样（B 案；这格违反的正是 §2 不变量的后半句「不得留孤立段落」）
4. 【禁止破坏】顶层**单项** offset=1 ⇒ 原样（B 案；D3 的行为回退在此登记）
5. 【公理 3 不外溢】上面四格 ⇒ 未选中项的文字与容器归属一字不变
6. 【嵌套项不回归】嵌套项 offset=1 ⇒ 仍只提升一级
7. 【组字门控】组字期间 Shift+Tab 不改结构（与现有 Backspace 版同构）
8. 【有选区·现状登记】单项内有选区 ⇒ 现状读数落锁（D2 拍板后按结论改写）
9. 【有选区·现状登记】跨项选区 ⇒ 现状读数落锁（同上）

**反向校准判据（必做）**：把 `handleListShiftTab` 的门槛改回 `resolveGuardContext` 后，**用例 1–4 必须转红**；若仍绿，说明锁没有真承重，方案不予验收。

**真机要求**：CI 之外必须真机按一次（Shift+Tab 涉及浏览器/WebView2 的默认焦点行为，happy-dom 不覆盖；本项目口径：UI/键位改动单测只是入场券）。
