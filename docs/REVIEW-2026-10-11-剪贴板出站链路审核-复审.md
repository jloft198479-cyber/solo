## 2. 补核与修正

1. **P1-1 存盘链传播已闭合**（原审核 §4「未验证」第 2 条）：`useDocumentSession.ts:242-283` 存盘 try/catch 会兜住异常并**弹「保存失败」modal**（自动保存首次弹，超过阈值降级为状态栏文本）⇒ 实际表现从「可能无法保存」收敛为「**保存必失败且报错可见**」，非静默丢数据。P1 定级维持（文档存不出去，删脚注前持续报错）。
2. **P1-1 触发面收敛**：markdown 开盘路径安全——markdown-it-footnote 的脚注定义**必须有引用才入列**（其源码 `refs[':'+label] === 'undefined'` 即 return false），`footnote_open` 的 label 恒为字符串 ⇒ 崩溃只经由**粘贴/HTML 往返**进入，正常打开脚注文档不会崩。审核范围判定正确。
3. **小瑕疵（不影响结论）**：P1-2 表格中「再序列化会写成 `^[^1]^`」不够精确——`[` 属 escapeInline 恒转义集合（clipboard 与文件两模式均转义，serializer.ts:479/499），实际输出应为 `^\[^1\]^` 之类（未逐字节实测，按转义集合推断）。结论「脚注链彻底断」不受影响。
4. **审核引用核对**：抽查的全部行号命中（serializer.ts:1033/1044/750/808-810/1055-1058/1101-1104/1139/122-124；plugins/footnote.ts:57；zwnj.ts:33；extensions/footnote.ts:19/54-58；sub-sup.ts:19；markdown-to-html.ts:44-69/65；MarkdownEditor.vue:688/692-695/905-915；editor-commands.ts:152-160）；「clipboard-serializer.spec.ts 27 条」经 grep 实测 = 27 ✅。

## 3. 修复方案复核（供拍板参考）

- **P1-1**：`String()` 兜底（治标、一行）+ `label` 显式 `parseHTML: el => el.getAttribute('label') ?? ''`（治本、绕开 fromString 强转）。**两者都要**：parseHTML 治本但兜底防未来路径。`FootnoteRef.label` 同样要锁（审核已提）——P1-2 修复后 footnoteRef 恢复 HTML 解析，同一强转会在它身上复发。
- **P1-2**：三案均验证可行；**换 `<span data-footnote-ref>` 载体最省心**（不与任何 mark 冲突、不依赖 priority 微操）。注意若换载体需同步检查渲染 CSS 选择器与既有保真测试。
- **P1-3**：`isTableInternal` 去掉 `'table'`，同步更新 `stripOpenLayers` 上方注释（「table 系无法独立序列化」的表述随之修正）。
- **P1-4**：修 `markdown-to-html.ts` 装配即可；另注意 §3 第 5 条的提醒——`Ctrl+C` 的 PM DOMSerializer 路径对数学/mermaid 同样漏原始 source，两条路要分开评估修法。
