# 方案：表格单元格的保真缺口

> **状态：仅方案，未改任何代码。** 由「Qoder 二批复查的两条新发现」独立复跑核实产出（自写探针，跑完已删）。台账指针：`KNOWN-ISSUES §二 #61`（本轮新登记）、`#60`（口径已订正）、`#56`（已修，同族）。
> **两张要拍板的单子在下文 §3**，其余是取证与判据。

---

## 0. 一句话说清两个现象

| 编号 | 白话 | 谁会中招 | 用户看得见吗 |
|---|---|---|---|
| **#61** | **你打开别人写的表格，一保存，文件就被悄悄改了** —— 只要某格的开头是 `-` `+` `>` `#` `1.`，solo 会给它前面加一个反斜杠 | **任何人**（不需要 solo 出任何操作，只要打开→保存） | **看不见**（渲染结果一模一样，只有文件字节变了） |
| **#60** | 在表格格子里用斜杠菜单插了列表 / 代码块 / 公式 —— 当场看着好好的，存盘再打开就**变味**（列表号变字面文字、公式被塞进乱码） | 只在格子里主动插块级结构的人（斜杠菜单 / 命令面板 / HTML 粘贴） | 看得见（重开就变样） |

**为什么 #61 更要紧**：它不需要误操作，只要用户打开一份「从别处来的」表格就会触发，且**完全不露痕迹**——这正是 `§一 #28`（B1「打开即保存就改文件」）去年专门清过的那一类缺陷的残留口子。

---

## 1. 取证

### 1.1 #61 最短复现（生产 schema，`parseMarkdown` → `serializeMarkdown` 恒等性）

| 磁盘上的原文（别的编辑器写的） | solo 保存后 | 内容有变化吗 |
|---|---|---|
| `\| - 甲 \|` | `\| \- 甲 \|` | ❌ 被加转义 |
| `\| > 乙 \|` | `\| \> 乙 \|` | ❌ 被加转义 |
| `\| 1. 丙 \|` | `\| 1\. 丙 \|` | ❌ 被加转义 |
| `\| # 丁 \|` | `\| \# 丁 \|` | ❌ 被加转义 |
| `\| + 己 \|` | `\| \+ 己 \|` | ❌ 被加转义 |
| `\| * 戊 \|` | `\| \* 戊 \|` | ⚠️ **应该转义**（行内恒需，见 §6） |
| `\| 甲 \|`（对照） | 列宽补空格，内容不变 | ✅ 内容原样 |

**关键事实（决定修法是否安全）**：markdown-it 在表格单元格里**不做块级解析** —— 实测把 `| - 项 |` 重新读回来，得到的是**字面文本 `- 项`**，不是列表。⇒ 「格首要转义 `-`」这个判断**在 markdown 语义上根本不成立**。

### 1.2 根因（#61）

```
serializer.ts::atBlockStart()  (:141)
  └─ 判据 = 「行首，或行首的列表 marker / 引用前缀之后」
  └─ 而 cellToText 是在**子状态**里渲染格内内容的 ⇒ 该子状态输出为空
     ⇒ prefix === '' ⇒ return true  ⇒ 「格首」被当成「块首」
        ⇒ escapeInline()  (:519) 的 ^([#+\->]) 与 ^(\d{1,9})([.)]) 开火
```

**本质**：`atBlockStart()` 缺了「这个位置到底是不是块语境」这一维。**表格单元格是行内语境**（GFM 规范：cell 内容只按行内解析），块语法在格内不存在。

### 1.3 #60 实测矩阵（9 种块可落进格子，其中 8 种 R1≠R2）

| 块型 | 怎么造出来 | 首存落盘（R1） | 重开再存（R2） | 性质 |
|---|---|---|---|---|
| `paragraph` | — | 同右 | 同左 | ✅ 正常（对照） |
| `heading` | 斜杠「标题」 | `\| 标题 \|` | 同左 | ✅ **已修**（#56） |
| `bulletList` | 斜杠「无序列表」 | `\| - 项 \|` | `\| \- 项 \|` | 转义漂移 |
| `orderedList` | 斜杠「有序列表」 | `\| 1. 项 \|` | `\| 1\. 项 \|` | 转义漂移 |
| `taskList` | 斜杠「待办」 | `\| - [ ] 项 \|` | `\| - \[ ] 项 \|` | 转义漂移（`[` 恒需） |
| `blockquote` | 斜杠「引用」 | `\| > 块 \|` | `\| \> 块 \|` | 转义漂移 |
| `callout` | 斜杠「zd callout」 | `` \| > [!NOTE]<br>> b \| `` | 加转义 | 结构降级 + 漂移 |
| `codeBlock` | 斜杠「代码块」 | `` \| ```js<br>x=1<br>``` \| `` | `` \| `js<br>x=1<br>` \| `` | **语义降级**：围栏→行内码，语言名混进正文 |
| `mermaidBlock` | 斜杠「图表」 | 同上型 | 同上型 | **语义降级** |
| `mathBlock` | 斜杠「公式」 | `\| $$<br>x=1<br>$$ \|` | `\| $<br>x=1<br>$ \|` | **公式被污染**（`latex` 里掺 `<br>`、块级降行内） |

**三处口径订正（原稿 #60 的说法要改）**：
1. 数量 **7 → 8 种**（`callout` 实测也在内，`wrapIn('callout')` 同样落进格内）；
2. 性质是**一次收敛**（**R2 === R3 全绿**），**不是**「每存一次变一次」——首存改写一次、之后稳定；
3. `mathBlock` **不丢字**：`x=1` 落在 `attrs.latex`（实测 `{"type":"mathInline","attrs":{"latex":"<br>x=1<br>"}}`）⇒ 是**公式被污染 + 降级**，不是文字消失。`codeBlock` 同型。

**可达性（不是只有 HTML 粘贴）**：把光标放进单元格后，`toggleBulletList` / `toggleOrderedList` / `toggleTaskList` / `toggleBlockquote` / `toggleCodeBlock` / `toggleHeading` **实测全部返回 `true` 且块落在格内**（`tableCell[bulletList]` 等）；`callout` 走 `wrapIn`、`math`/`mermaid` 走 `insertContent`，同样落格内。**斜杠菜单与命令面板走的就是这些命令。**

**根因（#60）**：`cellToText`（`serializer.ts:819-836`）对非 `paragraph` / `heading` 子块走 `renderNode` ⇒ 把**块级语法**写进了单行容器；`#56` 只给 `heading` 开了 `renderInline` 的口子。

## 2. 影响面

| 谁 | 会不会中 #61 | 会不会中 #60 |
|---|---|---|
| 用别的编辑器写表格的人（Typora / VS Code / GitHub 网页） | ✅ 只要格首是 `-`·`+`·`>`·`#`·`1.` 就中 | ❌（markdown 造不出格内块） |
| 从网页 / Word 复制表格进 solo 的人 | ✅ 同上（粘贴后再保存） | ⚠️ 粘贴 `<td><ul>` 会造出 `tableCell[bulletList]` ⇒ 中 |
| 在 solo 里往格子打斜杠菜单的人 | — | ✅ 中 |
| 只用 solo 打字、不碰表格的人 | ❌ | ❌ |

**共同点**：两条都属于「**内容渲染对、文件字节错**」或「**内容当场对、存盘变味**」——都不是崩溃，但都属于保真红线。

## 3. ⚖️ 要拍板的两件事

### 决策一（#61）：修不修？

| 选项 | 内容 | 代价 | 建议 |
|---|---|---|---|
| **A. 修** | `atBlockStart()` 开头加一行：`if (this.inTableCell) return false;` | 改 1 行 + 更新 1 条旧锁（Phase M 那条锁的是旧行为）；**全仓实测 1788 通过 / 1 失败**，唯一失败就是该锁 | ⭐ **建议修** |
| B. 不修 | 记在台账里当已知项 | 用户文件会被持续静默改写，且与 `§一 #28` 已确立的原则冲突 | ✖ |

**为什么这一行是安全的（已逐条查过）**：
- **渲染不变**：格首的 `- ` / `> ` / `# ` 在 GFM 单元格里本就不成语法，转不转义显示都一样；
- **不碰单元格必须的转义**：`\|`（会切开单元格）走的是**另一条**规则（`markTableCell()` / `:505`），不受影响；
- **不碰行内恒需转义**：`*` / `` ` `` / `[` / `~` 照旧转（所以 `| * 戊 |` 仍会变成 `| \* 戊 |`，这是**对的**）；
- **列宽补空格是设计**（B5 记宽对齐），不算漂移。

**顺带白捡**：#60 里 `bulletList` / `orderedList` / `blockquote` 三型**当场** R1===R2 收敛（因为它们的 R2 差异正是这条过度转义造成的）。

### 决策二（#60）：走哪条？

| 选项 | 内容 | 保住了什么 | 代价 | 建议 |
|---|---|---|---|---|
| **B1. 兜底拍平** | `cellToText` 的 `else` 分支（非 `paragraph`/`heading`）统一改走 `renderInline` ⇒ 格内块级结构一律拍成行内文本 | **文字**（列表项文字、代码内容、公式原文都留），换一次收敛 | 丢结构（列表符号 / 围栏 / 语言名 / 块级公式标记变字面量）；**不阻止继续造出来**，只是不再「变味」 | ⭐ **建议先做**（它是 B2 的安全网） |
| **B2. 收紧 schema** | `CustomTableCell` / `CustomTableHeader` 的 `content` 由 TipTap 默认的 `block+` 改为 `paragraph` ⇒ 格内**再也造不出**块级结构 | 从源头掐死：斜杠菜单那些命令在格内直接失败，`#60` 整族消失 | 动 schema（敏感区）；命令失败后斜杠菜单项在格内会「点了没反应」，需菜单侧给禁用/提示；**HTML 粘贴 `<td><ul>` 需配归一**（否则内容可能被丢） | 建议作为**第二步**，单独立案 |
| B0. 都不做 | 记在台账 | — | 用户在格子里用斜杠菜单就等着「存盘变味」 | ✖ |

**B2 的一个关键事实（已实测，决定它是安全的）**：markdown 解析**永远只产出** `tableCell[paragraph]` —— 实测 `| - 项 |`、`` | ```js<br>x=1<br>``` | ``、`| $$…$$ |`、`| > [!NOTE]<br>> b |` 四种写法读回来**全是 `paragraph`**。⇒ 收紧 schema **不会影响任何 .md 老文件的打开**；唯一的风险面是 **HTML 粘贴**（`<td><h1>` / `<td><ul>`）这一条入站路径。

**建议的组合**：**决策一先落（一行、零风险）→ 决策二走 B1（兜底，保证任何来源都不丢字）→ 之后再评估 B2（禁止造出来）**。理由：B1 是 B2 的必要安全网——schema 收紧后若还有漏网来源（粘贴 / 未来的新命令），兜底那一层仍要接住。

## 4. 回归锁与反向校准判据（修的时候照这个验，别只跑「有动作」）

**#61 的锁（写在 `roundtrip.spec.ts`，建一族）**
- 正例族：上表六种格首（`-` `>` `1.` `#` `+` 与对照）**逐字恒等**（`serializeMarkdown(parseMarkdown(md)) === md` 的单元格内容部分）；
- **反向校准**：撤掉那一行 ⇒ 该族**必须转红**（至少 5 条）；
- 边界不许误伤：`| * 戊 |` **仍要**转义（行内恒需）；`| 甲 \| 乙 |`、`| [a](b) |`、含 `<br>` / hardBreak 的单元格、粘贴 `<td><ul>` ——这四条要显式各留一条锁。

**#60 的锁（扩 `roundtrip.spec.ts` Phase M 为族级）**
- 每块型一条 `R1 === R2`（8 条）；
- **反向校准**：撤掉 `cellToText` 的拍平 ⇒ 对应锁全红；
- 内容不许丢：每条同时断言「重开后文字里仍能在**某个通道**（文本或 attrs）找到原文」。

**负面靶子（防止锁是假绿）**：锁必须建在**格内真的有这个块**的 doc 上（用命令造，或直接搭 `tableCell[bulletList]` 的 doc），**不能**用 `| - 项 |` 这种 markdown —— 它读回来本来就是段落，锁了也恒真。

## 5. 实测证据（可复现）

- 探针：生产扩展集 + `createTestSchema()`，happy-dom；对每种块型搭 `doc[table[row[cell[block]]]]`，跑 `R1 = serialize(doc)` → `R2 = serialize(parse(R1))` → `R3 = serialize(parse(R2))`，并 dump `textContent` 与 reparse 后的 JSON（用于分辨「丢字」与「换表示」）；
- 命令可达性：`Editor` + `parseMarkdown` 建表 → `setTextSelection` 到格内文本 → `editor.commands.<cmd>()`，记录返回值与 `descendants` dump 出的节点链；
- #61 修法验证：临时在 `atBlockStart()` 首行插入 `if (this.inTableCell) return false;` ⇒ 六种格首**全部原样保留**；`npx vitest run` ⇒ **1788 passed / 1 failed / 1 skipped**（失败项：`roundtrip.spec.ts` Phase M「旧文件里已存在的 `| # 标题b |` 读入后转义为字面量并收敛」，即锁旧行为的那条）；**验证后已完整还原**（`git diff` 仅剩 `cellToText` 的 heading 分支）。
- 注：`R1===R2` 这种写法**不能**当对象字面量的键（语法错）；探针里一度把 markdown 串直接喂给 TipTap 的 `content`（它按 **HTML** 解析、表根本没建起来）⇒ 差点拿假数据下结论。**两条都记在探针纪律里**。

## 6. 明确不改什么（避免后人当 bug 报）

- **`*` 起头的格仍会加转义**（`| * 戊 |` → `| \* 戊 |`）：`*` 是**行内语境**的恒需转义（防 `*文字*` 被读成强调），**正确，修了才是 bug**。
- **`taskList` 仍会差一步**（`- [ ] 项` → `- \[ ] 项`）：`[` 同属恒需转义。⇒ #61 修完后这一型的漂移**仍存在**（一次收敛）。要再收一档得单独评估「`[` 能否按语境放宽」，**有风险，先不做**。
- **列宽会补空格**：`| 项 | 值 |` → `| 项  | 值  |` 是 B5「按显示宽度对齐」的设计，**不是字节漂移缺陷**。
- **`cellToText` 的 `heading` 分支保留**：已在 `#56` 修好，是 B1 的同型先例（拍平、保文字）。

## 7. 请第三方重点挑战的 5 条

1. `inTableCell ⇒ atBlockStart() = false` 是否**漏掉**了某个「单元格里真的需要块首转义」的场景？请特别在 **① 一个格子里塞了多个块**（`renderNode` 会写出真实换行，`:523/:524` 那两条按 `\n` 的规则）与 **② 格内含 hardBreak / `<br>`** 两条路径上挑战。
2. B2 把 `tableCell.content` 收紧为 `paragraph` 后，`canReplaceWith` / `canJoin` / `lift` / `setBlockType` 这些**按父块类型做预判**的地方（见 `sensitive-areas §11 #22`）是否有连带影响？
3. HTML 粘贴 `<td><ul>` / `<td><h1>` 在 B2 下会怎样——会不会**静默丢内容**？归一该放在哪一层（`parseHTML` / 粘贴中间件 / `cellToText` 兜底）？
4. `taskList` 的 `[` 恒需转义造成的残留漂移（`- [ ] 项` → `- \[ ] 项`）值不值得再收一档？收的话风险是什么？
5. 列宽补空格造成的字节变化，**该不该**也算「打开即改文件」？（我方判定：**不算**，属设计。请挑战这个判定。）
